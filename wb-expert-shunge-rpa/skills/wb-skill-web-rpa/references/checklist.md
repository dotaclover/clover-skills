# 网页 RPA 验收清单

按顺序过，能勾的必须有证据（日志、截图或结果文件），不能只凭印象。

## 一、开工前

- [ ] 目标写成了一句可验收的话（产出什么、多少条、落到哪）
- [ ] 授权范围明确：站点、账号、只读/可写、时间窗、频率
- [ ] 数据规格明确：字段、唯一键、编码、命名、覆盖策略
- [ ] 失败处理明确：重试次数、间隔、遇验证码与登录过期的动作
- [ ] 限速明确，且已写进执行参数
- [ ] 已找过更简单的方式（导出、公开接口、站点地图），确认都不适用

## 二、执行中

- [ ] 每个动作后都读取了页面状态，没有"发送成功即完成"
- [ ] 等待用的是条件判断，不是固定睡眠
- [ ] 弹窗、浮层、公告有处理路径，关不掉时已停下
- [ ] 单页应用切换以内容变化为准，不是以 URL 变化为准
- [ ] 每 N 条落一次检查点，进度文件可读
- [ ] 写入前查过存在性，重复执行不会产生重复结果
- [ ] 失败条目单独记录，带页面提示原文

## 三、收尾

- [ ] 目标数 / 实际数 / 去重后数三者对得上
- [ ] 抽样比例达到约定（默认 5%），错误有归因
- [ ] 中途 kill 后续跑实测通过，未重复、未漏条
- [ ] 下载文件按新增 + 下载记录双重认领，无临时后缀残留
- [ ] 日志可还原单条记录的完整处理过程
- [ ] 交付物不含账号、密码、Cookie、密钥、个人隐私

## 四、交接

- [ ] 参数表（入口、限速、重试、字段映射）独立成文件
- [ ] 写明页面改版后优先检查的三处
- [ ] 写明已知限制与未覆盖场景
- [ ] 未执行的步骤标"未执行"，没有写成已完成
