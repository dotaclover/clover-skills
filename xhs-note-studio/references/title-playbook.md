# 标题方法论

每条标题 = **人群锚点** + **机制钩子** + **信息缺口**。三者缺一，点击率打折。
所有 `{}` 由本次预设场景卡的词填充。

---

## 第 -1 步：搜同类爆款（差异化 + 借鉴结构）

动笔前**联网搜索该垂类在小红书的爆款笔记**，两件事同时做：

**A. 避让（避免雷同）**
统计高频句式与高频词 → 这是"大家都在说的"，**要避开**；找出没人写的角度 → 差异化的落点。

**B. 借鉴（提上限）**

| 提取什么 | 拿它干嘛 |
|---|---|
| **开头逻辑**（前 2 行怎么写） | 复用开场方式，不是照搬内容 |
| **干货密度**（多少字一个信息点） | 复用节奏 |
| **互动话术**（结尾怎么钩） | 复用钩子类型 |
| **当季热搜词** | 做趋势词，须核实，不凭记忆 |

> 只避让不借鉴 = 凭经验写。避让 + 借鉴 = 照着已验证的写。差别在数据上限。

---

## 默认出 3 条

1. **三条三种机制。** 有两条同机制 = 一条作废，重写。
2. **取机制顺序**：从下方「形态 → 机制映射」取该形态的首选 + 次选。凑不齐三种 → 场景卡信息不够，回去补，不硬凑。
3. **情绪分层**：焦虑 / 柔软 / 理性各一条。
4. **轮换主语**：你 / 我 / 谁懂 / 别再 / 数字，三条开头不撞。

## 7 种机制

### 1. 激发好奇心 — 信息缺口
`你以为的 {旧认知}，其实是 {新结论}` / `为什么同样 {条件}，她 {好结果} 你 {坏结果}？`
她已有解释，你说它是错的，她必须点进来确认自己有没有中招。

### 2. 利用热点趋势 — 借搜索流量
`{趋势词} 火了，{人群} 用之前先看这 {数字} 个 {参数}`
趋势词自带搜索量，但必须绑定**人群判断**，否则只是搬运。趋势词须联网核实。

### 3. 增加互动性 — 拉读者进场
`评论区告诉我：你选 {A} 还是 {B}？` / `{人群A} 别慌，{人群B} 别笑：{话题} 我算清了 {数字} 笔账`
预设立场诱发表达欲。进阶：**同时点名两个对立人群**，容易引发站队讨论。

### 4. 数据利益法 — 数字替代形容词
`{数字} 招 / {数字} 天 / {数字} 小时` / `{数字} vs {数字}`
进阶最强：**两个落差大的数字并排**（排到 A140，才叫到 29），画面感自动生成，不需要形容词。数字必须真实，不为了好看编。

### 5. 制造紧张感 — 损失厌恶
`别再 {错误做法} 了！{正确做法} 反而 {好结果}` / `别等 {临界点} 再 {动作}！{阈值} 就该 {动作}`
人对损失的敏感度约为收益的两倍。进阶：**否定现有做法 + 立刻给替代方案**——只制造焦虑不给出路，读者会直接划走。

### 6. 引发共鸣 — 说她不敢说的话
`谁懂啊！{场景} 的那天，我……` / `{上半状态}，{下半状态}`
用自嘲式具体画面，不空喊"我理解你"。涨粉效率最高，收藏率略低。

### 7. 提供实用价值 — 收藏率之王
`{人群}{场景}{动作}{数字} 条：{要点1}+{要点2}+{要点3}` / `一篇讲透 {话题}｜附 {清单}`
进阶：**把清单要点直接压进标题**，读者不点进来也知道能拿到什么，反而更愿意点。

## 形态 → 机制映射

| 形态 | 首选 | 次选 | 避免 |
|---|---|---|---|
| A 单点放大 | 共鸣、数据 | 好奇心、热点 | 实用价值（太早剧透解法，画面感没了） |
| B 清单干货 | 实用价值、数据利益 | 紧张感 | 好奇心（干货型玩悬念，读者容易觉得被误导） |
| C 测评对比 | 好奇心、数据利益 | 互动性 | 共鸣（要理性，别煽情） |
| D 观点站队 | 好奇心、互动性 | 紧张感 | 实用价值（要吵起来，不是要收藏） |

## 评分

五维 × 20 分 = 100。

| 维度 | 满分看什么 | 扣分红线 |
|---|---|---|
| **人群匹配** 20 | 有锚点词，目标人群一眼认领 | 谁都能套用 → 扣 10+ |
| **信息缺口** 20 | 话说一半，促使点击 | 说满了 → 扣 10+ |
| **情绪唤醒** 20 | 有具体画面 / 数字 / 损失 | 只有抽象形容词 → 扣 10+ |
| **结构合规** 20 | ≤ 20 字、无折叠、无违规词 | > 24 字或含违规词 → 扣 15+ |
| **平台差异** 20 | 和搜到的同类爆款不雷同 | 与高频句式雷同 → 扣 10+ |

**等级**：≥85 优｜70–84 良｜55–69 待改｜<55 重写。

**填写负担控制（重要）**
不要 3 条 × 5 维 = 15 个分数一次全铺。分两遍：

| | 第一遍（必出） | 第二遍（用户要细化时） |
|---|---|---|
| 推荐那条 | 总分 + 最低维度 | 展开五维明细 |
| 另两条 | 总分 + 最低维度 | 展开五维明细 |

> 一次填 15 个分数既吃力又难校验。**总分 + 最低维度**已经能支撑选择——最低维度就是优化方向。

## 差异化检查（3 条版）

1. 三条三种机制，无重复
2. 焦虑 / 柔软 / 理性各一条
3. 三条开头主语不撞
4. 三条都 ≤ 20 字，无一条 > 24 字
5. 三条都和正文内容对得上，没有一条是标题党
6. 三条评分均 ≥ 70

## 推荐规则

标 ⭐ 推荐 1 条（通常是最高分那条，但**不是必须**——人群契合度优先于分数）。
- 理由必须**具体到机制层面**（`两个数字的落差直接构成绝望感`），不说"这条比较好"。
- 一句话说明另两条各自适合什么（要收藏率选 X，要评论量选 Y）。

## 扩展模式：10 条

用户明确要"多给几个 / 出 10 条 / 横向比对"时才启用。
- 表格加列 `适配场景`
- 单一机制最多 2 次，表下写分布统计
- 推荐 1 条 + 备选 1 条，备选须不同机制
- **只给推荐和备选打分**，其余不打分（10 条全打分太重）
