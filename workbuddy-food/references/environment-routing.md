# 环境路由：本地 / 云端，以及浏览器扩展的正确打开方式

> 开工前第一步不是建池，是**先判断自己站在哪台机器上**。
> 本文件配合 SKILL.md「步骤 −1」使用。判定逻辑与四项硬核验不变，只决定「能拿到什么数据」和「结论要降几级」。

---

## 一、两条路径的能力边界

| 维度 | 本地路径（扩展已连） | 云端路径（沙箱 / 无扩展） |
|---|---|---|
| 探测结果 | `browsers_list` 有 `type: "extension"` 实例 | 工具不存在，或只有 `managed`/`desktop` 实例 |
| 身份 | **用户的登录态**，点评/AI 站点认得这个身份 | 匿名，无 Cookie，撞登录墙或滑块只能停 |
| 数据 | 当下渲染的页面 | 搜索引擎抓的**静态快照**，可能停在两三年前 |
| 经营状态 | 地图 POI 显示「营业中／暂停营业」，商户页有闭店公告 | **看不到**。POI 只证明「数据库里还有这条记录」 |
| 评分 | 截图可读加密字体评分、评论数、口味/环境/服务 | 只能拿被索引的点评页片段，是历史存档 |
| 三路 AI 线索 | 可在浏览器里开豆包/元宝/DeepSeek，联网+禁搜两版 | 只能靠 `WebSearch`，拿不到 AI 对话正文 |
| 电话 | 可查到号码并建议用户打 | 同左（但这是云端唯一的验活手段，优先级更高） |
| 结论强度 | 可给「现在能去」的首选 | **必须降级**：默认不给「现在能去」的断言，除非电话验活 |

一句话：**本地是带着你的身份去看当下的店，云端是在搜索引擎的旧报纸堆里翻店**。前者能判生死，后者只能判「历史上存在过」。

## 二、步骤 −1 决策树

```
调 browsers_list
│
├─ 工具不存在（NameNotFound / 未注册）
│   └─ 【云端路径】→ §四：声明降级 + 结论强制降级，不要假装是本地
│
├─ 有实例，但 type 不是 "extension"（managed / desktop / 内置 Chromium）
│   └─ 【身份错误】拒绝使用，走 §三「未安装扩展」询问
│       理由：那是另一个身份，没有用户的登录态，拿到的评分和营业状态都不可信
│
└─ 有 type: "extension" 实例，记下 browser_id
    ├─ §三 身份校验三查
    ├─ 逐站验登录态（AI 三站 + 大众点评 + 地图）
    │   ├─ 已登录 → 【本地路径】正常跑，走 §五 收集候选
    │   └─ 未登录 → §三「未登录」提示，不代劳
    └─ 每轮操作前重新 tabs_list（tab_id 跨轮失效）
```

**不要做的事**：不要用桌面端托管浏览器凑数、不要另起 Playwright、不要替用户扫码或输入凭据。

## 三、两种询问（原技能是「直接停」，改成「问」）

### 1. 未安装 / 未信任扩展

用 `AskUserQuestion`，给三个选项：

| 选项 | 后续 |
|---|---|
| **安装并信任扩展（推荐）** | 提示用户到扩展管理页启用并「信任」，然后重新 `browsers_list` 确认 `type: "extension"` 出现；确认后走本地路径 |
| **走云端降级** | 明确告知会损失什么（见 §四），用户确认后走云端路径 |
| **我自己复核** | 转 `references/manual.md` 五步法，不依赖任何工具 |

问法示例：
> 当前没有检测到已连接的浏览器扩展（只有匿名沙箱通道）。有扩展才能读到大众点评站内实时评分和「营业中／暂停营业」状态。要现在装吗？
> 装了 → 数据最准；不装 → 我只能给「历史上存在过」的清单，且所有店的经营状态都要你电话确认。

### 2. 扩展已连但站点未登录

用 `AskUserQuestion`，给两个选项：

| 选项 | 后续 |
|---|---|
| **我去登录，继续（推荐）** | 停下等待，不代劳；用户说好了之后**重新截图确认**，别假设 |
| **跳过该站，换来源** | 该站记为「未取到站内实时数据」，转 `WebSearch` 抓摘要；损失写在结论里 |

判定口径（先截图再判断，别猜）：
- 右上角是**头像 / 用户名** → 已登录
- 右上角出现**「登录」按钮**、页面弹扫码框、撞滑块 → 未登录
- 小红书/抖音类：只能拿标题 = 无登录态，笔记正文和视频描述看不到

红线：**不替用户登录**，不扫码、不填账号密码、不反复刷新撞滑块（撞一次就停）。

## 四、云端路径的硬规则（上一轮踩过的坑，固化成约束）

1. **禁止把「页面/POI/词条还在」当成「店还开着」**。缓存页面可能停在 2022 年，闭店公告不会被自动标进摘要。
2. 所有候选的 `status` 一律默认 `unknown`；只有拿到**近 3 个月的明确在营证据**（近期评论、商户页「营业中」、电话确认）才允许写 `open`。
3. 逐店补一轮闭店检索：`店名 + 闭店/停业/歇业/搬迁/转让 + 近一年`。看到公告直接 `--status closed` 出局。
4. **口碑数据超 12 个月不计入排序**（脚本已实现）。老店评论数是历史累积，越多越可能是关店前的存档。
5. `status=unknown` 仍可进表，但必须标「未验活」并排在所有 `open` 之后；状态/四项/招牌不再当准入闸门，只影响排序与提示。
6. **结论必须跟着降级**：输出里写明「未取到站内实时评分与实时营业状态」；首选只从 `open` 里选并附电话号码；全是 `unknown` 时不给首选、只给排序线索，写明「出门前电话验活」。
   > ⚠️ 只写免责声明、结论却把「未验活」写成「现在能去」= 违规。限制要传导到结论，不是挂在备注里。

## 五、本地路径：三路 AI 线索的正确打开方式

AI 只是**提供线索的人**，不是证据。收集完仍要逐店核验（步骤 2）。

### 站点与 URL

| 站点 | URL | 备注 |
|---|---|---|
| 豆包 | `https://www.doubao.com/chat/` | 开「联网搜索」和「关闭搜索」两版 |
| 元宝 | `https://yuanbao.tencent.com/` | 同上 |
| DeepSeek | `https://chat.deepseek.com/` | 同上 |

### 操作序列

1. `tabs_new` **直接开上面的 URL**，不要在首页搜索框一步步点。
2. `tab_screenshot` 看右上角 → 判定登录态（口径见 §三）。
3. 未登录 → 停下按 §三 询问，**不要**在游客态硬问（答案更短、更笃定、更错）。
4. 粘贴统一提示词（下），每个站点跑 **联网开 / 联网关** 两版，共 6 份答案。
5. 用 `dom_cua_get_visible_dom` 或截图取回答案，**只提取店名**，地址和评价一律不采信。
6. 单个来源超过 6 家就截断。核验成本才是瓶颈，不是候选数量。
7. 每轮操作前 `tabs_list` 重新拿 `tab_id`。

### 统一提示词模板

```
{城市}{商圈}范围内，{品类}最值得跑一趟的店，列 4–6 家。
每家给出：店名（含分店名）、门牌地址、招牌菜、人均、营业时间。
如果某家不在{商圈}核心步行范围，请明确标注「不在核心」及大概距离。
只列你能确认存在的店，不确定的不要编。
```

### 六份答案怎么用（实测规律，见 sample.md）

| 现象 | 处理 |
|---|---|
| 六个答案几乎没有交集 | 正常。被**两个及以上独立来源**同时命中、且地址价格可核实的，才优先核验 |
| AI 联网答案自己写了「⚠️ 不在 XX 核心」 | 这是它做的范围校正，可信度反而更高，优先采信这条标注 |
| 禁搜答案把别处同名店安到目标商圈 | 逐店搜地址，搜不到直接 `--status closed` 或判同名异地出局 |
| 引用被 SEO 内容农场污染 | 标题带「N 个维度拆解 + FAQ」「人均 N 元起」的，一律不作证据 |

## 六、身份校验三查（判断「是否正确打开了那台 Edge」）

打开之后必须确认连的是**带用户登录态的扩展实例**，而不是沙箱里的另一台 Chromium：

| 查什么 | 通过标准 | 不通过怎么办 |
|---|---|---|
| `browsers_list` 的 `type` | 必须是 `extension` | 是 `managed`/`desktop` → 拒绝使用，走 §三 |
| 页面右上角 | 头像/用户名，不是「登录」 | 用户坚称已登录却显示「登录」→ **连错实例了**，回步骤 −1 重选 `browser_id` |
| 页面内容 | 能读到需要登录才可见的商户详情/笔记正文 | 只有标题或跳滑块 → 无登录态，按 §三 处理 |

三条都过，才算「正确使用了浏览器链接打开 Edge」。任何一条不过，后续拿到的评分和营业状态都不能当证据。
