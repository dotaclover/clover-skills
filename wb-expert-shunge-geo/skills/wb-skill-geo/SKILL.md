# 网优专员工作手册（GEO侧）

> 从当前project brief、合同政策和验收清单确认平台、页面、问题集数量、工具位置与账号授权，缺项询问，不依赖固定仓库或SKU。

开工先读项目事实卡、[SEO地基](references/seo-foundation.md)、`references/geo-operations.md`及`references/geo-measurement.md`。本技能负责GEO方法与测量口径，价格、周期、平台数和交付范围由本项目确认，不内置商业政策。

## 一、GEO到底解决什么

GEO（Generative Engine Optimization）处理的不是“排第几名”，而是：**用户把问题交给AI时，AI会不会提到你、引用你、把你说对。**

先按五问拆开，每问能做的动作不同：

1. **能否被检索到**——AI联网检索多数复用搜索引擎索引或平台自有内容池；没被索引就进不了候选集。
2. **能否被读懂**——切片后的段落是否自包含，实体、时间、地点、数字是否说清楚。
3. **能否被选中**——多个候选源之间，谁更像可靠的一手信源。
4. **说得对不对**——答案里你的价格、范围、地区、名称是否准确。
5. **有没有下一步**——用户看完答案能不能找到你并联系。

第1、2段是工程，能改；第3段是概率，能提高不能保证；第4段是必须守住的底线，错了要立刻修；第5段属于站点承接，回到SEO和服务页设计。

**关键判断：GEO不是SEO的替代品，是叠在SEO之上的一层。** 做过SEO的站做GEO起步快，没做过的先补抓取与索引，跳过地基直接谈“让AI推荐”就是骗人。

## 二、核心理论模型

### 1. AI搜索的四步链路

| 阶段 | 机器在做什么 | 失败表现 | 谁负责 |
|---|---|---|---|
| 召回 | 用搜索引擎索引或平台内容池取候选页 | 答案里完全没有你的站 | SEO地基 + 平台收录 |
| 切片 | 把页面切成段落/块做语义匹配 | 段落被取到但读不懂 | 内容结构（GEO主战场） |
| 选源 | 在候选源中挑“值得写进答案的” | 被取到但没进最终答案 | 权威信号、站外提及 |
| 生成 | 大模型组织语言并标注来源 | 提到你但说错价格/范围 | 事实一致性、时效 |

报告必须写清问题卡在哪一阶段，不能笼统说“AI不推荐我们”。

这条链路是RAG（检索增强生成）的通用形态：问题被改写成若干检索意图 → 从索引取回候选片段 → 按语义相关与来源可信度排序 → 只把少量片段喂给模型 → 模型用自己的话重写并标注来源。

对我们这边意味着三件事：

- **参战单位是段落，不是整页。** 整页写得好但段落不自包含，切出来就是残句，模型读不懂。
- **没进候选就没有第二次机会。** 收录是门槛不是成果；进了索引才有资格被切片和排序。
- **重写会失真。** 来源标注是平台行为，模型改写后未必逐字忠实，所以事实越明确（数字、单位、口径、时间）越不容易被说错；写得含糊的，被含糊地转述几乎是必然。

### 2. 三种引用强度（不能混）

- **提及（mention）**：答案正文里出现你的品牌名，可能没有来源链接。
- **引用（citation）**：答案把某个页面标为来源，用户可点开。
- **推荐（recommendation）**：答案在“选哪家”这类问题里把你列为建议对象。

三者价值与难度递增，**监测必须分开记**。把“提及”写成“推荐”、把“有一次出现”写成“已被AI推荐”是最常见的造假点，也是最快失去客户的方式。

### 3. 排名与引用不同源

传统搜索排名靠前的站，在AI答案里缺席是常态，原因是：

- AI答案通常只容纳3—8个来源，比首屏十连少得多。
- 选源看“能否直接支撑一句话答案”，不看整页相关性。
- 同一问题在不同平台、不同时间、不同账号下答案会变。

所以**不能拿百度排名截图当GEO效果，也不能拿一次AI问答截图当长期结论**。

### 4. 信源分三层（做GEO必须先看清）

| 层 | 内容来源 | 你能做什么 | 说明 |
|---|---|---|---|
| 索引层 | 百度、搜狗、必应、Google、夸克等网页索引 | 提交Sitemap、修抓取、做收录 | 大多数AI联网检索的入口 |
| 生态层 | 头条/抖音（字节）、公众号/视频号（腾讯）、百家号/百科（百度）、知乎等 | 仅作引用来源归因 | 平台内容由客户自行维护，不属于技术优化交付 |
| 权威层 | 行业媒体、门户、协会、公开报道 | 仅作引用来源归因 | 不承接发稿与信源建设 |

三层都要有可见事实，缺一层就有结构性缺口。**具体权重百分比（诸如“某平台占35.2%”）来自服务商宣传，无法验证，一律不写进交付报告。**

### 5. 证据分级（GEO领域谣言极多，必须立规矩）

| 级别 | 来源 | 用法 |
|---|---|---|
| A | 平台官方文档、后台可见状态 | 可直接写入报告并作为动作依据 |
| B | 我方自测可复现（抓日志、curl、问题集实测） | 写入报告，附时间与方法 |
| C | 第三方研究（需标样本量、时间、机构） | 可引用，必须带口径，不转为承诺 |
| D | 服务商话术、行业传闻、无法追溯的百分比 | **不写入交付、不作报价依据、不当策略前提** |

### 6. 什么真的有用，什么只是热闹

有可复现证据支持的方向：

- **页面源码有正文**（AI爬虫JS执行能力弱，空壳站天然缺席）。
- **问句式标题 + 自包含答案段落**（切片后仍能被读懂）。
- **事实锚点明确**（价格区间、服务区域、时长、流程步数，带单位和时间）。
- **内容时效**（显式更新日期且实质更新；被引内容普遍比仅排名内容更新）。
- **品牌提及面**（跨平台同口径提及，比单纯外链更能预测被引用）。
- **实体一致**（同一品牌名、电话、地址、服务名在各处完全一致）。

被大样本证伪或证据不足的方向：

- **`llms.txt`**：可作为文档型站点的目录供支持它的工具使用，不能据此保证抓取或AI引用。历史研究的精确样本/百分比及平台支持结论**来源待核实，不作为决策/效果承诺依据**（线索见操作参考）；仅列为可选项，不视为GEO必要条件。
- **关键词密度、批量伪原创、AI批量灌水站群**：短期可能被抓，长期被降权，且直接违反我们的红线。
- **“保证被豆包/元宝推荐”的套餐**：没有任何平台提供此类保证，属于D级话术。

## 三、技术条件（GEO的可达性门槛）

详细命令、候选UA清单、robots写法、schema字段和自检表见`references/geo-operations.md`。以下UA用途与平台对应关系来源待核实，不作为决策/效果承诺依据；实际放行先核对官方说明、真实来源和用户训练/索引政策，不能仅凭UA字符串测试放宽防护。这里只留判断框架：

- **服务器不拦AI爬虫**：宝塔/WAF/CDN的UA黑名单、Bot Fight、频率限制都可能把AI爬虫挡在门外，且日志里表现为403或521。要放行检索型UA，训练型UA可单独决策。
- **区分训练与检索**：`GPTBot`偏训练、`OAI-SearchBot`偏ChatGPT搜索；封训练不等于封搜索，反之亦然。对客户要讲清取舍，不能一刀切。
- **正文在源码里**：`curl` 拿不到正文的站，先修渲染再谈GEO，不要用“AI很聪明会执行JS”当解释。
- **结构化数据与可见文字逐字一致**：JSON-LD只标页面看得见、客户已确认的事实。
- **有可验证的主体页**：关于、联系、服务范围、价格口径、更新时间，是AI判断“这是谁”的依据。
- **`robots.txt` 与 `sitemap.xml` 正常**：同SEO，不重复造。

## 四、内容可抽取改造（GEO的核心动作）

### 段落级规范

| 规范 | 做法 | 反例 |
|---|---|---|
| 一页一问 | 一个页面回答一个具体问题，问句式H2 | 一页塞十个不相关业务 |
| 自包含 | 每段脱离上下文可读，首次出现写全称+地区+时间 | 「我们提供上述服务，价格另议」 |
| 答案前置 | 段首一句话给出结论，再展开依据 | 先讲行业趋势三段才回答 |
| 事实锚点 | 数字带单位、带口径、带时间 | 「价格优惠」「多年经验」 |
| 可摘取 | 流程用有序列表，参数用表格，问答用Q&A | 长段落叙述流程 |
| 来源可溯 | 每个外部数字标来源或写“客户提供” | 无出处的“行业平均38%” |
| 实体稳定 | 同一主体全站同一写法，不换简称 | 首页“品牌简称”/服务页“未经确认的主体名称” |

### 站内事实一致性

先定一份客户确认的《事实卡》：主体全称、品牌简称、服务区域、价格口径、服务时长、联系方式、可外发的一句话介绍。官网可见文字与JSON-LD只使用事实卡字段，缺项标待补。

## 五、测量方法（GEO最容易糊弄的地方）

完整协议、采样表、判读规则和报告模板见`references/geo-measurement.md`。执行原则：

- **固定问题集**：数量由本项目确认，用于本次基线与变更后复测；临时加题单列，不换基线。
- **固定条件**：同一平台、同一账号状态、同一地区、同一时段、新开会话、逐字提问不改写。
- **分层取样**：约一半问题不含品牌名（测品类可见性），一半含品牌名（测实体准确性）。
- **四档判读**：未提及 / 提及无引用 / 提及有引用 / 推荐；另记“描述是否准确”。
- **如实记录“未提及”**：基线期未提及是正常结果，写成提及就是造假。
- **样本量说明**：一次问答只是一次抽样，报告必须写“本平台本次N条提问、X条提及”，不写“AI已经推荐我们”。

优化目标不是效果保证：交付可达性、结构改造、事实一致性和如实采样记录，平台是否引用不由执行者决定；未提及照实记录，不改结果迎合预期。

## 六、工作流

1. 读取当前project brief、事实卡和验收清单，确认平台、页面、问题集数量及客户目标；超范围动作交主理人评估并取得用户确认，不默认平台或费用。
2. 取客户已确认的《事实卡》素材；缺项标“待补”，不编造年限、案例、评价、价格。
3. 跑只读基线：抓取可达性、AI UA放行情况、正文可读性、结构化数据、实体一致性，按P0—P3排序。
4. 执行一次性技术可达性、页面可抽取改造与站内事实一致性检查。
5. 建立基线问题集并实测一次，形成GEO基线表；这一步和数据改造分开记录。
6. 开发/预渲染/批量改造另行评估授权，故障交`site-rescue`，未上线交`site-launch`。
7. 通过SendMessage向主理人回传：范围、证据分级、已完成动作、未提及如实结果、客户待办、下一步。

## 八、红线

- 不承诺被提及、被引用、被推荐、首屏占位、AI引用率提升、竞品挤出。
- 不把“提及”写成“推荐”，不把一次抽样写成长期结论，不把已提交写成已收录，不把收录写成引用。
- 不引用无法追溯的权重百分比、白皮书结论和服务商案例作为交付依据（D级证据）。
- 不买软文刷量、不刷评价、不做自问自答式假问答、不做AI批量灌水站群、不做cloaking。
- 优先用户持有平台账号并授权最小权限协作者；不默认代持。确需例外须先明确书面授权、期限、数据可见性、撤销及移交方案并符合平台规则；用户自行完成实名和付费。与SEO采用同一规则。
- 不删客户站上已有的真实内容去“重写一版更好喂AI的”，改稿必须留原稿和客户确认记录。
- 平台规则与入口会静默变化，所有结论标注实测时间；不拿三个月前的经验当今天的事实。
- 完成后通过SendMessage向主理人回传，不与其他成员直接通信。
