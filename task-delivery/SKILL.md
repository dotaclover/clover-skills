# 通用任务与交付

## 输入与开工门槛

接收显式任务上下文：`project_root`、`input_paths`、`output_dir`、`private_state_dir`、`skill_root`、目标环境、provider/账号/项目、目标、唯一结果负责人、允许访问与修改范围、验收标准、预算币种及上限、禁止事项与待确认点。路径相对 project_root 解析，缺项先问，不假设仓库布局或桌面目录。

先确认 `project_root`；只有该目录属于 Git 工作树时才在该目录执行 `git status --short`，非 Git 项目检查实际文件清单与备份。读取相关文件后修改；保护用户未提交工作，不覆盖不明来源文件。客户材料、凭据、任务原始响应与账单放私有交付目录，不进入Git或公开报告。

将授权分为只读、文件修改、外部上传、收费提交、生产变更、发布、删除；前一类不自动包含后一类。挂载技能、账号已登录、Key可用都不是授权。默认不提交Git、不部署、不发布、不付费；任务明确授权的范围内才执行。

## 执行闭环

1. 建立任务记录：目标、范围、负责人、输入版本、验收项；标记进行中。
2. 先保存基线。变更既有系统前备份文件、配置及涉及的数据，记备份位置并在隔离环境验证恢复；没有验证就明确写“备份存在，恢复未验证”。保留回滚步骤，回滚前也保护当前状态。
3. 先在本地或测试副本实施最小改动；每一步记录命令、时间、退出码、关键输出与产物位置，脱敏凭据及私人资料。
4. 执行匹配任务的测试：代码运行/测试、网页真实浏览器、媒体实际播放与规格、文案事实核查。不能用源码阅读代替运行，也不能用HTTP成功代替业务成功。
5. 对照验收标准逐项写通过/失败/未验证/不适用及证据。前端桌面1440与移动390分别操作导航、按钮、表单、图片与控制台，逐页截图；正式部署另在正式地址复验，不拿本地结果冒充。
6. 失败保留现场并定位；超出范围先报告并等待新授权，不通过删除数据、关闭安全检查或重复付费提交解决阻塞。
7. 交付可打开的文件、运行说明、实际验证结果、限制与遗留事项。撤销本次临时权限并提醒更改临时密码；未获授权不替用户修改账号。

## 付费任务证据

提交前确认内容、规格、数量、渠道、费用依据与上限。默认一份，不增加备选。提交即保存渠道/账号配置来源（不含密钥）、请求版本、幂等键（如支持）、任务ID、HTTP状态及request_id。超时先查原任务；未核实幂等语义不自动重试写请求。失败、取消和超时不等于免费。

区分预计费用、usage用量、实际结算和币种；没有账单标待核实。将凭证交留名按任务去重登记，不把星桥专属计价推广到其他渠道。

## 回传模板

通过SendMessage向主理人一次回传完整内容：

- 实际完成与未完成：按任务项列明。
- 验证：方法、命令/操作、退出码或实际结果、证据路径。
- 产物：文件/运行入口、配置说明、版本。
- 费用：渠道、任务ID、预计/用量/结算、凭证位置；未知项明确标记。
- 风险与下一步：遗留问题、回滚位置、所需用户决策。

复核未通过不得写“完成”；检查报告不得冒称修复或完整安全审计。短剧、自媒体、教程分别按各自验收口径，不混用素材与结论。
