# 后台交付演示参考

按项目实际功能裁剪，不固定时长、步骤数或主题插件组合。前提是本项目验收清单已通过、用户角色已确认；优先测试副本，生产写入及录屏另获授权。客户操作、执行者指导，凭据和个人数据不进入录屏。

## 前台与后台关联

1. 在目标设备打开前台，指出内容、站点资料、导航和联系入口分别在哪里维护。
2. 登录后台，解释角色权限及常用入口。菜单隐藏不是权限控制。
3. 用测试页面修改一段文字，等待保存完成，前台刷新验证；保存前后原值，按授权恢复。
4. 使用测试资料演示电话、营业时间、图片和配色；不得误拨真实电话、发送真实通知或覆盖他人并发修改。
5. 若有预约/询盘功能，使用明确标记的测试对象，记录ID、后台状态和通知结果。邮件提交不等于送达，不假定演示环境必然没有SMTP。

## 三类变更先说明影响

- 更换主题或模板可能改变布局，先在副本验证并备份。
- 停用插件可能影响表单、内容类型、权限及安全功能，核对依赖后决定。
- 删除页面或用户须确认引用、内容归属和恢复方式；优先回收站/转移内容，不默认整站回滚或永久删除。

## 交接

交接当前项目使用说明、操作证据、备份位置与恢复验证。新页面、新语言、商城、支付等由当前合同确认范围，缺项先评估，不内置不接规则或套餐价格。支持期限及响应窗口按合同告知，不承诺固定天数。

清理仅限本任务创建且用户确认的测试对象；核对原有业务记录、用户和设置与基线差异，不要求总数为零。安全交接账号，撤销临时权限。

## 常见问题

| 问题 | 处理 |
|---|---|
| 保存后前台没变化 | 先确认保存完成，再查浏览器/CDN/页面缓存；依据实测响应头说明刷新策略，不承诺固定缓存分钟数 |
| 想换结构 | 说明与换配色不同，按项目变更流程确认 |
| 邮件没收到 | 查后台记录、发送日志、收件箱及垃圾箱，按实际SMTP状态排查 |
| 需要其他同事编辑 | 按工作职责授予最小必要权限，不默认管理员 |
