# 搜索平台验证与索引提交

仅处理用户拥有或书面授权的站点。平台能力、入口、配额和权限以执行当日官方后台核实，不把历史站点状态当通用事实。账号优先由用户持有，我方作为最小权限协作者；不默认代持。例外必须事先书面授权，确认期限、数据可见性、平台限制、撤销与移交方案；实名、付款及签字由用户完成。此规则与SEO/GEO主技能一致。

## 官方入口与公开协议（不是私人环境配置）

保留公开入口用于定位官方后台；执行当日核对跳转、功能及账户权限，不将入口可达等同服务状态。

| 平台 | 官方入口 | 常用后台路径/公开协议 |
|---|---|---|
| 百度 | `https://ziyuan.baidu.com/` | 站点管理→验证；资源提交/普通收录→Sitemap、手动或API |
| Bing | `https://www.bing.com/webmasters/` | Sitemaps、URL Inspection、Settings→Users |
| Google | `https://search.google.com/search-console` | 资源选择→Sitemaps；URL检查→请求编入索引；设置→用户和权限 |
| IndexNow | `https://www.indexnow.org/` | 站点key验证与变更通知，公开端点`https://api.indexnow.org/indexnow` |
| 头条搜索 | `https://zhanzhang.toutiao.com` | 先核对当前官方落地页和可用提交功能；`search.volcengine.com`是否接管须现场确认 |

百度公开提交接口结构为`https://data.zz.baidu.com/urls?site=<规范站点>&token=<本次站点token>`，真实地址/权限以后台为准。请求体为逐行URL文本；不把真实token写到命令历史或报告。IndexNow批量通知结构如下，主机、key与URL须来自获授权站点，实际方法、端点与配额核对当前官方规范：

```json
{
  "host": "example.com",
  "key": "CLIENT_INDEXNOW_KEY",
  "urlList": ["https://example.com/page-a", "https://example.com/page-b"]
}
```

Google网域属性通常通过DNS TXT验证，URL前缀属性按后台选择HTML文件/标签等方式。Bing可按用户批准从GSC导入；百度、Bing和Google的角色名称/可授权能力不同，不把完全访问者等同所有者。需要移交时先让用户以自身账号完成当前挑战并核实所有权，不能复用旧文件假定“秒过”。

## 提交前

1. 从project brief取得规范域名、页面清单、平台范围和发布权限；工具路径从当前工作区核实。
2. 只读检查HTTPS、重定向链、状态码、正文HTML、robots、sitemap和canonical。示例中的`example.com`均为不可直接执行的占位，先替换为获授权目标。
3. sitemap仅收录预期可索引的规范URL，剔除404、重定向、重复和noindex页面；`lastmod`使用真实更新时间。
4. 记录基线、账号归属、角色、验证方式和待提交URL；上传验证文件、改DNS、改配置及平台提交均为外部变更，先获授权。

## 百度搜索资源平台

- 在用户账号添加准确协议与域名，用当次后台提供的文件、标签或DNS方式验证。使用原文件内容，不复用其他站点token。
- 按后台实际权限提交sitemap、少量规范URL或使用API；接口地址与token从当前站点后台取得，token放秘密管理中，不进入命令日志、前端或报告。
- 只推送新增/实际更新URL，去重并记录返回、失败项及配额。成功仅表示接收通知。
- 使用抓取诊断、抓取异常、索引量和日志定位问题；`site:`只是辅助观察，不是完整统计。
- 死链/改版提交需精确核对已删除页面与新旧URL映射并授权。移动适配仅在独立移动站且内容一一对应时考虑；响应式同URL站不盲目提交适配。
- Logo、子链、品牌展现按当期资格、尺寸及审核要求准备，不把历史VIP规则或固定反馈天数当承诺。

## Bing Webmaster Tools / IndexNow

- 用户账号加站，按后台支持的XML、Meta或DNS方式验证；从其他平台导入需用户确认数据授权。
- 提交sitemap并核对读取状态、发现URL与错误；可在robots声明sitemap，不使用过时的匿名ping接口。
- 需要IndexNow时，按官方当前规范生成站点级key文件并验证可访问，仅通知真实新增/更新/删除URL；记录请求及响应。key文件按协议公开不代表账号秘密可以公开。
- URL检查与索引报告用于观察，通知不等于抓取、索引或生成式答案引用。

## Google Search Console

- 用户选择网域属性（DNS验证）或URL前缀属性（后台支持的验证方式），确认覆盖实际规范域名。
- HTML验证必须使用当前后台下载的文件名和原始字节，不硬编码旧文件名、字节数或`www:www`属主；按现场服务权限部署。
- 网络不可达先核对DNS、TLS、路由和用户已授权的网络环境；不假定特定浏览器SSO必然可用，也不擅改代理。
- 平台超时先比较访问日志、DNS、CDN/WAF和验证URL；有200不等于验证已通过，无源站日志不等于平台故障，以后台最终状态为准。
- 提交sitemap；少量页面使用URL检查→请求编入索引，保存反馈。普通网页没有保证收录的通用API；专门Indexing API仅在符合当前官方内容资格时使用。
- API需OAuth与正确资源权限；不能把Search Console API当强制索引接口。

## 其他搜索平台

先核实官方入口、当前是否提供网站提交、可用账号角色及robots要求。不要把某搜索平台收录当作某AI产品必然召回的前置保证。爬虫用途和放行策略由用户确定，核对官方UA与来源验证，不仅凭伪造UA放宽安全防护。

## HTTP验证例外

先请求实际验证文件并检查跳转。仅在平台确实要求且用户批准时为精确验证路径设置HTTP例外，改前备份、配置测试后重载；普通页面HTTPS策略保持不变。参见 `../../ops-deploy/references/hosts.md`。不要声称已有白名单或把所有验证前缀放行。

## 账号交接

1. 开工记录用户所有权、执行者角色、操作范围及到期时间；没有协作者功能时由用户执行敏感步骤，不自动借用自有账号。
2. 如存在获批临时代持，先导出必要的索引、提交、sitemap及权限基线，再按当前平台支持的移交/重新验证流程建立用户所有权。
3. 用户确认可访问及管理后，按批准清单撤销我方权限。删除站点资源、验证文件或token可能影响权限和数据视图，须单独确认，不作为默认收尾。
4. 不保证重新验证秒过、历史数据保留或配额不变；以平台当前规则和实际结果记录。
5. 验证文件是站点级资产，按移交策略保留；账号密码、API token通过安全渠道管理，不放报告或录屏。
