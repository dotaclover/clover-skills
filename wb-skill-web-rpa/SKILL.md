# 网页RPA：把重复操作做成可复用流程

## 使用边界

本技能给的是方法与验收口径，不是某个平台的接口文档。页面结构、登录方式、风控规则随时会变，所有元素定位、等待条件与限速都必须按当次实测确认，不能照抄历史结论。涉及账号登录、批量写入、对外发送、付费操作时，先取得明确授权，授权范围一次有效，不因"上次允许过"自动延续。

**默认只读优先**：能只读拿到数据，就不要用模拟点击。能用页面自带导出、公开接口、RSS、站点地图解决的，不写自动化。

## 什么时候该做 RPA

| 适合 | 不适合 |
|---|---|
| 同一套动作每周重复，页面上没有批量入口 | 只做一次，做完就再也不用的活 |
| 数据在页面里，没有导出或接口 | 官方有 API、导出或订阅，只是没去找 |
| 需要按规则逐条录入、核对、下载 | 需要人判断、协商、改写内容的活 |
| 步骤固定、失败可重试、结果能机器校验 | 涉及风控绕过、验证码破解、绕过付费墙 |

**不做**：破解验证码、绕过登录与付费、伪造身份、批量注册、刷量刷评、抓取明确禁止抓取的隐私数据。遇到这类需求，说明风险并给合规替代方案。

## 开工前的六项契约

拿不到就先问，不要拿假设开工。

1. **目标**：这次要产出什么（一张表、一批下载、一次录入），怎么算完成。
2. **授权**：操作哪个网站、哪个账号、哪些数据；只读还是可写；允许的时间窗与频率。
3. **数据规格**：字段、去重键、编码、落盘位置、命名规则、是否允许覆盖。
4. **失败处理**：可重试次数、重试间隔、遇到验证码/登录过期/弹窗时停下还是跳过。
5. **限速**：每分钟请求数或操作数上限，避免把对方服务打挂。
6. **验收**：抽查比例、比对基准、证据形式（日志、截图、结果文件）。

## 标准流程

严格按顺序，前一步不通过不进下一步。

1. **摸页面**：手动走一遍完整路径，记录入口 URL、登录态、分页方式、懒加载触发条件、结果落点。把每一步写成"动作 → 预期变化"。
2. **定策略**：优先选稳定的定位方式。顺序是：语义节点（role/label/可访问名）> 稳定属性（name、data-*）> 相对结构 > 文本 > 坐标。坐标只作兜底，且必须每次现量。
3. **单步复现**：一次只做一个动作，做完立刻读状态确认。动作返回成功不等于页面已经变化。
4. **小批量试跑**：取 3—5 条真实数据跑通全链路，含一次失败与一次重试，检查去重、编码、落盘。
5. **全量执行**：按限速跑，边跑边记日志。每处理 N 条落一次检查点，支持从断点继续。
6. **验收比对**：抽样人工核对，总数、去重后数量、字段完整率、异常条目分列；与基准表逐项对。
7. **交接**：交付流程说明、参数表、日志位置、失败样本、重跑方法，以及"页面改版后先改哪一处"。

## 稳定性要点

- **等待条件化**：等具体元素出现、文本变化或网络空闲，不用固定睡眠秒数。固定 sleep 在慢网必炸，在快网白等。
- **幂等**：同一条记录重复执行不产生第二条结果。写入前先查存在性，或用唯一键去重。
- **断点续跑**：进度落盘（已处理 ID 或页码），中断后不从头再来，也不重复写。
- **限速与退避**：失败重试用递增间隔，连续失败到阈值就停，不无限重试掩盖问题。
- **登录态**：只在用户已授权的浏览器窗口里操作，不读取、不保存、不代填密码。登录过期就停下请用户处理。
- **弹窗与遮挡**：新版本公告、Cookie 提示、引导浮层会挡住点击。先按可关闭控件处理，关不掉就截图说明并停下。
- **单页应用**：切页不刷新页面，URL 可能不变。以内容区域的实际变化判断是否加载完成。

## 采集类专项

- 先确定唯一键（ID、URL、编号），没有唯一键就先造一个稳定指纹。
- 字段映射写成表：页面位置 → 字段名 → 类型 → 缺失时填什么。缺失不要留空字符串冒充 0。
- 分页有上限、有"加载更多"、有滚动加载三种，做法不同；先确认到底属于哪种。
- 翻页到重复内容即视为到底，不靠"下一页按钮消失"单一判断。
- 编码统一 UTF-8，CSV 用带 BOM 或明确说明；数字与日期保持原始精度，不在采集阶段做四舍五入。

## 写入类专项

- 先在一份测试数据上跑通，再上真实数据；测试数据要能一眼认出、事后能删。
- 每条写入前后各留一次状态证据；批量写入前先备份原数据或导出快照。
- 提交前把关键字段回读一遍，确认没有被页面自动改写（单位、日期格式、下拉默认值）。
- 失败条目单独成表，写明失败原因与页面提示原文，不混进成功结果。

## 下载认领

- 下载前记录目录基线，下载后按新增文件 + 浏览器下载记录双重认领，不只看最新修改时间。
- 同名文件会被追加编号，多文件逐张核对归属。
- 存在临时后缀（如 `.crdownload`）时，先确认写入稳定，再判断完成。

## 验收清单

细节项见 `references/checklist.md`。最低要求：

- [ ] 目标数、实际数、去重后数三个数字能对上
- [ ] 抽样 5% 人工核对，错误条目有归因
- [ ] 失败条目可复现、有页面提示原文
- [ ] 断点续跑实测过一次（中途 kill 再续）
- [ ] 日志能还原"第几条、做了什么、结果如何"
- [ ] 交付物里没有账号密码、Cookie、密钥

## 输出规范

交付时分四块，不合并成一段话：

1. **方案**：目标、范围、授权、策略、限速、失败处理。
2. **结果**：结果文件路径、条数、字段说明、异常条目。
3. **证据**：日志、关键截图、抽样核对记录。
4. **交接**：怎么重跑、怎么改、页面改版时先看哪里、已知限制。

不把"跑完了"当验收；不把脚本存在当交付。未实际执行的步骤标"未执行"，不写成已完成。

## 沉淀

跑完一轮，把这次真实踩到的坑写回本技能的 `references/checklist.md` 或项目记录：哪类定位失效、哪个等待条件不成立、哪种重试策略有效。只写能纠正下次行为的结论，不写感想。
