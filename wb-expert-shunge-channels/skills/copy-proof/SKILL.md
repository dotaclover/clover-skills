# 对外正式稿校对

校对面向的是**要交出去的文字**：客户交付说明、公开文案、公众号与视频号稿件、报价与合同附件。判断标准只有一个——**对方看得懂、看得下去、看得放心**。

不是润色，不是重写。用户给的每一句话都要当成事实来源保留，**但不要把它再复述一遍**。

## 四项硬要求

### 一、脱敏

凡是能定位到具体人或具体客户的信息，一律替换，不做模糊化处理：

| 类型 | 处理 |
|---|---|
| 真实姓名 | 客户A、张先生、负责人 |
| 手机号、微信号、QQ、邮箱 | 手机号、微信号（不保留任何位） |
| 公司全称、门店名、项目代号 | 某公司、某门店、该项目 |
| 身份证号、银行卡、订单号、合同号 | 身份证号、订单号 |
| 服务器IP、域名、后台地址、账号 | 服务器地址、后台账号 |
| 真实价格与未公开报价 | 按合同价、另议 |
| 未公开的内部数据 | 内部数据（不写数值） |

替换后**不能出现部分保留**：写`138****1234`、`某科技有限公`、`xxx.com`都算没脱敏。测试环境地址、内部系统名同样按敏感处理。

### 二、合规

| 项 | 处理 |
|---|---|
| 极限词 | 最好、第一、唯一、100%、全网最低 → 改成可核对的表述 |
| 承诺 | 保证过审、稳赚、包上线、绝对安全 → 删掉或改成已做到的事实 |
| 导流 | 微信号、二维码、外链、"私信领资料" → 交付稿里默认删 |
| 资质与效果 | 医疗、金融、法律类断言必须有依据，没有就写经验 |
| AI 内容 | 按现行要求披露，不明确就留一句提示给用户 |
| 他人信息 | 未经授权的客户案例、截图、评价一律不用 |

**合规不是删信息，是换说法。** 删掉客户想表达的意思，等于把活干废了。

### 三、用语规范化（不用开发语言）

面向客户和普通读者的稿子，**不出现工程与开发术语**。改法如下：

| 不要写 | 改成 |
|---|---|
| 接口、对接接口 | 打通、连上、能自动同步 |
| 字段、参数、返回值 | 信息项、设置、返回结果 |
| 部署、上线、回滚 | 发布、正式启用、退回上一版 |
| 报错、异常、堆栈 | 提示错误、打不开、卡住 |
| 配置项、环境变量 | 设置项、后台参数 |
| 实例、服务器、容器 | 服务器（能不写就不写） |
| 缓存、清理缓存 | 刷新、重新加载 |
| 权限、角色、Token | 账号权限、登录凭证 |
| 脚本、定时任务 | 自动执行的操作 |
| bug、修复bug | 问题、已修好 |
| 迭代、版本号 | 更新、这一次的改动 |

原则：**说结果，不说实现。** 客户关心"能不能用、什么时候好、要花多少"，不关心怎么做到的。

### 四、不重复原话

- 终稿里不出现"您提到／您说的是／如前所述"这类复述铺垫。
- 不把原句换几个词再说一遍凑字数，能删就删。
- 修改说明只列改动本身，不整段引用原文。
- 同一个意思全文只出现一次，后面重复的一律删。

## 正式版文字标准

- 称谓统一用"您"，不混用"你"。
- 书面语，去掉口语碎屑：啊、呢、吧、其实、 basically、然后呢。
- 不用网络用语与表情符号；不用连续感叹号。
- 数字用阿拉伯数字；中文与英文单词、数字之间不加空格（用户口径）；`·` 与 `/` 两侧留空格。
- 一段不超过 3 行，长句拆开。
- 同样的专业名词第一次出现时用一句人话解释，后文直接用简称。

## 六层检查

按顺序过，前一层有硬错误先停下问，不带着事实错误往下校。

| 层 | 查什么 | 处理 |
|---|---|---|
| 1 事实 | 数字、人名、公司名、价格、日期、时长 | 与用户给的信息核对；对不上标【待核：字段】并问一句 |
| 2 脱敏 | 见上表 | 一律替换，不部分保留 |
| 3 口径 | 同一事物前后叫法是否一致 | 统一成一个，列出被改的位置 |
| 4 用语 | 开发术语、口语碎屑、网络用语 | 按对照表改 |
| 5 合规 | 极限词、承诺、导流、资质、AI 披露 | 给替换写法，不直接删信息 |
| 6 逻辑 | 前后矛盾、因果跳跃、时间倒置 | 只指出并给最小改法 |

错别字与标点在第 4 层一并处理。

## 输出格式

**终稿放最前面**，用户复制就能用；说明放在后面，不影响取用。

```
【正式版】
（可直接复制，已经是成品，不含批注）

【改动说明】
  位置 | 原文片段 | 改为 | 原因
  原因只用四类：事实错误 / 未脱敏 / 不合规 / 表达不清

【待核】
  逐条列出不确定的事实，附建议核实方式
```

## 三条铁律

1. **不改原意。** 觉得表达不好但没错，最多在末尾附一行"可选建议"，不动终稿。
2. **不猜事实。** 不知道的数字不填不改，标【待核】。
3. **不静默改动。** 终稿每一处改动都能在说明里找到对应行。

## 常见误报（不要改）

| 看起来像错 | 其实是对的 |
|---|---|
| 剧名、产品名与常见写法不同 | 以设定总表或品牌 brief 为准，先查再改 |
| 口语化短句、缺主语 | 短视频口播本来就该这样，不改 |
| 重复某个词 | 口播重复是强调手段，明显冗余才删 |
| 数字不规整（99+、8:59） | 剧情或事实需要，不改 |
| 客户坚持的行业说法 | 属于客户口径，先问再改 |

## 边界

- 不承诺过审与流量。
- 不替用户核实外部事实（无联网授权时不查），只标【待核】。
- 不做翻译、不做改写、不做降 AI 味处理。
- 不把客户原文改到看不出原意；改了意思要在说明里写明并请用户确认。
