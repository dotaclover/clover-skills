# 分层现场排障

先读取当前project brief、诊断记录、合同政策和验收清单。范围、费用、工时上限、服务窗口及退款抵扣按当前项目确认，缺项询问，不依赖固定SKU或仓库。应用、环境和复核负责人按项目指派；授权不明、目标不明先停止。诊断见 `site-audit`，修复记录见 `site-maintenance`，疑似入侵见 `site-incident`。

## 一、先问三句（决定排查方向）

1. **什么现象**：打不开、白屏、报错码、错版、内容变了、慢、还是收到提示？
2. **什么时候开始、之前动过什么**：改过代码、装过插件、换过主题、续费忘了、服务器重装过？
3. **有没有备份、备份验证过吗**：没备份的，动手前先做一份，并写明「未验证可恢复」。

## 二、分诊（一句话现象 → 先查哪一层）

| 客户说的 | 优先怀疑 | 先看 |
| --- | --- | --- |
| 完全打不开、超时 | DNS / 安全组 / 服务没起 | 解析、端口、nginx 状态 |
| 白屏、500、502、504 | 应用或 PHP-FPM | 错误日志、FPM 状态 |
| 403、404 | 权限、入口、伪静态 | 目录属主、`index`指令、rewrite |
| 样式乱、图片不显示 | 路径、缓存、静态资源 | 资源路径与状态码 |
| 后台进不去、一直跳转登录 | 缓存、cookie、站点 URL | 站点 URL 配置、插件冲突 |
| 只有某地区/某网络打不开 | 解析线路、运营商、CDN | 多地点 ping、CDN 节点 |
| 证书警告 | 证书过期、域名不匹配、中间证书 | 证书到期日与链完整性 |
| 页面出现陌生内容、被跳转 | 被挂马、被篡改 | **转 site-incident，不在这里硬修** |

详细对照表见`references/fault-playbook.md`。

## 三、逐层定位（不跳层，别一上来就改代码）

1. **DNS**：`nslookup` / `dig` 看解析是否指向预期 IP；换线路解析要分地区验。
2. **网络与端口**：`ping`、`curl -I`、安全组与防火墙是否放开 80/443；服务器负载与磁盘。
3. **Web 服务**：`systemctl status nginx`、`nginx -t`、PHP-FPM 状态、错误日志`error_log`。
4. **应用**：WordPress 看`wp-config`常量、插件/主题冲突（禁用排除法）、固定链接与伪静态；Hyperf/Go/Python 看 systemd 日志与进程。
5. **数据**：数据库能否连、表是否损坏、磁盘是否满、备份能否恢复。

每一层都先**记录证据**（命令 + 输出 + 时间），再动手改。

## 四、改之前三条铁律

1. **先完整备份，并验证能恢复**；验证不过的写「未验证」，不写成「已备份」。
2. **在副本上先验证**修复动作，通过再动正式站。
3. **留回滚路径**：改完不达标就回滚；回滚后仍收诊断费与已发生工时。

## 五、范围与停手

| 情况 | 动作 |
|---|---|
| 授权内单点故障 | 备份→副本验证→获批正式修复→复测记录 |
| 升级、迁移、多问题叠加 | 评估兼容、写入冻结、数据同步和回滚，另确认范围 |
| 超出约定工时/预算、涉及支付或数据覆盖 | 暂停并给证据与影响，用户批准后继续 |
| 反复篡改或后门迹象 | 转 `site-incident`，先止损留证 |
| 修复不如重建 | 给技术依据与方案，不擅自重做或确定抵扣规则 |

提前确认停止条件和工作量边界，不使用固定金额、文件数或一天上限。

## 六、交付与红线

- 交付一份处理记录：问题、根因、改了什么、怎么避免、遗留事项、已用工时。
- 验收看「客户报的现象消失且可复现验证」，不是「看起来好像好了」。
- 记录里写事实，不写「已修复」「已安全」「绝对不会再被黑」。
- 不做等保测评、不出渗透测试报告、不出合规证明、不承诺解封。
- 不碰未授权站点，不爆破、不绕过权限、不做渗透；凭据不进仓库或录屏。
- 临时权限最小化，处理结束撤销并提醒客户改密码。
- 服务窗口、响应和待命范围按本项目合同确认；响应时间不等于修复时限，不内置SLA。
