# 常见报错与处理

以当前响应中的 HTTP 状态、`error.code` 和 `error.message` 判断原因。型号列表用于选择型号，不表示实时健康度；同一型号在不同时间、不同 Key 下的结果可能不同。

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| HTTP 400，参数或请求格式错误 | 接口与任务类型不匹配、缺少必填字段、尺寸或时长格式错误 | 按文本、图片或视频示例检查请求路径和字段类型；根据错误信息修改后再提交 |
| HTTP 401，鉴权失败 | 当前发送的 Key 错误或已失效 | CLI 返回 unauthorized 并清理型号缓存；先检查 auth status 的来源，旧环境变量会覆盖安全存储，不输出 Key。不自动删除已存凭据；确认已保存凭据确实失效后，才向用户索取新 Key 并用 `auth set --stdin` 覆盖 |
| HTTP 403，无权访问 | 当前 Key 没有对应型号或接口权限 | 检查 Key 权限和可用型号，必要时联系服务方开通 |
| HTTP 404，找不到型号或接口 | 型号 ID、路径错误，或型号列表已调整 | 重新获取 `/v1/models`，使用完整 `data[].id`，检查 Base URL 与路径拼接 |
| HTTP 429，提示频率或并发限制 | 请求过快或同时运行的任务过多 | 降低并发，按 `Retry-After`（如有）等待后重试，避免连续立即重发 |
| HTTP 429，提示额度、余额或使用额度 | 账户、Key 或服务侧可用额度不足 | 检查余额和 Key 额度；余额充足仍报错时联系服务方，避免反复重试 |
| HTTP 5xx，服务错误 | 服务暂时异常或负载较高 | 稍后有限次数重试；持续失败时向服务方提供错误信息和请求 ID，隐藏 Key |
| HTTP 520–527，网关错误（常见 524） | 边缘网关等待源站超时，多为该型号上游长时间无返回 | 加大客户端超时后原样重试无效；按下方“单型号无响应判定”换型号验证 |
| 客户端超时、连接断开 | 网络中断、排队或处理时间超过客户端等待上限 | 合理增加等待时间；超时不代表服务端未处理。视频已有任务 ID 时先查询原任务，避免重复生成与计费 |
| HTTP 200，但文字截断或为空，`finish_reason: length` | 输出上限不足；部分型号的推理也会占用 token 预算 | 适当提高 `max_tokens` 或对应接口的输出上限，或简化请求，并确认结束原因 |
| 视频一直为 `queued`、`running` 或 `in_progress` | 仍在排队或生成 | 间隔查询原任务；长时间无变化时联系服务方，不重复创建相同任务 |
| 视频状态为 `failed` | 输入、素材、内容要求或生成过程出错 | 停止轮询，读取任务的错误字段；按提示修正输入或联系服务方 |
| 素材读取失败或结果链接失效 | URL 无法被远端访问、需要登录或签名已过期 | 提供可公开读取且在处理期间有效的 HTTPS 地址；成片完成后及时保存 |

## 单型号无响应判定

型号列表只说明“存在且有权访问”，不代表该型号当前可用。按以下顺序判定，避免把服务端故障当成客户端等待不够：

1. 用响应最快的文本型号发一条最小请求（如 `max_tokens` 很小的一句），确认 Key、额度、Base URL 正常。
2. 文本正常而目标型号超时或返回 524，判定为该型号通道问题，不要继续排查 Key 或账户。
3. 用同系列另一个型号提交同一请求，区分“单型号不可用”和“整条链路不可用”。
4. 客户端超时已设到 180–300 秒仍无任何响应，停止加大等待时间，换型号；视频场景先按任务 ID 查询原任务。
5. 上游故障常被包装成 `error.message: "openai_error"`、`error.code: "bad_response_status_code"`，此时以 HTTP 状态判断原因，不要按 `error.code` 的字面含义推测。

图片型号之间可互相替代测试同一提示词：`gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`qwen-image-3.0`、`wan2.7-image-pro` 均为 `POST /v1/images/generations`，只改 `model` 字段即可。

## 请求格式排查

- 视频型号使用视频创建接口，例如 `wan3.0-video-prime` 使用 `/v1/videos`，不要套用 Chat Completions 请求体。
- `wan2.6-image` 提示缺少参考图片时，提供参考图片的 JSON 输入，或使用 multipart 图片编辑格式，见 [图片接口](images.md)。
- HappyHorse 参考图片使用 `input.media[].type: "reference_image"`，视频编辑的源视频使用 `type: "video"`，见 [其他视频请求](other-video.md)。
- 图片响应按实际字段处理：`b64_json` 需要 Base64 解码，`url` 需要下载；不要将 JSON 响应直接当作图片文件。
- 请求返回成功状态不等于视频已生成完成；查询到完成状态后再下载。下载失败先重新查询原任务获取结果，避免重新创建。
