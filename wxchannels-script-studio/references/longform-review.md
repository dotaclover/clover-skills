# 长视频对比测评口播（形态 F）

> 适用：两个工具 / 产品 / 方案的横向测评，180–240 秒，纯口播。
> 和 A–E 的区别：**不追求单点爆点，追求"听完觉得你说得公道"。**
> 案例来源：一条 3 分钟的「Codex vs WorkBuddy」对比稿，成稿结构就是下面这套。

## 一、什么时候用 F

| 用 | 不用 |
| --- | --- |
| 两个东西都有人问"该选哪个" | 只有一个产品要卖（走 A 知识科普或 D 教程） |
| 两边都有明确短板，你能公道地说出来 | 你只深度用过一边，另一边靠听说 |
| 30 秒讲不完，必须展开 | 只想抛一个结论（走 C 观点洞察） |

**前提**：两边都要有真实使用经验。缺一边就别写 F，写成"我为什么选 A"更诚实。

## 二、九段骨架（3 分钟版）

| # | 段 | 时长 | 这一段干什么 | 语气 |
|---|---|---|---|---|
| 1 | 开场 | 15s | 从一个具体提问切入（"前两天有人问我…"），声明不吹不黑、短板也讲 | 聊天式，放慢 |
| 2 | 定位 / 来路 | 18s | 各自从哪长出来的，服务的是不是同一拨人 | 平铺 |
| 3 | 干活方式（痛点） | 30s | **全片重点**：各自治的是什么痛点 | 说透，语速稍慢 |
| 4 | 各自的短板 | 32s | 你擅长的领域里，对方的短板；再反过来说自己的 | 转折处停顿，短板处加重 |
| 5 | 生态 / 能接什么 | 22s | 接的是"代码世界"还是"公司正在用的东西" | 稍快 |
| 6 | 自动化 / 人不在时 | 22s | 定时、远程遥控、谁值守 | 平 |
| 7 | 安全 | 20s | 两边管法不同：一个防"它乱动手"，一个防"谁在用它" | 平 |
| 8 | 上手与花费 | 18s | 订阅制还是积分制，谁更零成本 | 轻松 |
| 9 | 总结 / 怎么选 | 30s | **不给"谁赢"**，给两个场景 + 记忆点句 + 下期预告 | 放慢，最后一句是记忆点 |

**要压到 2 分半**：删第 7 段（安全信息密度最低），并在第 4 段里各砍一句。
**不要靠加快语速压时长**——长视频的信任感来自从容。

## 三、四条写法规则

### 1. 去编号腔

不写"第一点、第二点"。用**主语切换**推进：

```
Codex 解决的是「一个人不够用」……
WorkBuddy 解决的是「中间步骤太碎了」……
```

段落之间靠"再说一个很多人关心的""这块反而简单"这类口语过渡，不靠序号。

### 2. 每组对比后面必须有一句金句收束

一句话把两边的关系说清，观众记住的就是这句：

| 对比维度 | 收束句范式 |
| --- | --- |
| 痛点 | 一个治的是「忙不过来」，一个治的是「懒得动手」 |
| 生态 | 一个接的是「代码世界」，一个接的是「你公司正在用的那些东西」 |
| 自动化 | 一个管「机器值守」，一个管「你随时能遥控」 |
| 安全 | 一个防「它乱动手」，一个防「谁在用它」 |
| 价格 | 一个「顺手就用了」，一个「装完就开工」 |

**句式**：`一个……，一个……`。对仗、短、可比。不要写成长句解释。

### 3. 短板要双向写

先写对方短板，紧接着写自己短板，中间用"但这两边也都有话得说回来"过渡。
只写一边＝软文，评论区第一条就会指出来。

### 4. 结尾不给赢家，给判据

```
别问哪个更强。问你自己，明天早上打开电脑，你第一件事是写代码，还是写文档。
```

给一个**用户自己能回答的问题**，比给结论更有传播力。最后接互动提问 + 下期预告。

## 四、事实纪律

| 项 | 规则 |
| --- | --- |
| 价格 | 必须写清币种、周期、档位；拿不准就写"以官网为准" |
| 功能 | 只写你亲手验证过的；听说的一律标"据说"或删掉 |
| 时间 | "现在""目前"要带月份，否则三个月后这条片子就是错的 |
| 竞品短板 | 必须能举例（哪个功能、什么表现），不能只有形容词 |

**对比测评最容易翻车的是"绝对化"**：最好、唯一、完全不行——这类词既失真又容易被投诉。

## 五、与短视频骨架的差别

| | 短视频 A–E | 长视频 F |
| --- | --- | --- |
| 开场 | 3 秒必须进主题 | 15 秒可以从一个提问慢慢进 |
| 节奏 | 每 12 字一个信息点 | 每段一个完整论点，允许停顿 |
| 情绪 | 拉满 | 克制，靠"公道"建立信任 |
| 结尾 | 强 CTA | 一个判断题 + 轻 CTA |
| 复用 | 一条一个点 | 一条可拆成 4–5 条短视频（每个维度一条） |

**拆条是 F 的附加价值**：九段骨架里第 3、4、5、6 段各自都能独立成一条 45 秒短视频。
写完 F 顺手把这几段的钩子单独写出来，等于一次采集出五条内容。
