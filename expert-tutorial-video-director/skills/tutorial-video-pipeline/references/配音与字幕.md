# 配音与字幕

配音是节奏的标尺：**每段配音多长，画面就该多长**。所以配音必须在剪画面之前完成。

## edge-tts 音色

中文教程常用（`zh-CN-` 前缀，普通话）：

| 音色 | 听感 | 适合 |
|---|---|---|
| `zh-CN-YunxiNeural` | 年轻男声，偏轻快 | 技术教程默认 |
| `zh-CN-YunjianNeural` | 沉稳男声，解说味 | 严肃科普、企业课 |
| `zh-CN-YunyangNeural` | 新闻播报腔 | 正式课程 |
| `zh-CN-XiaoxiaoNeural` | 女声，自然 | 通用 |
| `zh-CN-XiaoyiNeural` | 女声，偏活泼 | 轻量科普 |

粤语别只换音色：文案要改成粤语口语（`zh-HK-` 前缀音色），否则念出来是"普通话字用粤语音读"。

## 速率与音量

- 教程默认 **`+8%`**。`+0%` 偏慢，`+15%` 开始赶。
- 语速不是靠全局调，是靠**句子里断句**。一句话 40 字以内，中间有逗号，配音自然就顺。
- 音量交给响度归一，不要手调 `volume`。

## 响度

统一 `loudnorm=I=-16:TP=-1.5:LRA=11`，落到 48kHz 单声道 wav。

- `-16 LUFS` 是网络视频的常规目标，B 站/YouTube 都不会再压。
- `TP=-1.5 dBTP` 留峰值余量，避免 AAC 编码后削波。
- 不要只对成片做归一：逐段归一后再拼，段与段之间音量才一致，不会一段响一段轻。

## 缓存

配音按 `build/audio/<id>.mp3|wav` 缓存。

- 文本没变 → 直接复用，重跑很快。
- 文本改了 → **必须 `--force`**，否则听的还是旧音频。这是最常见的一次返工原因。

## 字幕

### 生成方式

由本段台词按字数比例摊到本段配音时长上（`build_film.py` 内做），计时**相对片段**：

```
段内 0.00–2.35  "同一句话，换 WorkBuddy。"
段内 2.35–7.10  "点发送。它没有直接写字，先去读文件。"
```

不是 ASR、不是强制对齐。**没有逐字时间戳**，所以：

- 单条字幕 ≤ 26 字，按句末标点切，过长再按逗号切。
- 台词里多写逗号，字幕断句才自然。
- 念稿和字幕必须一字不差，不然会出现"嘴在说、字在跳"。

### 烧录

`--subs` 打开：`subtitle_mode=burn`，同时导出 `subtitles.srt`。

样式参数在 `beats.json` 顶层：

```json
{"font": "Microsoft YaHei", "font_size": 48}
```

`font_size` 默认 `max(16, 宽 × 0.025)` = 1920 时 48。字号再大就会两行挤在底部。

### 什么时候不烧字幕

- 平台自带 CC（B 站/YouTube 上传 SRT）→ 用 `sidecar`，只出 SRT 不改画面。
- 画面本身就是文字（讲义卡）→ 不烧，字幕会和卡片正文打架。
- 纯实拍演示 → 烧，观众经常静音看。

## 台词写法

对着画面写，不对着概念写。

| 别这么写 | 这么写 |
|---|---|
| 它具备文档生成能力 | 它生成了一份 Word，三页，右边直接开了预览 |
| 效率提升明显 | 这几步你平时自己干，一步都省不掉 |
| 模型具有局限性 | 记录里没写的负责人，它标了"未明确"，没编名字 |

数字必须是这次真跑出来的。跑出 10.5 KB 就说 10.5 KB。

## 字幕与配音对齐检查

```bash
# 看每段配音时长（build_film.py 的表已经打了）
# 听感抽检：整片响度
ffmpeg -nostats -i out/EP01_render/final.mp4 -af ebur128=peak=true -vn -f null - 2>&1 | grep -E "^ *I:"

# 找异常静音（超过 1.2 秒的空白）
ffmpeg -i out/EP01_render/final.mp4 -af "silencedetect=noise=-32dB:d=1.2" -vn -f null - 2>&1 | grep silence_
```

有静音不一定是错：卡片尾部停顿本来就该静。但**段落中间**出现 1 秒以上静音，通常是配音缺字或片段错位。
