# 选题方法论（技术向）

> 休眠素材：SKILL.md 未引用，不会自动加载。启用时在「模块路由」登记一行再删掉本句。

> 技术赛道的选题不靠灵感，靠**公式 + 搜索词**。灵感型选题十条能中一条，公式型选题三条能中一条。
> 本文件只解决"写什么"，"怎么写"看 `copy-playbook.md`。

## 一、先认清一件事：搜索流量比推荐流量稳

技术内容的流量大头来自**搜索**，不是推荐流。推荐流看命，搜索看标题里埋的词。所以选题的第一道关不是"这个话题火不火"，是"**读者会不会去搜它**"。

搜索词怎么来，按可靠性排序：

1. 自己后台的搜索词（有数据就看，最准）
2. 评论区/私信里读者原话（他们怎么问，就怎么搜）
3. 平台搜索下拉框（打两个字看联想）
4. 自己猜（最不准，别当依据）

规则：**一篇只打一个主搜索词**。读者打"cursor怎么用"，不会打"Cursor高效使用指南"——原样记下来，别美化。

## 二、六种选题公式

每个公式给的是骨架，填进去的必须是他真做过的事。

### 公式1 工具实测
`我用<工具>做了<一件具体事>，<周期>之后，这几个功能值钱，那几个是噱头`

- 读者层：不动手的人 / 半路的人
- 收藏钩子：功能取舍表
- 关键：必须有**做不到的**那一段。只夸不贬的测评没人信
- 前提：真用过一段时间，写不出细节就别写

### 公式2 工作流拆解
`把<某件重复劳动>从<X>压到<Y>，完整流程+提示词`

- 读者层：不动手的人
- 收藏钩子：可抄的提示词 + 步骤
- 关键：这条赛道收藏率最高的类型，直接对应"提效"需求
- 前提：耗时数字必须真实，写不出真实数字就只写"从很久压到几分钟"，别编

### 公式3 踩坑清单
`<某件事>踩过的<N>个坑，每个都花了时间`

- 读者层：半路的人 / 同行
- 收藏钩子：坑位清单 + 规避方法
- 关键：坑要具体到"报什么错、为什么、怎么改"。写"注意配置"等于没写
- 优势：门槛低、可信度高、天然带情绪

### 公式4 选型对比
`<A>和<B>我都用了，最后选<X>，理由是<一句话>`

- 读者层：半路的人 / 同行
- 收藏钩子：对比表（价格、速度、限制、适用场景）
- 关键：两个都得真用过；先给结论再给表
- 优势：长尾强，一年后还有人搜

### 公式5 复刻教程
`教你搭一个<具体东西>，从零到能用`

- 读者层：半路的人
- 收藏钩子：完整步骤 + 可跑代码
- 关键：得能跑通。跑不通的教程会招骂，技术号最忌这个
- 优势：收藏+关注双高，适合做系列

### 公式6 反常识判断
`别再<大众做法>了，<我的做法>才对，因为<理由>`

- 读者层：同行
- 收藏钩子：判断标准 / 边界条件
- 关键：必须说得出"什么情况下我这话是错的"，否则就是抬杠
- 优势：评论区最活跃，涨粉最快
- 风险：立场错了会被挂，只写自己真有把握的

## 三、三道过滤（任一不过就淘汰）

1. **他真做过吗？** 没做过 → 淘汰。装懂会被评论区拆穿。
2. **有收藏钩子吗？** 给不出能抄走的东西 → 淘汰或换角度。
3. **读者会搜这个吗？** 搜不到 → 换标题，或换选题。

## 四、交付格式

选题不许只给一串题目，必须给表：

| 选题 | 公式 | 读者层 | 收藏钩子 | 主搜索词 | 竞争度 | 本周能否出 |
|---|---|---|---|---|---|---|

**竞争度判断**：去平台搜这个主搜索词，前几条都是大号、数据很高 → 高；都是零散小号、数据平平 → 低。低竞争 + 有搜索量 = 优先做。判断不出就写"待你搜一下"，不要瞎填。

一次给3~5个，按"本周能否出"排序，最后补一句"先做哪个，为什么"。

## 五、系列化（涨粉的唯一系统手段）

单篇涨收藏，系列涨粉。可做的结构：

- **从零搭一个东西**：搭环境 → 核心功能 → 部署 → 踩坑复盘，4~8篇
- **工具轮测**：每周测一个同类工具，固定格式、固定时间
- **同一需求的不同解法**：一件事给三种做法，各一篇

第一篇就写明"这是第几篇、一共几篇"，读者才有理由关注。没有系列规划就别说"会持续更新"。

## 六、选题池怎么囤

- 一次囤10个，按周排，别每天现想。
- 分两类：常青（工具用法、环境配置、性能优化）+ 时效（新模型、版本更新、行业事件）。
- 常青占七成。技术热点半衰期只有3~5天，靠热点撑不起账号。
