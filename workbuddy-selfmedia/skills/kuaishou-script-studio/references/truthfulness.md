# 真实性规则：占位符与反编造

> AI 不掌握用户的真实经历。编出来的细节是内容事故，不是效率。
> 快手额外一条：**信任经济下，编造一次，人设就毁了**。这里的观众是长期关注的熟客，不是一次性流量。

## 必须留【】占位的 8 类

| 类别 | 例 |
|---|---|
| 工具名 / 产品名 | 【你实际用的工具】【品牌】【型号】 |
| 版本号 / 型号 | 【版本】【批次】 |
| 具体数据 | 【X】元、【X】斤、【X】次、【X】天 |
| 时间与时长 | 【X】月、【X】年、用了【X】小时 |
| 地点 | 【某村】【某市场】【某城市】 |
| 个人经历细节 | 【你的真实细节：当时…】 |
| 解法 / 做法 | 【你的真实解法：A / B / C】 |
| 他人原话 | 【当事人原话】【某条评论】 |

**判断标准**：这条错了，老铁会不会在评论区拆穿你？会 → 留占位。

## 写法规范

1. 用【】包裹，不用 XX / xxx / 下划线。
2. **给选项提示**，降低填写成本：`【你的真实解法：A / B / C】`
3. 口播稿上方必须声明：`⚠️ 带【】的是需要你填真实细节的占位，共 N 处，别直接念。`
4. 脚本骨架必须完整可用，不要整段占位。
5. **口播稿里不要出现读不出来的占位**——写 `【X】块` 不写 `【填写价格】`。

## 禁止

- ❌ 替用户填具体工具名（哪怕是"行业常用"的那个）
- ❌ 编造具体数字（哪怕是"典型值"）
- ❌ 编造案例、对话、他人原话
- ❌ 把别人的经历写成用户自己的
- ❌ 凭记忆写热点，必须联网核实
- ❌ 悄悄删掉占位符，输出一篇"读起来很完整"但细节全是编的稿子

## 交付义务

口播稿上方写明占位处数；自检清单必有一行：
- [ ] 所有【】占位都列给用户了？有没有任何一处是我替他填的？

## 用户填完后的下一步

说「去占位」/「按我填的重写」时做三件事：

1. 替换成真实值。
2. **顺一遍逻辑**：真实数字可能和原文冲突（原文写"很便宜"，用户填的价格不低 → 必须改结论）。
3. **重查标题和钩子**：真实值可能推翻原标题。

## 一条特别提醒

快手的分发是**关注页 + 发现页**，观众里有大量长期关注你的老粉。

这些人是真的记得你上次说了什么。价格对不上、工具换了一个、说法前后矛盾——**他们会直接指出来**。

在公域平台，编造的代价是一条视频；在快手，代价是整个人设。
