# 真实性规则：占位符与反编造

> AI 不掌握用户的真实经历。编出来的细节是内容事故，不是效率。
> 头条额外一条：**原创度 ≥ 90%、AI 痕迹 < 5%** 是硬指标，占位符填进真实经验是压住 AI 痕迹的主要手段。

## 必须留【】占位的 8 类

| 类别 | 例 |
|---|---|
| 工具名 / 产品名 | 【你实际用的工具】【车型】【型号】 |
| 版本号 / 型号 | 【版本】【批次】 |
| 具体数据 | 【X】元、【X】%、【X】次、【X】天 |
| 时间与时长 | 【X】点、【X】年【X】月、用了【X】小时 |
| 地点 | 【某服务区】【某平台】【某店】【某市】 |
| 个人经历细节 | 【你的真实细节：当时…】 |
| 解法 / 做法 | 【你的真实解法：A / B / C】 |
| 他人原话 | 【当事人原话】【某条评论】 |

**判断标准**：这条错了，用户会不会在评论区被拆穿？会 → 留占位。

## 写法规范

1. 用【】包裹，不用 XX / xxx / 下划线。
2. **给选项提示**，降低填写成本：`【你的真实解法：就近下高速 / 熬到凌晨错峰 / 充到80%走人】`
3. 正文上方必须声明：`⚠️ 带【】的是需要你填真实细节的占位，共 N 处，别直接发。`
4. 骨架和逻辑必须完整可用，不要整段占位。
5. **案例要标注来源**：`【你的真实案例】` 与 `（据【X】报道）` 不能混写——后者若无出处会被判不实信息。

## 禁止

- ❌ 替用户填具体工具名（哪怕是"行业常用"的那个）
- ❌ 编造具体数字（哪怕是"典型值"）
- ❌ 编造案例、对话、他人原话
- ❌ 把热榜上别人的经历写成用户自己的（要写就写"热榜上有人…我的是【X】"）
- ❌ 凭记忆写热榜词，必须联网核实
- ❌ 悄悄删掉占位符，输出一篇"读起来很完整"但细节全是编的稿子

## 交付义务

正文上方写明占位处数；自检清单必有一行：
- [ ] 所有【】占位都列给用户了？有没有任何一处是我替他填的？

## 用户填完后的下一步

说「去占位」/「按我填的重写」时做三件事：

1. 替换成真实值。
2. **顺一遍逻辑**：真实数字可能和原文冲突（原文写"等了很久"，用户填 40 分钟 → 必须改文案，不能生搬硬套）。
3. **重查标题**：真实值可能推翻原标题。数字小了，"等了 5 小时"就不能用，要换机制重写。

## 降 AI 痕迹的三条写法

平台按段落判定 AI 痕迹，以下三条能显著降低风险：

1. **加具体时间与地点**：`【X】月【X】号下午，在【某地】` —— AI 稿最缺的就是这种颗粒度。
2. **加个人化口吻**："我当时以为…""后来才发现…" —— 第一人称的过程叙述。
3. **加不完美的细节**：失败一次、走了弯路、价格记错了 —— 过于规整是 AI 稿的典型特征。

这三条都依赖用户填真实值，**不要替他编**。
