# 真实性规则：占位符与反编造

> AI 不掌握用户的真实经历。编出来的细节是内容事故，不是效率。
> 视频号额外一条：熟人社交场里，观众可能真的认识你——编造的细节代价更高。

## 必须留【】占位的 8 类

| 类别 | 例 |
|---|---|
| 工具名 / 产品名 | 【你实际用的工具】【品牌】【型号】 |
| 版本号 / 型号 | 【版本】【批次】 |
| 具体数据 | 【X】元、【X】%、【X】次、【X】天 |
| 时间与时长 | 【X】月、【X】年、用了【X】小时 |
| 地点 | 【某城市】【某公司】【某平台】 |
| 个人经历细节 | 【你的真实细节：当时…】 |
| 解法 / 做法 | 【你的真实解法：A / B / C】 |
| 他人原话 | 【当事人原话】【某条评论】 |

**判断标准**：这条错了，观众会不会在评论区拆穿你？会 → 留占位。

## 写法规范

1. 用【】包裹，不用 XX / xxx / 下划线。
2. **给选项提示**，降低填写成本：`【你的真实解法：A / B / C】`
3. 口播稿上方必须声明：`⚠️ 带【】的是需要你填真实细节的占位，共 N 处，别直接念。`
4. 脚本骨架必须完整可用，不要整段占位。
5. **口播稿里不要出现读不出来的占位**——写 `【X】元` 不写 `【填写金额】`。

## 禁止

- ❌ 替用户填具体工具名（哪怕是"行业常用"的那个）
- ❌ 编造具体数字（哪怕是"典型值"）
- ❌ 编造案例、对话、他人原话
- ❌ 把别人的经历写成用户自己的
- ❌ 凭记忆写热点与趋势，必须联网核实
- ❌ 悄悄删掉占位符，输出一篇"读起来很完整"但细节全是编的稿子

## 交付义务

口播稿上方写明占位处数；自检清单必有一行：
- [ ] 所有【】占位都列给用户了？有没有任何一处是我替他填的？

## 用户填完后的下一步

说「去占位」/「按我填的重写」时做三件事：

1. 替换成真实值。
2. **顺一遍逻辑**：真实数字可能和原文冲突（原文写"效果很好"，用户填的数据一般 → 必须改结论）。
3. **重查标题**：真实值可能推翻原标题。数字小了，"省了 5 万"就不能用。

## 一条特别提醒

视频号的传播路径是**朋友点赞 → 曝光给约 20% 的微信好友**。
这意味着观众里有相当比例是认识你的人——编造的经历、夸大的数据、虚构的场景，被熟人拆穿的概率远高于公域平台。

占位符不是流程负担，是保护。
