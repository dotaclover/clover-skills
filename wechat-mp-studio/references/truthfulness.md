# 真实性规则：占位符与反编造

> AI 不掌握用户的真实经历。编出来的细节是内容事故，不是效率。
> 真实案例与数据须有来源，原创判断还涉及作品权利及当前规则，不能以加入经历保证原创判定。

## 必须留【】占位的 8 类

| 类别 | 例 |
|---|---|
| 工具名 / 产品名 | 【你实际用的工具】【品牌】【型号】 |
| 版本号 / 型号 | 【版本】【批次】 |
| 具体数据 | 【X】元、【X】%、【X】次、【X】天 |
| 时间与时长 | 【X】月、【X】年、用了【X】小时 |
| 地点 | 【某公司】【某城市】【某平台】 |
| 个人经历细节 | 【你的真实细节：当时…】 |
| 解法 / 做法 | 【你的真实解法：A / B / C】 |
| 他人原话 | 【当事人原话】【某条留言】 |

**判断标准**：所有未确认事实均标待核或留占位，不以是否可能被发现判断真实性。

## 写法规范

1. 用【】包裹，不用 XX / xxx / 下划线。
2. **给选项提示**，降低填写成本：`【你的真实解法：A / B / C】`
3. 正文上方必须声明：`⚠️ 带【】的是需要你填真实细节的占位，共 N 处，别直接发。`
4. 骨架和逻辑必须完整可用，不要整段占位。
5. **案例要标注来源**：`【你的真实案例】` 与 `（据【X】报道）` 不能混写——后者若无出处会被判不实信息。

## 禁止

- 不得无来源替用户填写工具名；用户已提供并授权的真实名称可直接使用。
- ❌ 编造具体数字（哪怕是"典型值"）
- ❌ 编造案例、对话、他人原话
- ❌ 把别人公开分享的经历写成用户自己的
- ❌ 凭记忆写热点与趋势，必须联网核实
- ❌ 悄悄删掉占位符，输出一篇"读起来很完整"但细节全是编的稿子

## 交付义务

正文上方写明占位处数；自检清单必有一行：
- [ ] 所有【】占位都列给用户了？有没有任何一处是我替他填的？

## 用户填完后的下一步

说「去占位」/「按我填的重写」时做三件事：

1. 替换成真实值。
2. **顺一遍逻辑**：真实数字可能和原文冲突（原文写"效果很好"，用户填的数据一般 → 必须改结论，不能生搬硬套）。
3. **重查标题**：真实值可能推翻原标题。

## 真实经验的三条写法

1. 有依据才交代具体时间地点，未知就留占位。
2. 亲历才使用第一人称，引用内容注明实际来源。
3. 保留真实过程的限制与不确定性，不为制造真实感编造失败。

这些方法用于准确表达，不用于隐藏AI辅助或规避检测；按适用要求披露AI使用。
