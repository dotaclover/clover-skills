# 已知坑位

真实踩过的坑，按踩到的概率排序。

## 1. 删除垫片：删了但空间没少

**现象**：`shutil.rmtree` 返回成功，目录从视野消失，`disk_usage` 一点没变。回收站容量倒涨了同样的数。

**原因**：部分环境的 Python 删除被 safe-delete 垫片接管，实际走的是 Windows 回收站。

**解法**：用 `purge.py`（`SHFileOperationW`，`fFlags` 不含 `FOF_ALLOWUNDO`）。
**自查**：删完立刻比对 `disk_usage`，没变化就去看回收站。

## 2. 把"移动"当成"释放"

同盘 `os.rename` 只是改目录项，不占也不放空间。报告里写"已回收2.6GB"而实际可用空间没动，是最容易翻车的表述。

**规矩**：移动量、进回收站量、真正释放量，三个数字分开报。

## 3. `%USERPROFILE%\WorkBuddy` 不是纯临时目录

看起来像一堆 `2026-09-14-19-47-27` 的临时空间，实际可能同时含：

- 旧版本安装（`WorkBuddy.exe` + `resources/app.asar` + 一堆 DLL，约 700MB）
- 用户的真实产出（简历 PDF、项目方案 docx、`outputs/` 里几十上百 MB 的成品）
- 空壳目录（只有 `.workbuddy` 标记，0 字节）

**判据**：
- 当前进程路径用 `Get-Process WorkBuddy | Select Path` 确认，再比对快捷方式指向
- 目录里有没有非 `.workbuddy` 的文件，有就先列文件名再问
- 空壳（总字节 0 且只有 `.workbuddy`）才能直接删

## 4. `projects` 目录名转义

工作空间路径转成目录名时，`C:/code/x` 要把 `:/` 整体换成一个 `-`，不是分两步各换一次，否则得到 `c--code-x` 这种双横线，匹配不到任何目录（真实案例：漏清 99MB）。

```python
esc = cwd.replace("\\", "/").lower().replace(":/", "-").replace("/", "-")
```

## 5. `modify_backup` 不是聊天记录

`workspace/sessions/<uuid>/` 里九成是 `modify_backup/`，是"撤销修改"用的文件快照；聊天正文在 `projects/<escaped>/<uuid>.jsonl`。

删 `modify_backup` = 旧会话点撤销恢复不了文件内容，但"改了什么"（diff）还在。必须把这句话说清楚，否则用户以为聊天没了。

## 6. 软删除不会释放空间

界面删会话 = `sessions` 表打 `deleted_at`，四类文件全留。必须显式调用 `session_clean.py --clean-deleted`。

## 7. 运行中清理的边界

这些被进程占用，运行中清不干净，只能跳过或请用户退出 WorkBuddy：

- `plugins/cache/**`（插件按需从磁盘加载，运行中删会让工具报错）
- `logs/sandbox/<今天>/*.log`
- `app/session/Partitions/*/Cache`、`GPUCache`、`DawnWebGPUCache`

## 8. 数据库写入要与进程共存

应用在跑时会持有 `workbuddy.db` 的 WAL。改库前：

1. `sqlite3.Connection.backup()` 先备份
2. 连接时 `timeout=30` + `PRAGMA busy_timeout=30000`
3. 用单一事务批量提交，别开长事务

另外应用可能把内存里的会话状态重新落库，所以清完行数可能回涨——以磁盘占用和 `deleted_at` 是否为空为准。

## 9. 别删空文件夹本身

`%USERPROFILE%\WorkBuddy` 可能是旧版的默认工作空间根目录，删掉空文件夹会让新版创建空间时找不到父目录。清空内容即可，保留目录。

## 10. GitBash 会吃掉 `$`

`C:\$Recycle.Bin` 在 GitBash 里被 `$Recycle` 展开成空。涉及 `$` 或 Windows 路径的脚本一律写成 `.py` 文件执行，不要用 `python -c "..."` 内联。
