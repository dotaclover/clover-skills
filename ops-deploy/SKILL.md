# 站点更新部署

先读 [目标配置与探测指南](references/hosts.md)。本技能只更新已有站点；新建站点、面板登记、Nginx配置和证书申请交 `ops-btpanel`。范围、费用、服务窗口从当前 project brief、合同政策及验收清单取得，缺项询问，不内置商业套餐。

## 开工门槛

1. 确认目标域名、实例标识、环境（测试/生产）、SSH连接配置、远程站点目录、本地产物目录及授权范围，不复用历史主机库存。
2. 只读核实系统、Web/FPM运行用户、目录属主、服务版本、磁盘空间与inode、应用类型、当前发布版本。存在`wp-config.php`只是WordPress线索，混合应用仍需核实。
3. 明确备份目录（站点目录之外、访问受限）、保留政策、恢复方法和变更窗口。验证归档可读，数据库在隔离副本试恢复；未验证须如实标记。
4. 将实际目标、拟执行命令、覆盖文件清单、影响、回滚条件给用户确认。授权只覆盖本次范围，不自动授权清理、改权限、重启或数据库迁移。

## 目标变量

从任务配置填写 `SSH_TARGET`、`SITE_DIR`、`ARTIFACT_DIR`、`BACKUP_DIR`、`BASE_URL`、`WEB_USER`、`WEB_GROUP`。变量未解析或含占位时停止。连接优先使用已核实SSH配置与最小权限账号；密钥只引用安全配置，不读取或展示内容。远程参数须按实际shell安全转义，禁止直接拼接未经验证的用户输入。

## 流程 A：静态站更新

1. 在本地产物目录打包，排除`.git`、依赖、缓存、密钥和旧压缩包；检查归档无绝对路径或`..`穿越项，保存文件清单与校验值。
2. 备份目标文件及必要配置，记录部署前的页面、资源和响应头基线。
3. 上传到本任务独占的暂存目录，核对校验值；只覆盖已批准文件，优先版本目录与可回滚切换。
4. 保留`.user.ini`、`.well-known`、`.htaccess`、验证文件和非本任务资产。不默认使用`rsync --delete`；旧文件删除须另列精确清单并确认。
5. 按现场权限模型仅调整本次新增/更新且确需调整的文件，不递归重设整站属主。
6. 请求正式首页、关键内页及真实静态资源，核对状态码、内容版本、导航、控制台、缓存与安全响应头；本地预览不能代替正式网址验收。

## 流程 B：PHP / WordPress 更新

1. 备份文件、数据库及配置；一致性策略根据存储引擎和写入流量确定。凭据通过受限配置/凭据管理传入，不写入命令行或报告。
2. 只更新本次主题、插件或程序目录，不覆盖`wp-config.php`、`.env`、上传文件、用户数据和运行期配置。
3. 在隔离副本验证版本兼容与数据库迁移；迁移、核心升级、缓存清理和服务重启须各自纳入获批计划，不自动执行。
4. 检查首页、内页、登录页、授权测试表单、上传及错误日志；测试写入必须单独获授权并记录本任务对象ID，清理只针对这些对象。

## 证书与面板衔接

通过面板支持的界面或当前版本公开API建站、登记、绑定域名及申请部署证书；不要复制其他生产站配置或直接写`site.db`。内部数据库路径、字段与私有Python接口随版本变化，不作为通用操作入口。

先只读核实证书域名、到期日、挑战目录、续期计划、最近结果与部署路径。优先staging/dry-run验证；真实重签会消耗额度，须确认。`pending`只表示待处理，不等于废弃；不得批删订单。确需清理时仅处理本任务创建、确认不再使用且用户批准的精确对象，并先备份、记录回滚。

## 回滚与收尾

- 变更失败先暂停，保存当前状态和日志，按预先批准的回滚方案恢复；涉及新增生产数据时不得直接覆盖数据库，应再次确认数据取舍。
- 解回归档不会自动删除新部署文件；依据部署清单恢复，避免残留混合版本。恢复后重新验收。
- 只清理本任务临时包；历史备份按用户确认的保留政策处理，不因旧磁盘状态自动删除。
- 回传目标、时间、变更清单、备份与恢复验证、正式URL证据、未完成项、残留风险和临时权限撤销情况。
