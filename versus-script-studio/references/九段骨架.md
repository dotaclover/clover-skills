# 九段骨架（3 分钟版）

> 状态：v0.1，仅由 1 条成稿（历史工具对比稿，3 分钟纯口播；不作当前产品依据）反推。
> 段长与段数在更多题材上是否成立，尚未验证——用之前先看 `SKILL.md` 的待完善清单。

## 一、九段逐段写法

| # | 段 | 时长 | 干什么 | 语气 | 禁忌 |
|---|---|---|---|---|---|
| 1 | 开场 | 12s | 从具体问题切入（“面对这两种方案，先看使用场景”）；只有确有来源才写“有人问我” | 聊天式 | 编造提问者或亲历 |
| 2 | 来路 / 定位 | 15s | 说明两边服务对象与定位 | 平铺 | 念官网简介；强行同类化 |
| 3 | 干活方式（痛点） | 25s | 结合真实材料说明各自解决的问题 | 说透 | 无依据罗列功能 |
| 4 | 各自的短板 | 28s | 双向说明限制与适用条件 | 转折停顿 | 只写一边短板 |
| 5 | 生态 / 配套 | 18s | 按题材比较兼容、配套或协作 | 稍快 | 仅以数量判胜负 |
| 6 | 流程 / 自动化 | 18s | 按题材比较操作、值守或维护 | 平 | 混淆实际能力与计划能力 |
| 7 | 安全 / 风险 | 20s | 按题材说明权限、数据、使用或维护风险 | 平 | 必要安全限制不得为压时长删除 |
| 8 | 上手与花费 | 16s | 核对实际投入、计价和使用条件 | 轻松 | 价格缺币种、周期、档位 |
| 9 | 总结 / 怎么选 | 28s | 给场景与判据；有已确认计划才预告 | 放慢 | 绝对结论或编造下期计划 |

示例合计：12+15+25+28+18+18+20+16+28=180秒。维度按题材与风险替换，试读后重分配并核算总和。

### 段长怎么调

九段是**默认分配**，不是模板填空题：

1. 按本次用户最在意的维度调整时长，以下秒数只是试读起点。
2. 先压缩重复信息，不预设安全段的信息密度最低。
3. 涉及权限、数据或操作风险时保留关键安全限制；缩短时长不能删掉必要风险说明。
4. 用自然试读校验总时长，不单靠加速压缩。

## 二、四条写法规则

### 1. 去编号腔

不写"第一点、第二点"。用**主语切换**推进：

```
方案A解决的是「重复录入太多」……
方案B解决的是「信息分散难查找」……
（虚构中性句式示例，不代表具体产品能力或用户实测）
```

段与段之间靠口语过渡（"再说一个很多人关心的""这块反而简单"），不靠序号。

### 2. 每组对比后必须有一句金句收束

一句话把两边关系说清，观众记住的就是这句。句式固定为 `一个……，一个……`：

| 维度 | 收束句范式 |
| --- | --- |
| 痛点 | 一个治的是「忙不过来」，一个治的是「懒得动手」 |
| 生态 | 一个接的是「代码世界」，一个接的是「你公司正在用的那些东西」 |
| 自动化 | 一个管「机器值守」，一个管「你随时能遥控」 |
| 安全 | 一个防「它乱动手」，一个防「谁在用它」 |
| 价格 | 一个「顺手就用了」，一个「装完就开工」 |

要求：短、对仗、可比。写成长句解释就失效了。

### 3. 短板双向写

写完对方短板，紧接着写自己短板，中间用"但这两边也都有话得说回来"过渡。
只写一边＝软文，评论区第一条就会指出来。

### 4. 结尾不给赢家，给判据

```
别问哪个更强。问你自己，明天早上打开电脑，你第一件事是写代码，还是写文档。
```

给一个**用户自己能回答的问题**，比给结论更有传播力。最后接互动提问 + 下期预告。

## 三、事实纪律

| 项 | 规则 |
| --- | --- |
| 价格 | 必须写清币种、周期、档位；拿不准写"以官网为准" |
| 功能 | 只写亲手验证过的；听说的一律标"据说"或删掉 |
| 时间 | 说"目前""现在"要带月份，否则三个月后这条片子就是错的 |
| 对方短板 | 必须能举例（哪个功能、什么表现），不能只有形容词 |

**最容易翻车的是绝对化**：最好、唯一、完全不行——既失真又容易被投诉。

## 四、与短视频骨架的差别

| | 平台工坊的短视频（A–E） | 对决稿（F） |
| --- | --- | --- |
| 开场 | 3 秒必须进主题 | 15 秒可以从一个提问慢慢进 |
| 节奏 | 每 12 字一个信息点 | 每段一个完整论点，允许停顿 |
| 情绪 | 拉满 | 克制，靠"公道"建立信任 |
| 结尾 | 强 CTA | 一个判断题 + 轻 CTA |
| 复用 | 一条一个点 | 一条可拆成 4–5 条短视频 |

## 五、拆条（未验证，P1）

九段里第 3、4、5、6 段各自能独立成一条 45 秒短视频：

| 原段 | 拆出来的钩子 |
| --- | --- |
| 3 痛点 | "这两个工具治的根本不是同一种病" |
| 4 短板 | "它最强的地方，也正好是它最弱的地方" |
| 5 生态 | "一个接代码世界，一个接你公司" |
| 6 自动化 | "人不在的时候，谁在替你干活" |

**待验证**：拆条后原稿的记忆点会不会被稀释——只有 1 条案例，样本不足。
