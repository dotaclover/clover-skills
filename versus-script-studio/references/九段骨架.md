## 一、九段逐段写法

| # | 段 | 时长 | 干什么 | 语气 | 禁忌 |
|---|---|---|---|---|---|
| 1 | 开场 | 15s | 从一个**具体提问**切入（"前两天有人问我…"），声明不吹不黑、短板也讲 | 聊天式，放慢 | 自我介绍、行业背景铺垫、"今天我们来聊聊" |
| 2 | 来路 / 定位 | 18s | 各自从哪长出来的，服务的是不是同一拨人 | 平铺 | 念官网简介；把两个不同物种说成同类 |
| 3 | 干活方式（痛点） | 30s | **全片重点**：各自治的是什么痛点 | 说透，语速稍慢 | 罗列功能清单；不落到"用户原来怎么做" |
| 4 | 各自的短板 | 32s | 先对方短板，再自己的 | 转折处停顿，短板处加重 | 只写对方短板（＝软文） |
| 5 | 生态 / 能接什么 | 22s | 接的是"代码世界"还是"公司正在用的东西" | 稍快 | 把连接器数量当胜负 |
| 6 | 自动化 / 人不在时 | 22s | 定时、远程遥控、谁值守 | 平 | 混淆"本地定时"和"云端触发" |
| 7 | 安全 | 20s | 两边管法不同：一个防"它乱动手"，一个防"谁在用它" | 平 | 信息密度最低，压时长时第一个删 |
| 8 | 上手与花费 | 18s | 订阅制还是积分制，谁更零成本 | 轻松 | 报价格不写币种/周期/档位 |
| 9 | 总结 / 怎么选 | 30s | **不给"谁赢"**，给两个场景 + 记忆点 + 下期预告 | 放慢，最后一句是记忆点 | 给绝对结论；带货式收尾 |

### 段长怎么调

九段是**默认分配**，不是模板填空题：

1. 先问"提问者最在意哪个维度"，把那一段加 10 秒
2. 从信息密度最低的段扣（通常是第 7 段安全）
3. 压到 2 分半：删第 7 段，并在第 4 段里各砍一句
4. **不要靠加快语速压时长**——长视频的信任感来自从容

## 二、四条写法规则

### 1. 去编号腔

不写"第一点、第二点"。用**主语切换**推进：

```
Codex 解决的是「一个人不够用」……
WorkBuddy 解决的是「中间步骤太碎了」……
```

段与段之间靠口语过渡（"再说一个很多人关心的""这块反而简单"），不靠序号。

### 2. 每组对比后必须有一句金句收束

一句话把两边关系说清，观众记住的就是这句。句式固定为 `一个……，一个……`：

| 维度 | 收束句范式 |
| --- | --- |
| 痛点 | 一个治的是「忙不过来」，一个治的是「懒得动手」 |
| 生态 | 一个接的是「代码世界」，一个接的是「你公司正在用的那些东西」 |
| 自动化 | 一个管「机器值守」，一个管「你随时能遥控」 |
| 安全 | 一个防「它乱动手」，一个防「谁在用它」 |
| 价格 | 一个「顺手就用了」，一个「装完就开工」 |

要求：短、对仗、可比。写成长句解释就失效了。

### 3. 短板双向写

写完对方短板，紧接着写自己短板，中间用"但这两边也都有话得说回来"过渡。
只写一边＝软文，评论区第一条就会指出来。

### 4. 结尾不给赢家，给判据

```
别问哪个更强。问你自己，明天早上打开电脑，你第一件事是写代码，还是写文档。
```

给一个**用户自己能回答的问题**，比给结论更有传播力。最后接互动提问 + 下期预告。

## 三、事实纪律

| 项 | 规则 |
| --- | --- |
| 价格 | 必须写清币种、周期、档位；拿不准写"以官网为准" |
| 功能 | 只写亲手验证过的；听说的一律标"据说"或删掉 |
| 时间 | 说"目前""现在"要带月份，否则三个月后这条片子就是错的 |
| 对方短板 | 必须能举例（哪个功能、什么表现），不能只有形容词 |

**最容易翻车的是绝对化**：最好、唯一、完全不行——既失真又容易被投诉。

## 四、与短视频骨架的差别

| | 平台工坊的短视频（A–E） | 对决稿（F） |
| --- | --- | --- |
| 开场 | 3 秒必须进主题 | 15 秒可以从一个提问慢慢进 |
| 节奏 | 每 12 字一个信息点 | 每段一个完整论点，允许停顿 |
| 情绪 | 拉满 | 克制，靠"公道"建立信任 |
| 结尾 | 强 CTA | 一个判断题 + 轻 CTA |
| 复用 | 一条一个点 | 一条可拆成 4–5 条短视频 |

## 五、拆条（未验证，P1）

九段里第 3、4、5、6 段各自能独立成一条 45 秒短视频：

| 原段 | 拆出来的钩子 |
| --- | --- |
| 3 痛点 | "这两个工具治的根本不是同一种病" |
| 4 短板 | "它最强的地方，也正好是它最弱的地方" |
| 5 生态 | "一个接代码世界，一个接你公司" |
| 6 自动化 | "人不在的时候，谁在替你干活" |

**待验证**：拆条后原稿的记忆点会不会被稀释——只有 1 条案例，样本不足。
