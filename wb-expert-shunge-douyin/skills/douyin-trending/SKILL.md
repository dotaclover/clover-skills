# 抖音热榜取数

只做一件事：**把热榜读出来，整理成能用的选题参考**。全部写操作（点赞、评论、关注、发布、私信）一律不做。

## 取数接口

```
GET https://www.iesdouyin.com/web/api/v2/hotsearch/billboard/word/
Header: User-Agent: 浏览器 UA（不可省略）
```

返回 JSON 主要字段：

| 字段 | 含义 |
|---|---|
| `status_code` | 0 为成功；非 0 直接报错，不解析榜单 |
| `active_time` | 榜单更新时间，落盘时必须带上 |
| `word_list[]` | 榜单条目，一次通常 50 条 |
| `word_list[].word` | 词条原文 |
| `word_list[].hot_value` | 热度值，整数 |
| `word_list[].label` | 数值标记位；**具体取值对应什么标签未核实，保留原值，不自行翻译成"新/热/沸"** |

已实测：带浏览器 UA 时 200 正常返回 50 条；本机存在 `http_proxy`，代理异常时加 `--direct` 绕过系统代理再跑。接口不是公开文档化的开放平台接口，字段与可用性会变，**任何一次取数失败都如实报，不拿旧数据冒充当天榜单**。

## 执行方式

优先跑脚本，不自写临时命令：

```
python scripts/fetch_hot.py --top 20                 # 打印前 20 条
python scripts/fetch_hot.py --out 热榜.md --json raw.json
python scripts/fetch_hot.py --direct                 # 代理异常时
```

脚本零依赖、只发读请求。脚本报错时按提示换 `--direct`；仍失败就转浏览器打开热榜页人工读，不在代码里硬编备用地址反复试。

## 输出格式

```
【快照】取数时间、榜单更新时间、条目总数
【榜单】排名 | 词条原文 | 热度 | 标记
【候选】与本账号相关的 3–8 条，每条给：
        为什么相关（人群／品类／情绪）
        切入角度（一句话，落到能拍的东西）
        风险（是否敏感、是否需要核实来源、是否与账号定位冲突）
【不选】明确排除哪些，各一句理由
```

词条**照抄原文**，不改写、不概括。改写会让后面卡词跑偏，也会误判热度来源。

## 与账号的三类内容对齐

候选必须能落进下面三类之一，否则直接排除：

| 内容线 | 能吃什么样的热点 |
|---|---|
| 免费AI视频／图片工具（帮选、教你做） | 新模型发布、免费额度变化、工具改版、AI生成争议 |
| AI动物／搞笑轻量内容 | 萌宠、反差、拟人化的生活向热点 |
| 短剧（独立号，不在工具号发） | 剧集话题、职场情绪向，但**不进工具号** |

判据只有一条：**能不能用现有生产能力在24小时内做出来**。做不出来的热点不写进候选，再热也不要。

## 一律不选的内容

榜单常被时政、外交、军事、灾害、事故、司法案件、个人隐私类词条占据，这类**不选、不解读、不改写、不做任何延伸**，在"不选"里只写一句"与时政/公共事件相关，按规矩不涉及"即可，不复述内容。

其他不选：需要医疗／金融／法律专业判断的；带明确商业推广属性的；涉及具体个人且未经核实的。

## 判定与后续

- 热度高但与我们无关的，写进"不选"并给理由，避免下次重复讨论。
- 同一词条连续两天在榜，说明有长尾，可做成"教你用"型内容，但必须核实事实与时间。
- 热榜只作选题参考，**不作流量或过审保证**。

## 边界

- 不保证热点能带来播放。
- 不抓取创作者后台数据、不读他人账号的私域数据。
- 不做发布、不做互动、不做批量操作、不做定时轮询刷取。
- 接口变更或返回异常时停下报告，不用历史数据拼一份"看起来正常"的榜单。
