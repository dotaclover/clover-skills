# 脚本契约

> ⚠️ **这 5 个脚本的实现没有随文档提供。** 以下是从源文档反推出的调用契约。
> 补脚本时按这个契约实现，调用方式就能和文档里的命令对上。
> 在脚本补齐并通过一次 15 秒样片之前，不要对外声称这个技能可用。

## 零、源项目用的是另一套文件名（先看这段）

源文档有两个版本，脚本命名不一致。契约按**通用版**写，但看到下面这些名字时别以为文档错了——
那是源项目里实际跑通的文件：

| 本项目契约名 | 源项目里的实际文件 | 差异 |
| --- | --- | --- |
| `plan_timeline.py` | `plan_15.py` / `plan_v7.py` | 源项目**每个时长一个脚本**，密度参数硬写在脚本顶部 |
| `build.py` | `build_sq.py` | 源项目用**位置参数**：`build_sq.py timeline_15.json 15.0 "输出名.mp4"` |
| `gen_bg.py` | `gen_bg2.py` | 第二版底图脚本 |
| `timeline.json` | `timeline_15.json` | 源项目按版本分文件，避免互相覆盖 |

改造建议：保持一版 `plan_timeline.py` 带 `--dur`，**不要**退化成每版一个脚本；
但 `build.py` 要同时接受位置参数和 `--timeline/--dur/--out`，这样源文档里的旧命令直接能跑。

### 编码参数有一处冲突，按机器实测定

| 来源 | libopenh264 码率 |
| --- | --- |
| 源文档「环境踩坑」表 | `-b:v 4M` |
| 本技能其余文档 | `-b:v 6M` |

两个都能出片，4M 体积小、弹幕密集时字会糊，6M 更稳。**以 15 秒样片实测为准**：
抽帧看弹幕描边是否发虚，发虚就抬到 6M。不要把这条写死成"必须 4M"或"必须 6M"。

## 目录约定

```
项目根/
├── scripts/
│   ├── check_env.sh
│   ├── gen_voices.py
│   ├── plan_timeline.py
│   ├── gen_bg.py
│   └── build.py
├── audio/          # ① 产物：01.mp3 … NN.mp3
├── clip/           # ③ 产物：d000.png …
├── chk/            # 自检抽帧
├── lines.json      # ① 产物
├── timeline.json   # ② 产物，⑤ 的输入
├── bg.png          # ④ 产物
└── out.mp4         # ⑤ 产物
```

所有相对路径以**项目根**为基准，不是以脚本所在目录为基准。

## 1. `check_env.sh`

```bash
bash scripts/check_env.sh
```

| 项 | 要求 |
| --- | --- |
| 输入 | 无 |
| 输出 | 逐项打印依赖版本，缺失项给出安装命令 |
| 退出码 | 全部满足返回 0，缺任一返回非 0 |
| 检查项 | `/usr/bin/python3` 版本、`edge_tts` 可导入、`PIL` 可导入、`ffmpeg` 路径与版本、Noto CJK 字体存在 |

## 2. `gen_voices.py`

```bash
/usr/bin/python3 scripts/gen_voices.py
```

| 项 | 要求 |
| --- | --- |
| 输入 | 脚本顶部 `TEXT`（台词）与 `V`（音色/rate/pitch/tag 列表） |
| 输出 | `audio/01.mp3 … audio/NN.mp3`、`lines.json`（每条的文本、时长、音色） |
| 行为 | **串行**生成，每条之间 `sleep(1.0)`；失败重试 4 次，退避 2/4/6/8 秒；产物 ≤1200 字节判失败 |
| 失败处理 | 单条最终失败时打印序号并继续，不能中断整批；结尾汇总失败条数 |

`lines.json` 至少包含：`[{"i":1,"text":"...","dur":1.63,"voice":"...","tag":"..."}]`。
`dur` 必须来自实际音频时长（`ffprobe` 或 `mutagen`），不能用字数估算——时间轴全靠它。

## 3. `plan_timeline.py`

```bash
/usr/bin/python3 scripts/plan_timeline.py --dur 15 --danmaku 120 --mode burst
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--dur` | 是 | 成片时长（秒） |
| `--danmaku` | 是 | 弹幕总条数 |
| `--mode` | 是 | `burst`（短片越冲）/ `sustain`（长片持续） |
| `--lines` | 否 | 默认读 `lines.json` |
| `--out` | 否 | 默认 `timeline.json` |

| 项 | 要求 |
| --- | --- |
| 输出 | `timeline.json` + **stdout 打印逐秒密度表** |
| 密度表 | 每秒一行：秒数、声音数 + 条形、弹幕数 + 条形；空秒必须肉眼可见 |
| 约束 | 弹幕首条 0.05；末条落在 `dur - 0.3`；人声末条落在 `dur - 1` 之前 |

`timeline.json` 结构固定，`build.py` 只认这个结构：

```json
{
  "audio": [{"i":1,"text":"...","dur":1.63,"start":0.15,"track":"main"}],
  "danmaku": [0.05, 0.24, 0.43]
}
```

`track` 只有 `main` / `sub` 两种，音量 0.60 / 0.44。

## 4. `gen_bg.py`

```bash
/usr/bin/python3 scripts/gen_bg.py --size 1080x1080 --out bg.png
```

> 源文档只给了用法和 8 层绘制顺序，没给命令行参数。上面是**推定契约**，
> 实现时以 `--size` / `--out` 为准即可，不要依赖其它参数。

| 项 | 要求 |
| --- | --- |
| 输出 | 目标尺寸的 RGB PNG，无 alpha |
| 图层顺序 | 深底 → 径向辉光 → 主体 → 主体细节 → 火焰/光效 → 粒子 → 暗角 → 噪点 |
| 硬要求 | 火焰底部必须在文字上方；暗角逐行/逐列叠半透明黑；噪点 ±15 |

这一步可以整体跳过——直接 `build.py --bg 现成图.png`。现成图要**先缩放到目标尺寸**。

## 5. `build.py`

```bash
/usr/bin/python3 scripts/build.py --timeline timeline.json --dur 15 --out 成片.mp4 \
    --bg my_bg.png --size 1080x1080 --text "大麦倒闭" --watermark "Powered by WorkBuddy"
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--timeline` | 是 | 读 `timeline.json`，**不允许自己重算时间** |
| `--dur` | 是 | 与 timeline 一致，末尾 `-t` 用 |
| `--out` | 是 | 输出 mp4 路径 |
| `--bg` | 否 | 不给则调 `gen_bg.py` |
| `--size` | 否 | 默认 `1080x1080`；`1080x1920` 竖屏 / `1920x1080` 横屏 |
| `--text` | 否 | 弹幕文本池，逗号或列表分隔 |
| `--watermark` | 否 | 水印文字，默认不带 |

内部必须按顺序完成五件事，**每步可单独调试**：

1. 按 `danmaku` 时间点生成弹幕 PNG → `clip/dNNN.png`
2. 底图准备（缩放或程序化生成）
3. `zoompan` 推拉 + `scale` 预放大 1.1 倍
4. `overlay` 逐条叠加 + `enable=between(t,st,st+life)`
5. `adelay + amix(normalize=0) + alimiter` 混音 → `drawtext` 水印 → `libopenh264` 编码

| 项 | 要求 |
| --- | --- |
| 编码 | `-c:v libopenh264 -profile:v high -coder 1 -b:v 6M -pix_fmt yuv420p`；**无 `-crf`** |
| 输出 | `-movflags +faststart`；时长精确等于 `--dur` |
| 失败处理 | 中间产物保留在 `clip/` 和临时目录，便于单独重跑某一步 |

## 补脚本时的顺序建议

先补 `check_env.sh`（5 分钟，立刻能确认环境），再补 `gen_voices.py`（能出声就知道 TTS 通了），
然后 `plan_timeline.py`（不依赖渲染，纯计算，最容易验证），最后 `build.py`。
`gen_bg.py` 放最后——它可以被现成图替代，不阻塞出片。
