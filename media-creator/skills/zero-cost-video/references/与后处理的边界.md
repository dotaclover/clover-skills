# 与 video-post-production 的边界与重合面

> 结论先行：**任务不重合，技术栈重合 4 处，其中编码器是硬冲突。两个技能应保持独立，不要合并。**

## 一、判断规则：只看一句

**手上有没有源视频。**

| 有源视频 | 没有源视频，只有文案和底图 |
| --- | --- |
| → `video-post-production` | → `zero-cost-video` |

这条规则没有例外。两个技能的输入模型不同，混用会导致完全错误的产出物：
拿本技能去"加工"一条已有视频，等于把原片丢掉重画一张底图。

## 二、任务层：互补，不重合

| 维度 | zero-cost-video | video-post-production |
| --- | --- | --- |
| 输入 | 文案 + 底图（无视频） | 已有视频文件（必需 source） |
| 输出 | 一条全新的合成短片 | 加工后的成片 |
| 核心动作 | 画图 + 生成人声 + 叠加弹幕 | 剪辑 / 拼接 / 重排 / 混音 / 转画幅 |
| 独有能力 | 弹幕层、程序化底图、多人齐喊 | 多源统一、遮挡、限体积双遍、字幕烧录 |
| 明确不做的 | 视频剪辑、ASR、字幕对齐 | 从零生成画面、弹幕、多人音色矩阵 |

`video-post-production` 的 description 里写了「不用于生成新视频」。
本技能正好落在它排除的那一侧，**边界是干净的**。

## 三、技术栈重合矩阵

| 能力 | zero-cost-video | video-post-production | 重合度 |
| --- | --- | --- | --- |
| edge-tts 配音 | 14 中文音色 × rate × pitch | 4 个试听确认音色 × rate | **中**：同一底层，用法不同 |
| 多角色处理 | rate/pitch 矩阵，同音色最多用 3 次 | 分别生成 voice_file 再混入 | 目的相近，手段不同 |
| 混音 | `adelay + amix(normalize=0) + alimiter=0.93` | `amix(normalize=0) + alimiter=0.95` | **高**：同一套滤镜链 |
| 时间轴 | `timeline.json` 驱动渲染，含 `danmaku` 数组 | `timeline.json` 作为交付物，记录剪辑轴 | **名称撞车，含义不同** |
| 文字渲染 | `drawtext` 水印 + PIL 弹幕描边 | `drawtext` / `subtitles` 字幕烧录 | 中：都依赖字体与 drawtext |
| 画幅适配 | `--size`，缩放 + zoompan | `portrait-contain` 等 preset，等比补边 | 中：目的相同，实现不同 |
| 视频编码 | `libopenh264 -b:v 6M`（无 crf） | `libx264 -crf 20`，size 模式双遍 | **冲突**：见下 |
| 弹幕 | 核心能力 | 完全没有 | 不重合 |
| ASR / 字幕对齐 | 没有 | 没有（仅按句长近似计时） | 都没有，别互相推 |

## 四、四处需要处理的问题

### 1. 编码器硬冲突（最要紧）

| | 本技能 | video-post-production |
| --- | --- | --- |
| 编码器 | `libopenh264` | `libx264` |
| 质量参数 | `-b:v 6M`（文档明确 **不能** 用 `-crf`） | `-crf 20`，size 模式双遍 `-b:v` |
| 假设 | **目标机没有编入 x264** | 目标机有 x264 |

`scripts/video_pipeline.py` 第 280 行与第 311 行都硬编码 `libx264`。
而本技能的环境文档明确写「没有 `libx264` / `libx265`，只能用 `libopenh264`」。

**这两个假设不可能同时成立。** 后果：在同一台机器上跑另一个技能的编码参数，直接 `Unknown encoder`。

处理方式：两个 SKILL.md 各自把环境假设写在显眼位置（本技能已写在「四条硬约束」第 2 条）。
**不要为了"统一"去改其中一边的编码器**——openh264 画质与 x264 差距明显，
在支持 x264 的机器上强行降级是净损失。

### 2. `timeline.json` 同名不同义

| | 结构 | 用途 |
| --- | --- | --- |
| 本技能 | `{audio:[...], danmaku:[...]}` | **渲染输入**，脚本只读它 |
| video-post-production | 片段/音轨/字幕的加工记录 | **交付物**，供用户复核 |

两个文件都能叫 `timeline.json`，但结构完全不兼容。
如果两个技能在同一目录下产出，后跑的会覆盖前一个。

处理方式：本技能的产物目录约定为项目根，且文档里明确「`timeline.json` 是渲染输入」。
跨技能协作时，把本技能的 timeline 改名或在独立子目录产出。

### 3. edge-tts 音色策略不同

| | 本技能 | video-post-production |
| --- | --- | --- |
| 音色数 | 14 个中文音色全用 | 4 个用户试听确认的音色 |
| 参数 | rate **+ pitch** | 仅 rate |
| 默认 | 无默认，按情绪矩阵配 | `zh-CN` 缺省走 11 号（台湾女声） |
| 用途 | 伪装成一群人在喊 | 单人旁白 |

**不冲突，但会让用户困惑**：同一台机器上两个技能给出两套"推荐音色"。

处理方式：本技能**不要**定义"默认旁白音色"。它的音色是素材，不是偏好。
单人旁白类需求一律引导到 `video-post-processing` 的音色表（有试听记录，更可信）。

### 4. 混音参数几乎一样，但阈值不同

| | 本技能 | video-post-production |
| --- | --- | --- |
| amix | `normalize=0` | `normalize=0` |
| 限幅 | `alimiter=limit=0.93` | `alimiter=limit=0.95` |
| 人声音量 | 主 0.60 / 副 0.44，逐条 volume | 固定 original_volume / voice_volume |

`normalize=0` 两边一致，这是正确做法（否则 amix 会自动压音量）。
限幅阈值 0.93 vs 0.95 的差异来自人声叠加强度不同：本技能同时 3 人以上，留的余量更大。

**不建议抽公共库。** 两个 skill 要能独立分发，共享一个 `ffmpeg_utils` 会让安装和升级互相牵制。
重复这十几行滤镜字符串，比引入耦合划算。

## 六、结论与动作

| 决定 | 理由 |
| --- | --- |
| **保持两个独立技能** | 输入模型不同（有无源视频），合并后 description 无法自洽 |
| 各自在 SKILL.md 声明边界 | 已在本技能写入；建议 `video-post-production` 也加一句反向指引 |
| 不抽公共库 | 独立可分发优先于 DRY |
| 不统一编码器 | 环境假设不同，强行统一必然有一边降级 |
| 不统一音色表 | 用途不同：一个是素材，一个是旁白偏好 |

**唯一建议的联动**：两个 SKILL.md 互相写一句"另一个场景走 XX"。
这是纯文本指引，不产生代码耦合，能避免调用时选错。

## 五、与口播工坊的边界（稿子 → 成片）

三个 `*-script-studio`（抖音 / 快手 / 视频号）产出的是**稿子**，本技能产出的是**成片**，不重合。
但两者共享同一个方法论：**先把"什么时候响"排成表，再渲染**——口播工坊叫段落节奏表，本技能叫密度表。

| | 口播工坊 | 本技能 |
| --- | --- | --- |
| 输入 | 选题 / 简报 | 台词 + 底图 + 密度参数 |
| 中间产物 | 时间轴脚本（段落 / 秒数 / 语气） | `timeline.json`（每条起止 / 弹幕时点） |
| 输出 | 可念的稿子 | mp4 |
| 失败点 | 前 3 秒不进主题 | 开头留白、末段掉成 0 人声 |

**接口只有一处**：口播稿的段落秒数可以直接当 `--dur` 和密度表的骨架用，
但**不能**把口播稿逐句塞进本技能——本技能是多音色齐喊，不是单人旁白；
要单人旁白请走 `video-post-production`。

## 附：检查中发现的无关缺陷

`video-post-production/SKILL.md` 的 YAML frontmatter 定界符被写成了 `\---`（反斜杠 + 三横线），
首行和闭合行都是。**这会让 frontmatter 解析失败**，WorkBuddy 可能因此读不到 name/description/agent_created。

当前该文件在 git 里处于未提交修改状态（`M video-post-production/SKILL.md`）。
修正只需把两处 `\---` 改成 `---`，但属于另一个技能的改动，本次未动。
