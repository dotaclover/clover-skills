# 渲染细节（步骤 ③④⑤）

## 一、弹幕 PNG（Pillow）

每条弹幕渲成一张**带 alpha 的独立 PNG**，再由 ffmpeg 叠加。不做这个分层，就没法逐条控制飞入时间和轨道。

```python
fs = random.choice([38, 44, 50, 56, 64, 72, 80])   # 字号随机，大小不一才像弹幕
f = ImageFont.truetype(FONT, fs)
bb = f.getbbox(TEXT); pad = 30
im = Image.new("RGBA", (bb[2]-bb[0]+pad*2, bb[3]-bb[1]+pad*2), (0,0,0,0))
dr = ImageDraw.Draw(im); ox, oy = pad-bb[0], pad-bb[1]

# 黑描边：以字为中心、半径 5 的圆内反复偏移描
for dx in range(-5, 6):
    for dy in range(-5, 6):
        if dx*dx + dy*dy <= 26:
            dr.text((ox+dx, oy+dy), TEXT, font=f, fill=(0,0,0,245))

# 主色随机
col = random.choice([(255,255,255,255), (255,250,240,255), (255,70,58,255),
                     (255,150,36,255), (255,246,86,255), (140,220,255,255)])
dr.text((ox, oy), TEXT, font=f, fill=col)
```

**描边不能省。** 底图是深色时白字会糊在背景里，黑描边让它始终跳出来。
`pad=30` 是给描边和字形外扩留的余量，太小会把边缘切掉。

## 二、底图（两选一）

| 路线 | 做法 | 什么时候用 |
| --- | --- | --- |
| A 程序化画 | `gen_bg.py`，8 层绘制 | 要风格统一、可批量改色的插画 |
| B 用现成图 | `--bg 你的图.png`（**先缩放到目标尺寸**） | 已有满意底图 |

程序化底图的**图层顺序**（顺序错了画面会脏）：

```
1. 深色打底
2. 径向辉光（决定亮部在哪，先画）
3. 主体（人物/物件）
4. 主体上的细节（文字、线条）
5. 火焰/光效（锥形多边形做火舌，别用椭圆堆）
6. 粒子（火星、烟）
7. 四边暗角（逐行/逐列叠半透明黑）
8. 噪点（随机像素扰动 ±15，去数码感）
```

**两个画底图的坑**：

- 火舌用椭圆堆会**盖住招牌文字**。必须写锥形多边形函数，并把火焰底部定在文字**上方**。
- 火柴人别画成保龄球瓶：头用**窄椭圆**（横向半径 ×0.92），躯干要比头宽，腿要够长。

### 横屏素材转竖屏 / 方屏

**不要直接裁。** 横图硬裁成 9:16 会把两侧的文字和主体切掉——这是改画幅时最常见的废片原因。

正确做法（三步）：

```
1. 原图按目标高度等比缩放，居中放 —— 主体和文字完整保留
2. 两侧空出来的部分，用「原图放大填满 + 高斯模糊 + 压暗」的版本垫底
3. 两条接缝用羽化蒙版过渡（横向渐变 alpha），别让边线一眼看出来
```

糊边不能太亮：压暗到原图亮度的 0.5–0.6，否则观众的视线会被两侧抢走。
主体占画面宽度不足 60% 时，宁可重新构图（把文字重排到竖向版式），也不要用这套填充硬凑。

## 三、混音（adelay + amix）

每条音频按它的 `start` 延迟，再全部混合：

```
[0:a]adelay=150|150,volume=0.60[a0];
[1:a]adelay=700|700,volume=0.44[a1];
...
[a0][a1]...amix=inputs=N:duration=longest:normalize=0,alimiter=limit=0.93[aout]
```

| 参数 | 说明 |
| --- | --- |
| `adelay=150\|150` | 毫秒，两个通道都要写，只写一个会有一边不延迟 |
| `normalize=0` | **必须加**。否则 amix 自动压音量，人声叠得越多反而越小 |
| `alimiter=limit=0.93` | 末尾防削顶爆音。人声峰值叠加很容易超过 0dB |

## 四、底图动效（zoompan）

静止底图像 PPT。加缓慢推拉立刻活：

```
scale=1188:1188,
zoompan=z='1.025+0.04*sin(on/128)':d=1:
        x='iw/2-(iw/zoom/2)+20*sin(on/84)':
        y='ih/2-(ih/zoom/2)+16*cos(on/97)':
        s=1080x1080:fps=30
```

**先 `scale` 到 1.1 倍再 zoompan**，否则推拉时会露出黑边。
三个三角函数用不同周期（128 / 84 / 97），画面才不会规律地"呼吸"。

## 五、弹幕叠加（overlay）

每条弹幕一张 PNG，横向从右往左飞：

```
[base][1:v]overlay=
  x='W-(W+w)*(t-0.05)/1.8':              # 1.8 秒走完整个屏宽
  y=482:                                  # 所在轨道
  enable='between(t,0.05,1.85)'           # 生命周期
```

| 变体 | 做法 |
| --- | --- |
| 停留时长 | `random.uniform(1.5, 2.1)` 秒。低于 1.2 秒看不清，高于 2.5 秒屏幕糊成一片 |
| 全屏随机轨道 | `y = random.randint(0, H - th - 2)`；想避开主体就限制取值区间 |
| 斜向弹幕 | y 加微系数 `y + 0.02*f(t)` |
| 竖向弹幕 | 5% 概率改成 `y='H-(H+th)*(t-st)/life'`（从下往上） |
| 结尾大字 | 最后几条用 96–126px 放大并居中，做收尾强调 |

`enable` 的时间窗必须比位移时长**略宽**（0.05→1.85 走 1.8 秒），否则最后一帧会被截掉。

## 六、水印与合音

```
[0:v]drawtext=fontfile=/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc:
  text='Powered by WorkBuddy':
  fontcolor=white@0.85:fontsize=30:
  borderw=3:bordercolor=black@0.85:
  x=w-tw-26:y=h-th-22[v]
```

- 水印必须**带黑描边**（`borderw=3`），否则弹幕飞过后盖住就看不清。
- 最终输出加 `-movflags +faststart`，网页和手机能秒开。

## 七、编码

```
-c:v libopenh264 -profile:v high -coder 1 -b:v 6M -pix_fmt yuv420p
```

`-coder 1` = CABAC 熵编码，同码率下画质更好；`-profile:v high` 是允许 CABAC 的前提。
**不能写 `-crf`**，这台机器的 libopenh264 不吃。
