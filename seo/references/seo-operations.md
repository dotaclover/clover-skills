## 3. 只读基线命令

```bash
# 工具路径和输出目录先从项目配置解析并审查参数；无工具时手动记录同字段
python "$BASELINE_SCRIPT" \
  --site "$SITE_URL" \
  --name "客户已确认的品牌名" \
  --output-dir "$REPORT_DIR"

# 页面源码是否有正文；不要把“状态码200”当成“正文可抓取”
curl -L --max-time 20 -sS https://example.com/ | head -c 12000

# robots 与 sitemap 是否能访问
curl -i -L --max-time 20 https://example.com/robots.txt
curl -i -L --max-time 20 https://example.com/sitemap.xml

# 页面状态与跳转链
curl -I -L --max-time 20 https://example.com/

# 证书基本观察（不替代正式证书检查）
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | openssl x509 -noout -dates -subject
```

Windows PowerShell可将`curl`替换为`curl.exe`，避免调用别名；命令只读，不把结果直接当成排名结论。

## 4. 页面源码检查要点

- `<title>`存在且与页面主主题一致。
- `meta[name="description"]`存在且准确。
- 主内容不只有`<div id="app">`、骨架屏或空壳。
- H1数量与页面结构合理；不是为了凑数量硬塞。
- canonical指向正式URL，不能指向旧域名或首页。
- JSON-LD中的名称、电话、地址、服务、FAQ必须在页面可见文字中有依据。
- 图片有合理alt；装饰图可以空alt，不用关键词污染。
- 内链不是404、不是javascript伪链接。

## 5. 问题严重度

| 严重度 | 判断 | 例子 | 处理 |
|---|---|---|---|
| P0 | 页面不可访问或误封全站 | 5xx、robots封`/`、证书异常 | 先故障诊断/运维，SEO暂停 |
| P1 | 关键页面无法理解或无法抓取 | 空壳HTML、canonical全指错、首页无主体内容 | 一次性优先修 |
| P2 | 主题、结构和实体不清 | 标题重复、H1缺失、地址/电话不一致 | 排期修正 |
| P3 | 增长与内容机会 | FAQ不足、内链弱、问题集未覆盖 | 在本次页面范围内修正，超范围交主理人确认 |

严重度是技术影响优先级，不是搜索结果保证。

## 7. 诊断结论四句话

1. **问题是什么**：例如“服务页源码没有正文，只有JS挂载节点”。
2. **根因在哪**：例如“当前构建没有预渲染，抓取时拿不到业务文本”。
3. **能不能修**：例如“可以修，但属于开发改造，不在当前约定范围内”。
4. **修要多少钱/走哪里**：引用当前项目合同与工作量评估，转故障修复或开发流程，不内置价格。
