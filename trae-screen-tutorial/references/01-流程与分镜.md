# 流程与分镜

## 一条片的形状

以《决策复盘日记》三集为基准，一条竖屏教程片的规格是：

| 项 | 值 |
|---|---|
| 画面 | 1080×1920，30fps，H.264，yuv420p，`-crf 16`，`+faststart` |
| 时长 | 75–90 秒（远优于 45–60 秒：讲得清 + 完播率仍可接受） |
| 拍数 | 7–8 拍，单拍 10–13 秒 |
| 结构 | 开场钩子 → 3~5 个主体拍 → 收尾卡 |
| 旁白 | 每拍 60–90 字，语速 +18% |
| 字幕 | 大字结论（2 行）+ 底部烧录口播字幕 |

不要做成 9 拍 58 秒。拍越碎，每拍越像 PPT 切换，观众来不及读。宁可少一拍、多讲一句「为什么」。

## 每拍的固定骨架

1. **画面**：只保留一个信息焦点（一个对话气泡 / 一个页面 / 一段操作）。
2. **大字**：步骤号 + 章节 + 标题（标题是这一拍的观点，不是画面描述）。
3. **结论字幕**：两行，第一行是判断，第二行是补充，每行 ≤ 14 字。
4. **旁白**：先事实，再「为什么」。为什么能一次成型、为什么这次不合并、为什么先不做。

## 三集的叙事模板

- **EP01 需求 → 原型**：钩子是「一句话能不能变成能点的东西」；主体是四步（提需求 / 出 PRO / 定 MVP / 出原型）；收尾「只做到原型，下一条装进手机」。
- **EP02 改界面**：钩子是「界面改三遍，代码只写一遍」；主体是三次改动，每次一句「哪里不顺手」；收尾抛给下一集。
- **EP03 写代码 → 发版 → 开源**：钩子是「界面定死，代码就是翻译」；主体三页结构、验收数据、MVP；收尾是 star / fork 的引导。

三集共用一句话母题，每集只推进一个阶段，结尾互相接力。这是连更合集能被连播的前提。

## 先写文案，后做片

顺序不能反：

1. 出文案（每拍的旁白 + 大字 + 字幕），**贴给用户确认**。
2. 确认后量素材、配画面。
3. 出片、抽帧验收、交付。

文案阶段改一句是一分钟，出片后改一句是重渲一遍。

## 时长算法

```
dur = max(3.0, round((配音时长 + 0.55 + hold) * 30) / 30)
```

`hold` 用来给「需要多看两眼」的画面留时间（图表、文件树、推广卡）。缺省 0，重点拍 1.2–2.6 秒，收尾卡 2.6–3 秒。
