# 素材与裁切

三类素材，三种打法。

## 1. Windows 桌面 / IDE 录屏（16:9，如 2432×1440）

- 先用 `ffprobe` 记分辨率、帧率、时长；再每 5–10 秒抽帧，挑出「有信息变化」的窗口。录屏里大量是等待，全部剪掉。
- **裁切框必须量，不能猜**：`python scripts/measure_crop.py 录屏.mp4 --t 12` 打印列 / 行的墨迹分布，密集区间就是内容区。
- TRAE / VS Code 这类三栏布局（左文件树、中间对话、右预览），**一个 4:5 框不可能同时容下两栏**。每拍只对准一栏，另一栏宁可切掉。

真人踩过的坑：用 0.8 比例的框去套「整屏中段」，结果左右各切掉半个句子，必须重审。判断标准是**文字列的第一行和最后一行都完整**，不是「看起来差不多」。

帧内坐标参考（2432 宽录屏）：

| 区域 | x 范围 | 说明 |
|---|---|---|
| 文件树 / 侧边栏 | 0 – 500 | 一律不进画面 |
| 中间对话栏 | 500 – 1400 | 气泡右对齐时约 1080–2020，需按帧实测 |
| 右侧原型预览 | 1400 – 2432 | 手机面板约 1620–2300，居中取 1432 宽 1000 的框 |

## 2. TRAE 会话导出的长截图（如 1119×14990）

- 长图不能整张塞进画面框，要按**对话段落**切：一段一个拍，`crop=[图, x, y, w, h]`。
- 常见做法：窗口固定 `1119×1399`（正好等于 960×1200 的 4:5），只改 `y`，让内容首尾相接滚过去。
- 切段前先用 `measure_crop.py 长图.png` 看行墨迹，找段落之间的空白行当分界，避免半个气泡被切成两拍。
- 一段装得下一屏就**静止显示**，不要为了动而动。无意义的平移比静止更像 bug。

## 3. 手机真机录屏（竖屏，如 592×1280）

- 天然接近 9:16，直接 `scale` 到 960×1200 再 `pad` 黑边即可，两侧黑边是正常的。
- 竖屏素材做平移也不稳，**优先静止 + 放大**。截图类素材任何缩放动画都会让文字抖动，全部关掉。
- 真机素材最值钱的是「手指真的点了」的那几秒，取 `t_in/t_out` 时把成功动作完整包住，不要切在动作中间。

## 取景两种模式

- **铺满（fill）**：先按 4:5 取景框裁，再缩放，零黑边。适合截图、单栏对话、原型预览。
  `vcrop=(x,y,w,h)` 宽高比必须等于 0.8，`measure_crop.py` 会直接给出。
- **留边（contain）**：素材比例与画面框不符时等比缩进，两边黑底。适合竖屏真机、开发者工具整窗。

## 加速与补帧

材质时长 `mat` 与画面时长 `dur` 不等时：

```
speed = max(1.0, mat / dur)          # 打字过程可 1.5–2.4 倍
setpts=(PTS-STARTPTS)/speed
tpad=stop_mode=clone                 # 素材不够就挂尾帧，不要来回跳
```

打字、滚屏这类过程性画面加速到 1.5 倍以上仍然好看；翻页、弹窗这类结果性画面不要加速，加速会让观众漏掉结果。
