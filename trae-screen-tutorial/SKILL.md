# 录屏 → 竖屏教程系列

一条竖屏教程片的核心不是「把 16:9 转成 9:16」，而是**逐拍重新取景**：每一拍只保留画面里真正要看的那一栏，放大到手机上能读清，再用旁白和字幕补上「为什么」。

本技能以《决策复盘日记》三集（EP01 需求→原型 / EP02 改界面 / EP03 写代码→开源）为基准，三集连更、统一版式、统一封面、可直接发布的成品形态。

## 什么时候用

- 手上有 IDE / 浏览器 / 桌面录屏、TRAE 会话长截图、或者手机真机录屏，要做成竖屏教程。
- 要把一段开发过程拆成「系列」，一集只讲一个阶段，结尾互相接力。
- 要的不只是视频，还有封面、标题、描述、话题、跨平台分发。

不适用：纯口播、无人值守长录屏（>30 分钟）。要 16:9 长片时走横版讲解台，版式和规则见 `references/04-版式与封面.md` 的「横版讲解台」。

## 交付形态

```
<项目>/
├─ 成片 /*.mp4               # 1080×1920，75–90 秒一集
├─ 封面 /*.png               # 1080×1440，3:4
├─ beats.json               # 唯一事实源：每一拍的全部参数
└─ build/                   # audio（TTS 缓存）/ parts / slides / ep0x.mp4
```

## 流程

1. **先出文案，等确认**。写之前先读 `references/00-顺哥profile.md`（人设、三偏好多常做一底线、句式与自检清单）。每拍的旁白 + 大字 + 两行字幕，贴给用户过一遍。这一步改一句是一分钟，出片后改一句是重渲一遍。**没确认文案不出片。**
2. **量素材**。三类素材分别处理（桌面录屏 / 长截图 / 手机录屏），裁切框用 `scripts/measure_crop.py` 量出来的墨迹区间，不靠肉眼。
3. **写 `beats.json`**。7–8 拍，每拍 10–13 秒，字段见 `references/07-配置字段.md`。
4. **`--preview` 看静帧**。每拍出一张 1080×1920，只检查三件事：取景有没有切字、字幕有没有压进度点、有没有混进无关面板。
5. **出片**。`dur = 配音 + 0.55 + hold`，量化到 1/30 秒；素材长就 `setpts` 加速，短就 `tpad` 挂尾帧。
6. **验收 + 交付**。解码校验、抽帧、响度、ASCII 路径副本，见 `references/06-后期与验收.md`。**没抽帧看过成片不算完成。**
7. **出封面 + 分发文案**。`scripts/make_covers.py` 出三张 3:4 封面；文案按 30 字标题 / 100 字描述 / 5 个话题。

## 三条铁律

1. **一拍一个焦点**。TRAE 是左文件树 / 中对话 / 右预览的三栏布局，一个 4:5 框装不下两栏，装不下就切掉，不要「差不多居中」。
2. **截图绝不做缩放动画**。zoompan、缓慢推镜在 1080 宽度下会给文字带来亚像素抖动，是观众最容易察觉的瑕疵。静止即专业。
3. **画面框尺寸永不改变**。变的只是框里的内容和框外的文字，系列感来自这里。

## 命令

```bash
pip install -r requirements.txt          # Pillow / edge-tts / numpy

python scripts/measure_crop.py 录屏.mp4 --t 12      # 量取景
python scripts/build_video.py --beats beats.json --preview   # 静帧自查
python scripts/build_video.py --beats beats.json             # 出片
python scripts/make_covers.py                                # 三张封面
```

依赖 `ffmpeg` / `ffprobe` 在 PATH；中文字体用系统 `msyhbd.ttc` / `msyh.ttc`。

## 边界

- 只做「已有素材 → 成片」，不录屏、不做 ASR、不自动识别场景；时间窗与取景由预览决定。
- 不虚构画面里没有的输入、弹窗、报错。文案只能来自实际素材或用户提供的事实。
- 不自动上传平台。发布信息（标题 / 描述 / 话题）给文案，由人来发。
- TTS 需要联网；不可联网时用缓存 mp3 或纯字幕版。
