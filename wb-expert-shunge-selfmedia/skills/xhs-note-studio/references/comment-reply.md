# 评论区回复

> 用户贴来一串评论、要"帮我回评论"时加载本文件。**这条分支不写笔记**，只做分类、回复、处置。
> 语气一律按账号卡（`~/.workbuddy/xhs-profile.md`）的「说话方式」；没有账号卡时用本文件的中性默认。

## 一、先分类，再回复

| 类型 | 典型内容 | 本质 | 优先级 |
|---|---|---|---|
| **专业质疑** | "这个方案在高并发下不行吧""你这里是不是漏了锁" | 送分题。答得好立权威，答不好翻车 | 最高 |
| **求源码 / 求配置 / 求教程** | "求完整配置""有仓库吗" | 高意向，也是涨粉机会 | 高 |
| **报错求助** | "我照着做，报了 xxx" | 他替你踩了一遍坑，是选题 | 高 |
| **提问（怎么用 / 什么时候出）** | 明确提问 | 给答案，别引导私信 | 中 |
| **夸赞** | "学到了" | 一句带过，不客套连篇 | 低 |
| **同行引流** | 直接贴自己账号 / 联系方式 | 不回复，按平台规则处理 | 中 |
| **纯抬杠** | "没有意义""早就有了" | 无信息量，不消耗 | 低 |
| **催更** | "系列还更吗" | 关系资产，给具体信息 | 中 |

## 二、四条原则

1. **质疑必须正面答。** 对的就认，错的给依据，没测过就说没测过。回避、打太极、说"每个人情况不同"＝承认自己不懂。
2. **不客套。** "感谢支持""谢谢喜欢"在专业垂类里显得假，直接给信息。
3. **给到能用的东西。** 求配置就给配置，不能全给就说清为什么、能给到哪。
4. **报错当选题。** 同一个报错被问两次，就该写一篇。

## 三、专业质疑：三种情况三种答法

| 情况 | 答法 | 模板 |
|---|---|---|
| **他说得对** | 直接认，不找补 | 对，我这里只测了【场景】，你说的那个情况没覆盖。补一句：【局限或补充】 |
| **他说得不对** | 给依据，不给态度 | 我这边实测是【具体结果】，环境是【版本/配置】。你那边什么环境？可能是【差异点】 |
| **没测过** | 老实说 | 这个我还真没测过，只用过【范围】。等验完回你 |

**绝对不要写**："感谢指正，我们会不断优化""每个人情况不同""可以私信详聊"。这三句等于自证是营销号。

## 四、其他高频场景

**求源码 / 求配置**

> 完整配置在【哪里】，这里是节选。涉及【原因】的部分我去掉了，其余能直接跑。

不能全给时：

> 这套里有【客户/内部】的东西，不方便全放。能给的都写出来了，卡在哪告诉我。

**报错求助**

> 这个报错大概率是【原因】。先看【检查点】，不对的话把完整日志发我。

不要一上来让人"检查环境"，那是敷衍。

**催更**

> 在写，下一篇是【具体内容】，大概【时间】。

给具体内容，不给"尽快"。

**纯抬杠**：不回、不删、不拉黑（除非人身攻击）。回复抬杠的唯一后果是给它流量。

**同行引流**：软广和留联系方式不回复，按平台规则处理；正常同行讨论正常交流，不针对人。

## 五、评论区运营动作

- **置顶**：置顶一条**质疑 + 你的完整回答**。比置顶夸赞有效得多，等于公开摆出"经得起问"。
- **精选**：精选补充了有效信息的评论（别人帮你补了坑），公开致谢。
- **自己先示范**：结尾问的具体问题，自己在评论区先回一条，降低别人开口成本。
- **黄金时段**：发布后 1–2 小时优先回复（经验值，非平台承诺），这段互动密度影响初始推荐。

## 六、负面与危机

笔记本身有问题（方案不可行、数据写错）时：

1. **认**。第一句就承认，不要先解释。
2. **改**。说明改了什么，或直接编辑笔记标注更正。
3. **不删帖**。删帖等于承认心虚，容易被截图。
4. **不辩论**。说清事实后停止纠缠。

如果是误解：给依据，不指责对方理解能力。
