# 提示词模板库

> 模板为虚构场景，不代表真实客户门店、地址或案例。命令从当前技能实际目录运行。
> 记录提示词骨架；模型与服务变化时重新验证，不把历史效果当保证。
> 所有无文字/无水印构图要求仅针对可自由设计的内容；必须保留服务、版权或来源要求的标记。

## 一、总原则

### 1. 中文一律不让模型写

模型渲染中文必糊：字形错、笔画粘连、英文混排。海报上一个错字就废。

做法：
1. 提示词里写「画面里不要出现文字」「no text」「no watermark」
2. 出图后用 `image_api.py overlay --font <字体文件>` 叠中文，确认字体许可与字形覆盖
3. 网站里的正文、标题**根本不该由模型写**——那是 HTML 的活

### 2. 一套图一个风格

每张单独写提示词，风格必然漂移，整站看起来像拼的。
**把「光线、色温、材质」这三句抄三遍到每一条提示词里。**

实测用的风格前缀（咖啡馆纪实）：

```
真实感门店纪实摄影，暖色调，旧木与暖白墙面，午后自然光，浅景深，画面干净，无文字无水印，不出现人脸
```

换成别的行业就换这三句，但**结构不变**：材质 + 色温 + 光线 + 景深 + 干净 + 无文字。

### 3. 不要堆画质词

「高清、8K、masterpiece、ultra detailed」这类词对 gpt-image-2 系列几乎没效果，
反而容易让画面变假。要真实感就写具体的拍摄条件（手机随手拍、自然光、不摆拍）。

### 4. 构图留白是有目的的

| 位置 | 提示词里要写 | 为什么 |
| --- | --- | --- |
| 首屏大图 | 主体偏左或偏右 | 另一侧要放文字 |
| 菜单单品 | 主体居中，背景干净 | 卡片小尺寸也要认得出 |
| 砖块图 | 主体清晰，别拍太远 | 砖块只有 200px 宽 |
| OG 分享图 | 简洁构图 | 聊天软件里缩得很小 |

## 二、站点配图五类

对应 `image_api.py plan` 输出的五组。

### 1. 首屏大图（1536×1024，3:2）

```
【主体：门店门头 / 产品特写 / 工作场景】，横版构图，主体偏左，
大面积干净背景用于放文字，柔和自然光，浅景深，真实感纪实摄影，
无文字无水印，不出现人脸
```

实测可用（江南咖啡馆）：

```
广州老城区巷子里一间小咖啡馆的门面，木质门框与一整面大玻璃窗，
窗内暖黄灯光，门口两张小圆桌和折叠椅，墙边一盆龟背竹，
真实感门店纪实摄影，暖色调，旧木与暖白墙面，午后自然光，浅景深，画面干净，无文字无水印，不出现人脸
```

**首屏是最贵的一块地**，别让人物占正中，首屏要的是空间感。

### 2. 菜单/产品图（1024×1024，1:1）

```
一杯浅烘手冲单品咖啡，白色陶瓷杯与玻璃分享壶，旁边一小碟柑橘与咖啡豆，
吧台木面，真实感纪实摄影，暖色调，午后自然光，浅景深，画面干净，无文字无水印
```

要点：
- **一张图只放一样东西**，多个产品不要拼在一张里
- 写清器皿与台面材质（白色陶瓷杯 / 粗陶托盘 / 木质吧台），这是同店感的关键
- 写清饮品状态（冰块与水珠、奶泡拉花、切片露出流心）

### 3. 招牌砖块图（1024×1024，1:1）

```
手冲咖啡壶正在注水，细水柱落入滤杯，暖光侧照，能代表这类服务的特写，
真实感纪实摄影，暖色调，浅景深，画面干净，无文字无水印
```

砖块要小尺寸也认得出，所以**拍特写不拍全景**。

### 4. 案例/环境图（1536×1024，3:2）

```
咖啡馆室内手冲吧台，五个高脚位，吧台上摆着手冲壶、滤杯和几袋咖啡豆，
木质吧台，暖光吊灯，真实感纪实摄影，暖色调，画面干净，无文字无水印
```

环境图用于「到店什么样」，案例图用于「我们做过什么」，别混。

### 5. 社交分享图 OG（1024×1024，1:1）

```
【品牌主体】的极简图形标志，暖棕底色，单色描边，居中构图，
适合缩小后仍可辨认，无文字无水印
```

## 三、图生图（改图）

供应商 `sub` 的编辑协议为 `/images/edits`（multipart），但本脚本未实现该上传入口，`send --image` 不可作为该能力使用。
使用支持该协议的授权编辑工具，或使用 rrw 的 `upload` 获取引用 ID 后提交任务。
**图生图必须验原图主体有没有进去**，不能只看 HTTP 200。不要把特定兼容层曾丢弃字段的现象推断为所有模型行为。

## 四、整站设计图（4K 四宫格）

客户要"先看看整站长什么样"时，出四宫格设计稿：一张图里四个页面。

```
【站点类型，如：咖啡馆】的网页设计稿，四宫格布局，
左上：首页首屏，右上：菜单页，左下：预约页，右下：关于页，
米白纸底色，暖棕主色调，卡片圆角，真实界面截图风格，
每个页面留出清晰的排版区块，界面中用灰色占位条表示文字区域而非真实文字
```

要点：
- **界面里的文字必须写成"灰色占位条"**，不要写中文——模型写的中文会糊
- 明确说「界面中用灰色占位条表示文字区域而非真实文字」，这句能显著降低糊字概率
- 尺寸限制以当前模型目录为准，出图后用 `size` 核对真实尺寸
- 大响应要按网络条件配置超时；默认尊重系统代理，不强制绕过

## 五、叠字（overlay）

模型出的图没有中文，用 overlay 补。

```bash
python expert/skills/site-visual-design/scripts/image_api.py overlay \
  --image out/image-01.png --text "今日手冲" \
  --out out/hero.png --font-size 64 --align center --y 120 \
  --bg 43 38 34
```

参数：
- `--font-size` 起始字号，脚本会**自动缩到能放下**为止（不会出框）
- `--align center|left`，`--y` 距顶像素
- `--fg` `--bg` 是 RGB 三元组，`--bg` 给了就在文字后面垫半透明色块
- `--font` 或 `IMAGE_FONT` 指定已获许可的字体文件；缺失时明确报错

## 六、常见坏图与对策

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 中文糊成一团 | 模型渲染中文 | 提示词写「无文字」，出图后 overlay 叠 |
| 一套图风格不统一 | 每张单独写提示词 | 风格前缀抄三遍 |
| 主体被裁掉 | 没写构图 | 写明「主体偏左/居中，留出干净背景」 |
| 尺寸对不上 | 服务端压了 | `save --expect-size` 看 mismatch，用 `size` 核真实值 |
| 图里有水印 | 来源或服务要求的标记 | 不得移除必须保留的标记，不得换模型或裁切来绕过服务限制；只有确有处理权且服务允许时才处理 |
| 出现奇怪的人脸 | 场景里带了人 | 提示词写「不出现人脸」；有真人产品图改用客户原图 |
| 图看着很 AI | 堆了画质词 | 去掉「8K/高清/masterpiece」，改写具体拍摄条件 |
| 图片内容像错误页 | 存的是 HTML | `save` 会拦（内容不像图片），别直接改名 |
