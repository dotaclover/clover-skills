# WordPress后台交付与教学

代码开发查 `wp-dev`，交付范围查 `site-delivery`。先取得当前project brief、实际主题/插件清单、客户使用说明和验收清单，不假定固定仓库、演示站、页数或插件组合。参考 `references/backend-map.md`、`references/pitfalls.md` 和 `references/demo-script.md`，其中`opc-*`是可选实现示例，须核对现场再使用。

## 后台地图

记录页面、媒体、产品/CPT、预约/询盘、外观、自定义、菜单、用户、导出、站点设置的实际入口、角色权限及前台影响。按用户任务设置快捷入口；隐藏菜单不等于权限控制。是否保留评论、站点编辑器、字体和注册功能由站点业务及角色策略确定，不把示例站的禁用规则当通用标准。

## 交付前检查

1. 在测试副本核对管理界面、语言、时区、固定链接、注册策略和实际权限。修改这些配置需要授权，不默认中文、固定时区或关闭注册。
2. 检查隐私页及草稿归属；不得因为英文标题或草稿状态就删除。只有本任务创建且确认无引用的冗余对象，经用户确认后优先移入回收站，永久删除另行确认。
3. 核对电话、联系入口、营业时间、表单与配色等项目字段，保存后验证前台真实变化。
4. 按本项目功能清单验收，不固定要求21步、17个字段或某组菜单消失。

## 操作测试

优先在隔离测试副本运行。若项目提供`admin_walk.mjs`或同类工具，先找到实际路径、完整审查目标/凭据/写入/删除行为，再读`--help`；不能仅凭`--dry`名称认定只读。脚本不存在就按清单手动执行，不引用固定工具仓库。

- 首先只读记录基线：现有页面、产品、预约、用户ID及关键设置；私有数据只保存必要字段并保护访问。
- 写入、发布、发邮件、创建账号及删除均须单独授权；生产测试须额外确认窗口与通知影响。凭据经安全输入/秘密管理传递，不放命令行、录屏和报告。
- 每次测试对象带唯一标记，记录创建ID、旧值、新值及恢复步骤。修改真实页面前保存原值，恢复时核对是否有并发修改，冲突停止并询问。
- 清理仅限本任务创建、用户已确认的对象；不批删预约或用户，不以“预约必须为0”“用户只剩demo”为通过标准。
- 验收依据基线差异和对象ID：原有数据未动、任务对象按授权清理或保留、设置回到原值；计数相同不能证明恢复完整。
- 脚本失败不等于自动回滚。停止后核对现场，列出残留对象和未恢复值，不能标记完成。

## 推荐测试路径

| 动作 | 验收 |
|---|---|
| 登录与菜单 | 角色权限及入口符合本项目约定 |
| 修改测试页段落 | 保存完成后前台可见，恢复后与基线一致 |
| 修改测试设置/配色 | 设置已保存、前台变量变化、其他字段未清空 |
| 创建测试产品/CPT | 前后台可见性及授权清理记录 |
| 提交测试预约/询盘 | 后台ID、状态与邮件交付证据，记录不等于邮件送达 |
| 创建测试账号 | 最小权限生效，按授权撤销，不删除原有用户 |

## 用户教学与收尾

按演示参考依次讲前台、内容编辑、站点资料、配色、业务记录和权限边界；实际功能不适用则跳过并注明。让用户自己操作获准的测试内容，录屏避开秘密和个人信息。改结构、换主题、停插件及删除业务内容先说明影响与恢复方式，不禁止用户依法管理自己的站。

交接裁剪后的说明、操作记录、备份与恢复步骤；新增需求、支持窗口和售后按当前合同，不内置售价或期限。撤销临时权限并回传完整结果。
