# 后台地图：每屏改什么，改完影响前台哪一块

> 以下为可选`site-store` / `site-business`实现的后台地图示例；开工先核对当前项目主题、插件版本及实际菜单，不假定已部署这些实现。

## 一、设置 → 站点资料（`options-general.php?page=site-site-kit`）

客户最该记住的一页，17 个字段，存在 option `site_site_kit`，**换主题也不丢**。

| 字段（后台显示名） | 键 | 影响前台哪里 |
| --- | --- | --- |
| 商家名称 | `name` | 页头字标、页脚、结构化数据 `LocalBusiness.name`、标题后缀 |
| 主体类型 | `business_type` | 结构化数据 `@type`（`LocalBusiness` / `Organization`） |
| 联系电话 | `phone` | 页头热线、页脚、手机底部拨号条（`tel:`）、结构化数据 |
| 微信号 | `wechat` | 页脚/联系页 |
| 微信二维码图片地址 | `wechat_qr` | 联系页二维码；**先上传到媒体库再粘地址** |
| 电子邮箱 | `email` | 联系页、表单通知收件人、结构化数据 |
| 详细地址 | `address` | 页脚、联系页、结构化数据 |
| 所在城市 | `locality` | 结构化数据、页脚 |
| 营业时间 | `hours` | 页脚、联系页、结构化数据 `openingHours` |
| 服务区域 | `area` | 结构化数据 `areaServed` |
| 联系页地址 | `contact_url` | 页头/页脚「联系我们」按钮 |
| 预约表单地址 | `booking_url` | 手机底部「立即预约」；门店站指向 `/booking#booking` |
| 可预约的服务项目 | `booking_services` | 预约表单的服务下拉（每行一项，或 `\|` 分隔） |
| 产品页按钮文案 | `catalog_button` | 产品卡片上的按钮字 |
| 手机底部固定条 | `sticky_bar` | 手机端底部「拨打电话 / 立即预约」是否显示（复选框） |
| 首页描述 | `description` | 首页副标题、`meta description` |
| 配色主题 | `theme` | 见第三节；与「外观 → 自定义 → 配色方案」**读写同一个键** |

检查点：

- 改完点「保存更改」，页面回到顶部时字段值要回填，空掉就是没存上。
- 复选框要读 `checked`，不是 `value`（`value` 恒为 `1`，看着像开着其实没开）。
- 保存后刷新**前台**看一遍。邮件能力按当前环境配置实测，不能由“演示站”名称推定SMTP状态。

## 二、页面 / 产品 / 预约 / 询盘

### 页面（`edit.php?post_type=page`）

页面清单与数量按project brief，例如首页、关于、联系、隐私说明及门店预约或产品展示页，不设置默认6页。所有写入及删除先授权，优先测试副本；只清理本任务创建且用户确认的对象。

- 页面模板都是 `page-landing.php`（落地页，无侧栏）。**不要改页面模板**，改了版式就塌。
- 编辑器是原生区块编辑器，段落常嵌在 `core/group` 里——脚本里只查顶层区块会一个都找不到。
- 换图：点图片 → 工具栏「替换」→ 媒体库选图或上传。图片必须有使用权。
- 改完点右上角「更新」。已发布页面这个按钮直接提交；**新建页面第一次点「发布」只是展开确认面板，还要点面板里的按钮**。

### 产品展示（`edit.php?post_type=site_product`）

CPT `site_product`，归档在 `/products/`，分类法「产品分类」`site_product_category`。

- 参数：编辑器里的「产品参数」面板，格式 `参数名称|参数值`，一行一项。填虚构认证、评价、销量是红线。
- 门店站的菜单卡片读：标题、正文首段、特色图、分类、参数摘要。
- 加一条 → 发布 → 前台 `/products/` 或业务页能查到；删要「移到回收站」再「永久删除」两步。

### 预约记录（`edit.php?post_type=site_booking`，门店站）

- 列表列：预约人 / 服务项目 / 电话 / 期望时间 / 状态 / 邮件状态 / 提交时间。空态文案「还没有预约」。
- 状态四档：待确认 → 已确认 → 已完成，另有已取消。改状态在详情页「状态」下拉 + 点「更新」。
- 邮件状态区分提交给邮件服务、发送失败及实际收件证据；按环境核查SMTP和日志，不把失败默认视为演示站正常现象。
- 预约记录是私密文章（`private`），不进前台搜索与 RSS。

### 客户询盘（`edit.php?post_type=site_inquiry`，产品站）

同预约，短代码 `[site_inquiry]`，多一个「公司」字段；邮件状态列同上。

## 三、外观 → 自定义 → 配色方案

- 门店站 4 套：`warm` 暖棕 / `jade` 墨绿 / `brick` 砖红 / `navy` 靛蓝。
- 产品站 3 套：`navy` 深蓝 / `graphite` 石墨 / `forest` 深绿。
- **只换颜色，不改结构**。点色块 → 右侧实时预览 → 点「发布」→ 前台生效。
- 与「设置 → 站点资料 → 配色主题」下拉是**同一份数据**，两处改哪边都同步。
- 自定义器里的「颜色」段（WordPress 自带全局色板）已移除，那段改了不生效。
- 配色变量声明在 `body` 的 `.site-style-*` 上，**不在 `:root`**。验收要读 `getComputedStyle(document.body).getPropertyValue('--site-brand')`，读 `documentElement` 拿到的是基础层默认值，切换前后一样，会误判成「没生效」。

## 四、外观 → 菜单

- 一个菜单 `主导航`，挂在 `Primary menu` 位置。
- 门店站含「预约」条目，产品站按版式含「应用场景 / 产品展示」等。
- **导航里不要重复放预约入口**：页头已有「在线订位」CTA，菜单再放一个就是两个按钮抢注意力（2026-10 修过一次）。

## 五、用户与权限

- 交付只给客户一个管理员账号，凭据单独安全交接，不写在页面、文档、录屏里。
- 客户要给别人看内容，加「编辑」角色，不要给管理员。
- 删除用户确认页有个「同时删除其内容」勾选项；页面上另有一个「应用」筛选按钮，脚本按 `#submit` 取，别按 `input[type=submit]` 取第一个。

## 六、工具、插件、主题

- 工具 → 导出：只导出内容 XML，**不含主题、插件、图片文件**。整站备份在服务器上做，不在后台点。
- 插件：只有四个自研的（`site-china`、`site-slim`、`site-site-kit`、`site-harden`），全启用。**停用任何一个都会掉功能**（拨号条、预约记录、备案号、登录限速）。
- 主题：两个（`site-store` 门店 / `site-business` 产品），有封面的才是我们的。**换主题会丢模板**，版式与配色都在站点资料里切。
