# 网优专员工作手册（SEO侧）

> 从当前project brief、合同政策和验收清单确认页面、平台、采样量、工具位置与账号授权；缺项询问，不依赖固定仓库、SKU、价格或SLA。

开工先读项目事实卡、页面清单及 [交付规程](delivery-rules.md)、`references/index-submission.md`、`references/seo-operations.md`。工具须从当前工作区找到并审查参数与作用范围后使用。

本技能负责SEO方法；服务范围与费用由当前项目约定，不从示例推出商业承诺。

## 一、SEO到底解决什么

SEO不是“堆关键词”，也不是保证排名。它解决的是：

1. 搜索引擎能否发现页面（发现）
2. 能否抓取并理解页面（抓取与理解）
3. 是否愿意把页面放进索引（索引）
4. 页面是否匹配用户问题（相关性）
5. 页面是否值得在结果里展示（质量与信任）
6. 用户点进来后是否能完成联系或下一步（承接）

因此每次诊断都要把“技术可见性、主题相关性、内容可信度、转化承接”分开写，不能把“暂时没排名”直接归因成内容差。

## 二、核心理论模型

### 1. 搜索意图

| 意图 | 用户想做什么 | 页面形态 | 例子 |
|---|---|---|---|
| 信息型 | 了解问题、学习方法 | 指南、解释、FAQ | “网站打不开怎么办” |
| 商业调查型 | 比较方案与供应商 | 对比、案例、服务说明 | “广州网站维护哪家好” |
| 交易型 | 准备购买或联系 | 服务页、报价说明、联系页 | “广州宝塔网站部署” |
| 导航型 | 找指定品牌或页面 | 首页、品牌页、地图/联系页 | “用户确认的品牌名” |

一个页面优先服务一个主意图；不要用首页同时抢所有词。关键词只是用户表达，意图才是页面结构依据。

### 2. 关键词分层

- **核心词**：业务品类，例如“网站制作”“WordPress维护”。
- **地域词**：广州、天河、珠江新城等，必须是实际服务范围，不能为了流量虚写。
- **场景词**：上门、远程、急修、上线、迁移、价格、备案。
- **人群词**：个人、门店、小企业、程序员、外包团队。
- **问题词**：打不开、502、证书过期、怎么部署。

记录关键词时至少有：词、意图、服务区域、目标页面、客户原话、事实依据、当前状态。没有公开数据时不编造搜索量、难度和排名。

### 3. 页面主题与信息架构

建议采用“首页—服务页—问题/知识页—案例/证据页—关于与联系”的结构：

- 首页回答“你是谁、服务谁、解决什么问题、覆盖哪里、怎么联系”。
- 服务页回答“具体做什么、不做什么、流程、价格口径、适用对象、交付物”。
- 问题页回答用户搜索的具体疑问，末尾自然承接相关服务。
- 案例页只写真实且获授权的案例，不用演示站冒充客户案例。
- 联系页提供可验证的联系方式与服务时间，不堆无关关键词。

一个URL一个主要主题，内部链接按用户下一步组织，不为了“密度”机械互链。

### 4. 抓取、索引、排名三件事要分清

- **可抓取**：爬虫能拿到页面和资源，不代表已收录。
- **已索引/已收录**：平台把页面放进自己的索引，不代表排名靠前。
- **排名**：对某一关键词、地区、设备、时间的结果位置，会变化。

报告必须写清“已提交”“已抓取”“已收录”“有排名”分别有没有证据，不把其中一个写成另一个。

### 5. E-E-A-T的实际落地

不把它写成空口号，而是落到页面可见证据：

- 经验：真实交付过程、现场记录、实际截图（经授权）。
- 专业：明确技术栈、适用条件、限制和判断依据。
- 权威：品牌、主体、联系方式、备案和第三方公开信息一致。
- 可信：价格与范围透明、隐私/协议入口、不过度承诺、错误信息及时更正。

## 三、技术SEO检查框架

### 站点级

- 域名HTTPS正常，HTTP跳转策略明确，证书无警告。
- `robots.txt`可访问，不能误封首页、CSS、JS、图片和关键目录。
- `sitemap.xml`可访问，URL是规范地址，`lastmod`只写真实更新时间。
- 站点有唯一规范域名（canonical），避免http、https、带/不带www重复。
- 重要页面返回200；404、5xx和重定向链记录清楚。
- 页面源码能读到核心正文；不是只有`<div id="app">`再靠JS补全文本。
- 页面速度与移动端可用性至少做观察记录，不把一次测试当长期指标。

### 页面级

- 每页一个清晰的`title`，表达主题与服务区域，不堆同义词。
- `meta description`准确概括页面，不写无法兑现的承诺。
- 通常一个主要`h1`，`h2/h3`按问题层级组织。
- 首段尽早回答页面主题，之后再展开证据、流程和FAQ。
- 图片有描述性`alt`，不把关键词塞进无意义alt。
- canonical、Open Graph与页面主URL一致。
- 结构化数据只标记页面看得见且事实已确认的内容；JSON-LD与可见文字一致。
- 内链锚文本说明下一页内容，不使用大量“点击这里”。

## 四、内容SEO操作方法

### 内容 brief 必填字段

| 字段 | 要写什么 |
|---|---|
| 页面目标 | 这页服务哪个意图、希望用户下一步做什么 |
| 主主题 | 一句话，不写关键词堆 |
| 目标人群 | 谁在什么场景下搜索 |
| 必答问题 | 客户原话，通常3—8个 |
| 事实素材 | 价格、流程、地区、限制、案例，必须有来源 |
| 页面结构 | 标题层级、答案前置、证据、FAQ、CTA |
| 内链 | 从哪里来、链接到哪里 |
| 验收标准 | 可见文字、源码、结构化数据与链接检查 |

### 写作原则

- 先回答，再解释，再给证据和下一步。
- 用客户会说的话写问题，用专业语言给出准确答案。
- 价格、地区、时间、服务边界必须与交付卡和客户确认一致。
- 不编造年限、案例、评价、资质、排名、效果或客户数据。
- 不使用“最好、第一、唯一、100%”等无依据绝对化词。
- 医疗、金融、法律等高风险内容不由网优专员自行定业务口径。
- 发布前客户确认事实，保留确认记录。

## 五、搜索引擎提交实操

详细操作、验证、提交和账号交接见`references/index-submission.md`。移动适配、子链、Logo等能力先核对当前平台资格，不保证采纳。

- 百度：搜索资源平台验证站点，按后台当前规则使用Sitemap、普通收录手动/API提交；配额以后台为准。
- Bing：Bing Webmaster Tools提交Sitemap；页面变更优先用IndexNow；不要使用已取消的匿名`bing.com/ping?sitemap=...`。
- Google：Search Console验证资源并提交Sitemap；少量URL使用URL检查→请求编入索引；普通网页没有可以强制收录的通用API。
- 字节系：头条搜索站长平台验证站点、提交Sitemap与单URL（入口可能已并入火山引擎搜索增长平台，以实际落地页为准）；`robots.txt` 必须放行 `Bytespider`，否则这条线白做；豆包是否提及/引用归`geo`记录，不并入收录结果。
- 四个平台都要区分“提交/通知、抓取、收录、排名”，保存平台返回状态和截图。

**平台能力不等于交付项**：百度、Bing、Google和字节系是否纳入本次提交及验收，均从当前项目清单确认。新增平台先评估账号权限、工作量和费用，不默认免费或包含。

### 百度实操流程

1. **站点准备**：确认站点可访问、已备案条件（如涉及国内主机/广告）、HTTPS、robots、sitemap、正文源码和联系方式。
2. **基线记录**：记录页面清单、标题描述、H1、正文可抓取性、canonical、状态码、当前`site:`观察结果；运行：
   使用当前项目已核实的只读基线工具（如`geo_baseline.py`）或手动记录同字段；先读工具说明，输出到用户指定私有目录，不假定固定脚本路径。
3. **页面改造**：按本次清单逐页执行：标题描述、答案前置、JSON-LD、FAQ、更新时间、实体一致性。
4. **站点级文件**：生成并人工复核`robots.txt`、`sitemap.xml`、结构化数据草稿；草稿未经核对不能直接上传。
5. **平台提交**：在客户本人账号下提交百度搜索资源平台；账号、验证和官方费用由客户持有/直付，记录提交时间、站点、文件和截图。
   开工先确定账号所有权和最小协作者权限（详见`references/index-submission.md`账号交接）；例外代持须事先明确授权、期限和移交方案，不默认代持。
6. **复核**：用`curl`读源码，打开页面检查可见文字；验证没有误封、错误canonical、死链和虚假结构化数据。
7. **观察**：固定同一组查询和时间窗口，记录“已提交、已抓取、已收录、是否出现”的区别；不把观察结果写成承诺。

## 六、百度之外的平台

- 搜索平台各有抓取、索引和账号规则，不能用百度结果代表其他平台。
- 字节系平台是否纳入提交按当前项目清单，入口与账号规则见`references/index-submission.md`。先核对爬虫官方用途与用户robots策略，不把其收录当豆包必然引用的前置保证。
- 本地业务的百度地图、大众点评、抖音团购等是独立平台，不把网站SEO交付冒充这些平台运营。
- 平台规则变化时，以对应官方后台和最新公开说明为准，记录实际操作时间。

## 七、与GEO的分工（共享事实卡，指标分别记录）

GEO是独立的`geo`技能，与SEO由同一名优化人员执行，但本技能不承担GEO结论。接口如下：

- 本技能负责**可抓取、可索引、可排名**：状态码、robots、sitemap、正文源码、canonical、结构化数据、关键词与页面主题、平台提交与收录监测。
- `geo`负责**可被检索、可被读懂、可被引用、说得准确**：AI爬虫UA可达性、段落自包含改造、事实卡与站内一致性、已确认问题集四档实测。
- 共用同一份事实来源（客户《事实卡》）与同一套页面，不各改一版；改稿前SEO先给页面清单，GEO在清单内改结构，不另起新页。
- 索引未通之前不承诺AI可见性；两级都不通时先修P0/P1，再谈内容。
- 报告分表：本技能只写“已提交/已抓取/已收录/有排名”，AI侧四档（未提及/提及/引用/推荐）归`geo`，**不混表、不互相引用对方的数字当自己成果**——同一个人做两边也不能合并这两组数。
- 避免重复计费：当前合同已含动作分别由SEO/GEO方法执行，新增平台、问题或复测先确认范围与费用。

## 八、SEO侧切到GEO侧必带的四项

SEO侧做完交给GEO侧必带四项，缺一项GEO侧无法开工（现在是同一个人，但字段不能省，省了就没法向客户交代）：

| 字段 | 内容 |
|---|---|
| 索引状态 | 各平台已收录页数、未收录页清单 |
| 可抓页面 | 返回200且正文在源码里的页面清单 |
| 结构化现状 | 已有JSON-LD类型、与可见文字是否一致 |
| 实体不一致项 | 品牌名/电话/地址/价格在哪些页面冲突 |

GEO做完内容改造后，把“改了哪些页、改了哪些段落”回传SEO，避免下次SEO改版把GEO的结构改回去。

## 九、交付报告结构

1. 结论摘要：当前最大问题、影响层级、是否可修。
2. 站点基线：页面、状态码、抓取、索引可观察证据。
3. 关键词与意图表：主主题、用户问题、目标页面、事实来源。
4. 技术问题清单：严重度、证据、建议、完成标准。
5. 页面优化记录：每页改了什么，客户确认了什么。
6. 提交记录：平台、账号归属、时间、提交对象、截图位置。
7. 观察记录：提交≠收录≠排名，四态分别给证据；AI侧提及与引用不写进本报告，由`geo`另出。
8. 未完成项与风险：客户待补资料、平台待处理、不可控结果。
9. 下一步：一次性修正、转故障修复/开发评估或暂不继续。

## 十、红线

- 不承诺排名、收录、流量、询盘、成交、AI提及、AI引用或AI推荐。
- 不购买垃圾外链、不做隐蔽文本、不做cloaking、不给爬虫和用户展示两套内容。
- 优先用户持有账号并授权最小权限协作者；不默认代持。例外须事先书面授权，说明期限、数据可见性、平台限制、撤销和移交方案，不能因用户没有账号自动代持；实名、付款和签字由用户本人完成。
- 不编造搜索量、排名、案例、评价、资质、收录截图或监测结果。
- 故障先走`site-rescue`；成品未上线走`site-launch`；重构、开发、批量改站另确认范围。
- 完成后通过SendMessage向主理人回传：范围、证据、完成项、未完成项、客户待办和下一步。
