# 豆包网页版视频生成

## 前置契约

确认批准提示词、参考素材及上传权限、目标比例/时长/声音、预算与次数、交付目录及覆盖策略。豆包官网为 `https://www.doubao.com/`，官方创作入口为 `https://www.doubao.com/chat/create-image`；官方入口不属于私人硬编码。加载浏览器操作技能，再检查实际工具与登录窗口。查看本技能实际目录下 `references/ui-map.md`，其中控件文案仅为发现线索。

当前账号可用模型、套餐、分辨率、时长、配额及首尾帧能力必须实时核验，不用历史账号结论替代。严格首尾帧控制只有界面明确提供且验证有效时才能承诺；否则说明普通参考图不等于严格控制，询问是否改用其他授权渠道。

## 执行流程

1. 枚举工具可见浏览器及标签，定位用户授权的豆包标签并认领。核登录态；工具看不到的窗口请用户绑定，不新建错误窗口反复尝试，不读取凭证。
2. 优先使用官方创作入口 `https://www.doubao.com/chat/create-image`（页面标题「AI 创作」），再切换「视频」。该官方 URL 是产品知识，不是私人项目硬编码。也可由当前 DOM/截图找创作页或「技能」→「常用」→「视频生成」入口；优先语义点击 `role=tab` 的「视频」，确认输入框和创作模式已变为视频。详细控件、公开路由和参数发现线索见 `references/ui-map.md`，不要因入口变化删除仍有用的官方导航信息。
3. 打开参数面板，读取实际选项与费用提示，选择已批准规格。面板关闭后核摘要；若要求不可满足，先停下确认替代方案。
4. 用当前可用的官方上传控件或浏览器/系统工具上传参考图。仅在环境已提供受支持的剪贴板功能时粘贴；不依赖私人 `clip_img.py` 或 `choose_files2.py`。每次上传后截图核缩略图、内容、数量及顺序。失败先确认页面状态，不重复盲传。
5. 关闭弹层、聚焦输入框、输入提示词、截图核文字和附件，然后才发送。动作描述写起因、反应、结果及镜头收束；精确文字优先后期层。道具数量、持手和动作终态须明确，但不能据此保证模型不出错。
6. 按下面状态机跟踪同一请求；每次新任务提交前复核参数，不能假设参数保留，也不能断言每次都会重置。
7. 完成后核结果属于本次请求，预览视频并下载一次。用浏览器下载记录关联任务、文件名和路径，不单凭最新 mtime 认领文件。
8. 核浏览器显示下载完成、文件大小/mtime在观察间隔内稳定，且没有仍在写入的迹象。`.crdownload` 只代表可能未完成，不能直接改名视为成功；若残留临时后缀，先取得明确完成证据，再执行本地校验。仅稳定或仅 ffprobe 能解析都不足以证明下载完成。
9. 调用本地收尾脚本；失败保留源文件，报告错误并排查下载或解码，不把校验失败直接当作重新生成的授权。

## 提示词、构图与续拍实操

- 用“风格＋场景＋主光线”建立视觉约束，中段写“触发→反应→结果”的动作因果，末段交代镜头运动和收束姿态。提示词中的竖屏要求应与界面参数一致，文字要求不能代替实际比例设置。
- 精确中文、数字、招牌和界面文字容易出现错误，优先采用“警示灯闪烁”等可视动作或后期文字层；不是所有模型必然写错，但必须逐字验收。
- 若屏幕内容不是剧情重点，可只拍脸、手、屏幕侧面或底边，降低自动补出工具栏和品牌的概率。剧情必须展示屏幕时，预留贴图或局部修复窗口，不声称禁字提示能完全阻止补全。
- 对声音给正面可执行描述。例如“第一个音节约0.7秒、第二个约1.1秒、尾音上扬”，仅为表达方法示例，不是通用时长或效果保证；按批准台词节奏调整并试听。只写“不要拖音”等否定句可能难以表达期望表演。
- 锁定道具数量、持手和另一手动作。例如“画面中只有一部手机，始终在右手，左手自然垂下，不出现第二部手机”，仅当剧情如此时采用。还应写结尾是否放下、换手、换物，避免续镜指向错误。
- 普通参考图可能影响语义却不能锁定首尾帧。续拍时从已批准片段选择站位、服装、道具、光线均清楚的帧，作为参考上传，再写后续动作；先检查当前网页是否提供专用首帧功能。多图应明确各自用途和顺序，不能把“首图/尾图”的文字标签当严格首尾帧能力。
- 若生成对白同时变成画面文字，先评估现有素材的局部修复；禁字提示可以尝试但不能保证有效，重出仍需用户授权，不一律认定只能擦除。

## 焦点、消息与下载排障

| 现象 | 核查步骤 |
|---|---|
| 输入工具返回成功，输入框却为空 | 参数面板动画可能带走焦点；关面板→点击输入框→输入→截图核内容，确认附件也在，再发送 |
| 视频标签点击无变化 | 检查 `role=tab` 与选中状态、输入框 placeholder；邻近坐标易误点，优先语义节点 |
| 发完提示词看不到进度 | 滚到对话底部或点向下箭头，检查追加消息和本次任务回执；确认是否等待确认，不盲补确认 |
| 异常文案与受理回执同时存在 | 按本次任务标识查最新状态，归类为不明确而非立即失败；禁止重发 |
| 新窗口未登录，但用户称已登录 | 遍历可见浏览器和标签，核扩展绑定窗口；请用户绑定正确窗口，不反复新建标签 |
| 上传参考图无缩略图 | 先核上传控件、会话状态及系统文件选择结果；截图验证后再继续，不能假定工具点击成功就是附件已上传 |
| 看见旧视频或旧预计等待消息 | 滚底并关联本次请求及参数，不用旧消息宣布完成 |
| 保存按钮误关闭画布 | 核右上工具栏下载图标的「保存」tooltip，旁边 `X` 是关闭按钮；重新打开结果后检查下载记录，避免重复下载 |

## 请求状态机（防重复扣费）

| 状态 | 证据 | 允许动作 |
|---|---|---|
| 等待确认 | 本次请求明确要求确认参数、尚无受理回执 | 核参数与用户授权后，仅确认一次；记录已确认状态 |
| 已受理 | 本次任务编号、受理回执或排队信息 | 记录回执并观察，不补确认、不重发 |
| 生成中 | 进度或运行状态明确对应本次任务 | 在工具允许的检查节奏下刷新状态，不提交新任务 |
| 完成 | 本次任务成功状态且可用结果视频 | 预览、下载并验证；不能只看旧消息 |
| 失败 | 本次任务明确失败/取消状态 | 保存证据和费用情况，解释失败；重试需另行授权 |
| 不明确 | 异常文案、超时、矛盾回执、无最新状态 | 滚到底部核最新消息与任务历史，必要时请用户查看；绝不自动重发 |

“预计等待”是受理证据，不是完成；“系统异常”也不是足以重试的失败证据。页面需滚到最新消息再判断，不使用固定耗时预测或长时间 sleep 轮询。若确认已发送但无回执，将状态记为不明确，不能再次确认。升级套餐、付费、换账号及重新生成都需明确授权。

## 本地收尾

将 `SKILL_DIR` 设置为本次加载技能的实际绝对目录，不假设当前工作区存在 `expert/skills`。使用完整下载源路径及新的目标路径：

```bash
python "$SKILL_DIR/scripts/finalize_video.py" --source "<已确认下载完成的文件>" --dest "<交付目录>/视频.mp4" --download-complete --ffprobe "<ffprobe路径或命令名>" --ffmpeg "<ffmpeg路径或命令名>"
```

脚本再次检查源文件稳定性、ffprobe 视频流/时长，复制到临时文件，完整解码并抽取末帧，所有处理成功后发布结果。默认拒绝已存在的视频和末帧文件，拒绝源目标相同；只有用户授权覆盖才使用 `--overwrite`。工具默认从 PATH 查找，也支持显式路径。`--expect-duration` 与 `--duration-tolerance` 来自交付配置；`--no-frame` 必须明确选择，不会把抽帧失败吞掉。脚本不能自行核浏览器状态，`--download-complete` 仅是调用者已核验的声明，不可为绕过检查随意添加。优先使用新目标路径并保持默认不覆盖；`--overwrite` 对视频和末帧的发布不是跨文件原子事务，若第二个文件发布发生 I/O 错误，第一个文件可能已替换，即使脚本报告失败也须检查两个目标，不能假定整体回滚。

## 验收与交付

- 对照要求检查实际尺寸、比例、时长容差、编码及是否需要音轨；静音视频不因无音轨一律失败。
- 末帧文件只证明抽帧成功，不证明无黑屏。目视检查结尾、关键动作、字幕及中间帧；字幕文字与已批准逐字稿核对。
- 台词可能变为画面文字、屏幕可能出现意外内容；根据具体结果修复，不断言所有账号必然出现。
- 续拍选择站位、道具和光线清楚的已批准参考帧，实际核连续性，不承诺参考图精确锁帧。
- 交付视频、预览图、实测规格、已确认的额度/费用及未解决问题；未观察到费用不得编造。失败时不报完成。
- 仓库中的 `scripts/test_finalize_video.py` 提供离线 mock 回归，只在仓库 `_local` 隔离目录创建合成文件，不操作真实素材、浏览器或 API。
