# 站点迁移步骤（按需精读）

适用于授权的新旧环境间站点迁移，不限定云厂商。范围、费用、窗口、数据冻结及旧环境保留期限从当前project brief和合同取得，缺项先询问。

## 迁移前（先确认，再动手）

1. 授权：新旧两台机器都要有操作授权。
2. 盘点：站点根目录、数据库名与账号、PHP 版本、伪静态规则、SSL 证书、计划任务、绑定的所有域名、有没有常驻服务（Hyperf/Go/Python）。
3. 备份：旧机器全量备份（文件 + 数据库 + 配置文件），**验证可读**。
4. 时间窗：DNS 生效有 TTL，迁移要挑低峰，并告知客户可能有一段生效期。

## 迁移中

```bash
# 旧机器导出
tar -czf site.tar.gz -C /www/wwwroot <域名>
mysqldump -u<用户> -p --single-transaction --default-character-set=utf8mb4 <库名> > db.sql

# 传到新机器（rsync 或 scp）
rsync -avz -e ssh site.tar.gz root@<新IP>:/root/
scp db.sql root@<新IP>:/root/
```

新机器上：

1. 按目标系统部署兼容服务与扩展，不默认Ubuntu或宝塔；先在副本验证版本差异。
2. 建站点、建库，导入文件与数据库。
3. 配伪静态、SSL、计划任务、反向代理（Hyperf/Go/Python）。
4. **先不切解析**，用修改本地 hosts 或 `curl --resolve` 验证新站能正常打开：

```bash
curl -I --resolve <域名>:443:<新IP> https://<域名>/
```

5. 表单、上传、登录、支付回调、邮件这些交互项逐个验证——只测首页不够。

## 切换

1. 把 DNS 的 TTL 提前调小（如 60 秒），切完再调回。
2. 改解析指向新 IP，等生效（`dig <域名> +short` 多地验证）。
3. 旧环境按用户确认期限保留；停机、删除及计费变化另行批准，不能默认停机。
4. 有数据库的站点要确认旧库是否还在写入（比如旧站还有人下单），必要时做一次增量同步再切。

## 迁移后

- 检查：全站链接（使用当前项目已配置的链接检查工具；未提供时按页面清单核验，不假定存在仓库专用脚本）、SSL有效期、备案号展示、图片与附件路径、后台能否登录。
- 输出：改动清单、验证结果、旧机器保留期限、回滚方式（含DNS、文件版本与切换后新增数据协调，不能仅改回解析）。
- 通过 SendMessage 回传主理人。

## 常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| PHP 版本不一致 | 白屏、插件报错 | 新机器装与旧机器相同的版本，或提前测兼容性 |
| 伪静态没搬 | 内页 404 | 宝塔选对应伪静态模板，或复制旧 Nginx 配置 |
| 数据库字符集 | 中文乱码 | 导出与导入都指定 utf8mb4 |
| 文件属主变了 | 上传失败、无法升级 | 查目标运行用户、目录属主与ACL，按已批准对象恢复权限，不默认整站chown |
| 附件路径写死 | 图片 404 | 数据库里替换旧域名/旧路径，或做 301 |
| 证书没搬 | HTTPS 报不安全 | 新机器重新申请，别把私钥到处拷 |
| 常驻服务没跟着迁 | 502 | Hyperf/Go/Python 要单独部署 + systemd 守护 + 反代 |
