# 豆包网页版视频生成

## 用途

驱动用户已登录的豆包网页版，走「AI 创作 → 视频」路径生成视频，并把成品下载、校验、复制到工作目录交付。

不适用于：只需要文字/图片生成、需要 API Key 调用（走火山方舟）、或用户想要 1080p 以上规格（当前网页版 Mini 模型输出 720x1280）。

## 前置检查（必须先做，别猜）

1. 调用 `browsers_list`，对**每一个** browser 逐一调用 `user_open_tabs`。
2. 找出 `url` 含 `doubao.com` 的那一个 browser + tab，再 `tabs_claim`。
3. 判定登录态：页面右上角有「登录」按钮 = 未登录；左下角显示用户名/头像 = 已登录。

**关键坑**：同一台机器上可能有 Edge 和 Chrome 两扇以上窗口，扩展只汇报**当前绑定的那一扇**。用户说"我已经登录了"时，极可能是登录在另一个 browser 里。不要新建 tab 硬试——新 tab 会在错误的那扇窗口里打开，只会看到未登录状态。遍历所有 browser 是唯一可靠办法。

若所有 browser 都没有 doubao.com 标签，或全部未登录，停下来让用户扫码（`cua_click` 点右上角「登录」，弹窗里自带二维码）。

## 执行步骤

### 1. 进入视频创作页

```
tab_goto  →  https://www.doubao.com/chat/create-image
```

页面标题会是「AI 创作」，默认停在「图像」tab。

### 2. 切到「视频」

`dom_cua_get_visible_dom` 找到 `role="tab"` 且文本为「视频」的节点，用 `dom_cua_click` 点它。

**不要用坐标点**：图像/视频两个 tab 挨得很近，`cua_click` 经常点空，且点了没反应不报错。切成功后输入框 placeholder 会从「描述你想要的图片」变成「描述你想要的视频」，模型名会变成 `Seedance`。

### 3. 设置比例与时长

点输入框下方的「自动 · 10s」（或「比例 自动」）按钮，弹出同一个面板：

- 比例 7 档：自动 / 3:4 / 4:3 / 9:16 / 16:9 / 1:1 / 21:9
- 时长滑杆：4s ~ 15s

选完后按钮文案会变成 `9:16 · 10s` 之类，**以此文案作为设置成功的判据**。设置完点页面空白处关掉面板。

### 4. 填写提示词并发送

点输入框 → `cua_type` 写入提示词 → 点输入框右下角蓝色上箭头发送。

提示词写法（实测有效）：
- 开头点明风格 + 场景 + 主光线，中段写动作因果链（触发 → 反应 → 结果），结尾写镜头收束。
- 竖版用「竖屏/9:16」已在参数里定死，提示词里再提一次无害。
- **不要在提示词里要求画面出现准确的中文字**（HUD 文字、招牌文字）。模型必然写错。改为「中控屏亮起红色警报闪烁」这类纯视觉描述。

### 5. 二次确认（必过）

发送后不会直接出片，豆包会先回一份「视频生成参数确认」清单（模型/时长/比例/风格/画面主线/声音），末尾写「确认后我再开始生成视频」。

必须再发一句「确认，参数无误，开始生成」，否则永远不动。这是最容易被漏掉的一步。

### 6. 等待出片

确认后会回「预计等待 5 分钟」。实测 10 秒片约 1~2 分钟。

轮询方式：`sleep 90` → `tab_screenshot` → 出现「你的视频生成好了」即为完成。单次 `sleep` 不要超过 100 秒，前台命令会在 120 秒被打断。

### 7. 下载

1. 点聊天里视频缩略图，右侧会滑出画布面板（有大播放器和进度条）。
2. 面板右上角蓝色按钮，hover 后 tooltip 是「保存」，点击即触发下载。
3. Chrome/Edge 落盘后文件会**卡在 `.crdownload` 后缀不改名**，但内容通常是完整的——不要去点第二次下载，会多出一份 `(1)` 副本。

用 `scripts/finalize_video.py` 收尾：

```bash
python scripts/finalize_video.py --source "<Downloads 里的 .crdownload 或 .mp4>" \
    --dest "<工作目录>/outputs/<片名>.mp4"
```

脚本会：ffprobe 校验时长/分辨率/音轨 → 复制为正式文件名 → 抽结尾帧确认没黑屏。校验不过就报错退出，此时才考虑重新生成。

### 8. 交付

`present_files` 同时给出 mp4 和关键帧预览图。回复里写清：时长、分辨率、编码、文件大小、消耗的额度类型。

## 交付前自检

| 检查项 | 判据 |
|---|---|
| 时长符合要求 | ffprobe `duration` 与要求误差 < 0.5s |
| 比例正确 | 9:16 对应 720x1280 或 1080x1920 |
| 有音轨 | stream 里有 `codec_type=audio` |
| 结尾不是黑帧 | 抽 `duration-1s` 的帧目视确认 |
| 无乱码文字 | 抽中间帧看画面里有没有生成失败的汉字 |

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 新 tab 里豆包显示未登录 | 开在了未登录的那扇浏览器窗口 | 遍历 `browsers_list`，用已登录的那个 browser |
| 访问会话 URL 被重定向回 `/chat` | 同上，该窗口无 session | 同上 |
| 点了「视频」没反应 | 坐标点击点空 | 改用 `dom_cua_click` 点 tab 节点 |
| 发完提示词一直不生成 | 漏了参数确认环节 | 补发「确认，开始生成」 |
| 下载文件停在 `.crdownload` | 浏览器改名失败 | 直接改后缀，先 ffprobe 验证 |
| 提示额度不足/需开通 | 每日免费额度用完 | 停下来告知用户，不要自行付费 |
