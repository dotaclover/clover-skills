# 人声与时间轴（步骤 ①②）

## 一、免费中文音色只有 14 个（硬上限）

edge-tts 的中文音色就这么多，没有更多可挖。

```
普通话 6 个：zh-CN-XiaoxiaoNeural  zh-CN-XiaoyiNeural   zh-CN-YunjianNeural
             zh-CN-YunxiNeural     zh-CN-YunxiaNeural   zh-CN-YunyangNeural
方言   2 个：zh-CN-liaoning-XiaobeiNeural（东北）  zh-CN-shaanxi-XiaoniNeural（陕西）
中国香港 3 个：zh-HK-HiuGaaiNeural  zh-HK-HiuMaanNeural  zh-HK-WanLungNeural
中国台湾 3 个：zh-TW-HsiaoChenNeural zh-TW-HsiaoYuNeural  zh-TW-YunJheNeural
```

**要做出「N 个人在喊」的听感，只能靠 `rate` + `pitch` 矩阵组合。**
同一音色最多用 3 次，且三个参数必须拉开，否则一听就是同一个人。

## 二、情绪 → 参数对照

| 想要的情绪 | rate | pitch | 备注 |
| --- | --- | --- | --- |
| 咬牙切齿 / 阴沉 | −18% ~ −25% | −30 ~ −55Hz | 低吼系，压低又放慢 |
| 沉重控诉 | −15% | −30Hz | 稳，不飘 |
| 常态陈述 | +0% | +0Hz | 基准 |
| 急眼 / 催促 | +28% ~ +35% | +40 ~ +55Hz | 语速先上去 |
| 破音 / 尖叫 | +40% ~ +45% | +60 ~ +70Hz | 拉到极限 |

> 语速和音调要**同向**动。只拉语速不提音调，听起来是「念得快」，不是「急」。

## 三、生成：必须串行 + 重试 + 判大小

```python
async def gen(i):
    voice, rate, pitch, tag = V[i]
    f = f"{AUD}/{i+1:02d}.mp3"
    for a in range(4):                      # 最多重试 4 次
        try:
            await edge_tts.Communicate(TEXT, voice, rate=rate, pitch=pitch).save(f)
            if os.path.getsize(f) > 1200:   # ← 关键：小文件=失败，必须判
                return {...}
        except Exception as e:
            print(f"retry{a}: {type(e).__name__}")
        await asyncio.sleep(2 + a*2)        # 退避：2s → 4s → 6s → 8s
    return None

async def main():
    for i in range(N):                      # ← 串行！不要用 asyncio.gather
        r = await gen(i)
        await asyncio.sleep(1.0)            # 条与条之间也要歇
```

**为什么必须串行**：用 `asyncio.gather` + Semaphore 并发打 TTS 接口，会大量返回
`NoAudioReceived` 和只有几百字节的截断 MP3。串行反而更快出全。

`getsize(f) > 1200` 这一行不能省。edge-tts 失败时不抛异常，只是写出一个 0 字节或几百字节的文件，
不判大小就会带着空音频往下走，最后表现为「某几秒没人声」，极难定位。

改台词、人数、情绪：编辑脚本顶部的 `TEXT` 和 `V` 列表，不动主循环。

# 时间轴（步骤 ②，最容易翻车）

产物 `timeline.json`，结构只有两个数组：

```json
{
  "audio": [
    {"i": 1, "text": "大麦倒闭", "dur": 1.63, "start": 0.15, "track": "main"},
    {"i": 16, "dur": 1.20, "start": 10.0, "track": "sub"}
  ],
  "danmaku": [0.05, 0.24, 0.43, 0.62]
}
```

## 一、人声密度：用双轨，别用单轨

单轨 N 条铺满全程，铺到一半就没气了，后面全是空。

| 轨 | 排法 | 音量 |
| --- | --- | --- |
| 主轨 | 开头密（每 0.55s 一条），10 秒后放缓到 1.85s | 0.60 |
| 副轨 | 从第 10 秒开始，每 0.95s 一条 | 0.44 |

**短时长版本要反过来。** 15 秒版用「主轨 0.85s 间隔 + 副轨 0.98s 间隔、偏移 0.45s」，
30 条全塞进去，第 0 秒就 3 个人同时喊——越短越冲。

> 踩过的坑：副轨间隔写 0.88s 时，副轨在第 13 秒就跑完了，结尾人声掉到 3→2→**0**，整条泄气。
> 把间隔放宽到 0.98s、让末条压到 14.1s 才解决。

## 二、弹幕密度

```python
DUR, N = 15.0, 120
danmaku = [round(0.05 + k * ((DUR - 0.3) / (N - 1)), 2) for k in range(N)]
```

| 项 | 值 |
| --- | --- |
| 起点 | **0.05**（不是 2.6、不是 2.6） |
| 短版密度 | 8 条/秒 |
| 长版密度 | 5 条/秒 |
| 结束留白 | 末条落在 DUR − 0.3 左右 |

## 三、出稿前必须打密度表

**这一步不能省。** 逐秒列出声音数和弹幕数，一眼看出哪一秒是空的：

```
 0s  声 3 ███        弹 8 ▓▓▓▓▓▓▓▓
 1s  声 5 █████      弹 8 ▓▓▓▓▓▓▓▓
 ...
14s  声 2 ██         弹 7 ▓▓▓▓▓▓▓
15s  声 0            弹 0        ← 这一行会立刻告诉你结尾空了
```

**先给用户看这张表再渲染**，比渲完再改省事得多。
表里出现连续两秒「声 0」或「弹 0」，就是排法有问题，回去改间隔。

## 四、模式切换

| 模式 | 适用 | 特征 |
| --- | --- | --- |
| `burst` | 15 秒以内的短片 | 开头即满，人声堆叠，越短越冲 |
| `sustain` | 30 秒以上 | 主副轨交替递进，末段不放空 |

同一套文案要出横竖屏多版本时，只改 `--dur` 和画布参数，
`timeline.json` 按各版本分别重算——**不要复用同一份时间轴**，密度是按时长算的。
