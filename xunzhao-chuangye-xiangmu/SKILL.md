# 创业全流程

从「我适不适合创业」到「一份能交出去的创业计划书」，一条完整链路。

**三层结构 + 一条横切线**：

```
理论层   判断标准（四问 / 自我评价 / 想法来源 / 筛选标准 / 环境影响）
  ↓
方法层   阶段 0–11（诊断 → 找项目 → 市场 → 开办 → 运营 → 计划书）
  ↓
交付层   创业项目档案/（01–11 + 98 证据台账）+ 99 人工核实清单

━━━ 横切：AI 取证层（贯穿全部阶段）━━━
没有数据源时怎么降级取数 · AI 答案可信度打分 · 多模型交叉验证 · 证据台账
```

> 只想要一个优胜项目 → 做到**阶段 6** 结束即可。
> 要开店 → 做到**阶段 10**；要交计划书/申请补贴/找合伙人 → 做到**阶段 11**。

## 阶段 0｜起点诊断（每次会话先做这一步）

不要一上来就跑阶段 1。先判断用户在哪一层，再决定入口：

| 用户说的 | 从哪进 | 先补什么 |
|---|---|---|
| "想创业，不知道做什么" | 阶段 1 | 先读 `理论层.md` 第二、三节 |
| "我有个方向，但不确定行不行" | 阶段 3（单候选）或 阶段 4 | 补阶段 1 的资源盘点 |
| "有几个想法，选不出来" | 阶段 2 | 缺信息先补阶段 1 的四象限 |
| "项目定了，怎么开" | 阶段 8 | 补阶段 7（市场分析没做过，开办就是盲开） |
| "店开了，怎么提升" | 阶段 9 / 10 | 要先有基线数据，没有就补阶段 9 的三张表 |
| "帮我写创业计划书" | 阶段 11 | **检查 1–10 的档案**；缺哪节让用户补哪节，不替用户编 |
| "接着上次继续" | 读 `创业项目档案/_进度.md` | 从断点续跑 |

**电商方向必须多问一句**：做的是农村/跨境/本地生活/O2O 哪一类？
不同机会类型的起步条件差别很大，跳过这一问会生成一堆不落地的方向。

**每次只推进一个阶段。** 一个阶段完成后停下来，把结论交给用户确认，再进入下一阶段。

## 全局硬规则（每一阶段都必须遵守）

### 规则 1：禁止凭模型记忆生成任何数字

```
❌ "这个小区大概有 2000 户居民"
❌ "该品类市场规模约 50 亿"
❌ "同行客单价一般在 80-120 元"

✅ "【未核实，需人工确认】建议通过以下方式获取：XX"
✅ "据 XX 来源（URL）显示：……（检索时间：YYYY-MM-DD）"
```

**凡是数字，要么带来源 URL，要么标【未核实】。没有第三种写法。**

### 规则 2：所有查证结论必须挂来源

检索不到就明说检索不到，并给出"用户可以自己去哪里查"的建议。

### 规则 3：不承诺任何结果

不得暗示项目必然成功或盈利。每阶段结尾保留一句：
结论依赖用户提供的信息质量，最终决策与风险由用户自行承担。

### 规则 4：信息不足先问，不要替用户假设

**每次最多追问两个问题**，问完就开工。缺失的城市、预算、可投入时间，是三个必问项。

### 规则 5：必须落盘

每阶段结束写入 `创业项目档案/`，更新 `_进度.md`。**状态放在文件里，不放在对话里。**

### 规则 6：区分「教材口径」与「我的判断」

本技能内容分两类，写档案时必须分清：

| 类型 | 标注方式 |
|---|---|
| 来自课程教材的结构与方法（四问、五种来源、八步、优化维度） | 直接写，不出处 |
| 来自案例归纳或经验值（痛痒点判读、否决信号、成本区间） | 写「经验值，需自行核实」 |

不要把经验值包装成教材结论，也不要把教材结构说成自己的原创。

### 规则 7：数字必须过「可信度闸门」才能进档案

规则 1 说"数字要带来源"，规则 7 说"**带来源还不够，还要够格**"：

```
每个要进档案的数字，走这三步：
① 标取证级别 L1–L5（见 AI赋能.md 第三节）
② 打可信度分 0–10（见 AI赋能.md 第六节）
③ 写进 98_证据台账
```

**硬门槛：可信度 < 8 分（C/D 级）的数字，不得进入成本表、销量测算、财务三表。**
只能出现在"待验证假设"或 `99_人工核实清单.md` 里。

另外三条常被违反的：

| 禁止 | 为什么 |
|---|---|
| 用闭卷（不检索）的答案填数字 | 看起来和查到的同样具体，是最危险的错觉 |
| 把转载当原文（统计数据尤其） | 公众号、百家号里的"据XX报告"多是第 N 手；只有发布机构页面才算 L1 |
| 心算但不给过程 | 只给结论，用户无法判断基数与口径错在哪 | 公式、每步基数、单位、中间值都写出来 |
| 追问三次以上逼出数字 | 那不是查到的，是被逼出来的 |

**AI 输出的证据等级上限是 B。** A 级（自己或熟人真实交易）只能靠真实交易与实地走访拿到——这条天花板必须向用户明说。

## 十一个阶段

详细步骤见对应 reference；本表只给"做什么 / 关键动作 / 产出"。

| 阶段 | 做什么 | 关键动作 | 产出 |
|---|---|---|---|
| **1 定位扫描** | 盘清自己，生成 10 个方向 | 四象限（我会/我能/我想/我做不了）；**城市必问** | `01_定位与候选方向.md` |
| **2 筛出三个** | 按资源 > 匹配 > 需求 > 门槛排序 | 淘汰的 7 个逐条存档，写"什么条件下可重启" | `02_三强筛选与落选存档.md` |
| **3 六维对比与算账** | 三选一，并给出结论的脆弱点 | 痛点是/痒点判断；成本与三档情景**写出公式与中间值**（复杂时用脚本） | `03_六维对比与测算.md` |
| **4 SWOT 体检** ★ | 只体检当选的那一个 | 四条防退化规则；结论三选一 | `04_优胜项目SWOT体检.md` |
| **5 业务画布** | 四问展开成可执行描述 | 每格绑定真实信息，禁止"25–45 岁女性" | `05_业务画布.md` |
| **6 客户细分** | 四维度推荐 2–3 个指标 | 不机械套年龄性别收入 | `06_客户细分.md` |
| **7 市场分析** | 环境 + 客户 + 对手 → **市场定位** | 差评表最值钱；定位写成一句话 | `07_市场分析.md` |
| **8 开办准备** | 平台 / 货源 / 团队 / 形态资质 / 启动资金 | 选规则能守住的平台，不选最大的 | `08_开办准备.md` |
| **9 运营与财务** | 店铺呈现、管理、推广、三张财务表 | 先跑转化率再投付费；三个必算指标 | `09_运营与财务.md` |
| **10 项目优化** | 五要素找短板，单变量试验 | 一次只改一个变量，跑满一个周期 | `10_项目优化.md` |
| **11 创业计划书** | 十节结构收口 | 每节必须能指回前面某个阶段 | `11_创业计划书.md` |

### 三个必停点

- **阶段 3 结束**：已有一个经过对比和算账的优胜项目，可以停
- **阶段 7 结束**：已有市场定位，可以拿去做小规模验证再投钱
- **阶段 10 结束**：已经在运营，优化是持续动作，可以按周期回来

### 两处最容易做废的地方

- **阶段 4 的 SWOT**：写成放之四海皆准的废话，等于没做。四条防退化规则是这一步的全部价值。
- **阶段 7 的定位**：写成商品说明或人群统计，等于没做。定位必须是"在什么场景下、为谁、比谁强在哪"。

### 测算：心算可以，但要把过程交出来

**结论可以心算，过程必须可见。** 用户要的是能自己判断的东西，不是一句"算过了"。

对话里给测算，必须长这样：

```
售价 199 / 进货 70 / 佣金 5%×售价 / 支付 0.6%×售价 / 履约 8 / 退货率 8%
单件贡献 = 199 − 70 − 9.95 − 1.19 − 8 = 109.86
盈亏平衡月销量 = 12000 ÷ 109.86 ≈ 110 件（向上取整）
```

每一步写出**基数、单位与口径**（佣金按售价还是按成本，是最常见的分歧点）。只给最终数字，用户无法判断对错。

多档情景、盈亏平衡、财务三表这类重复计算，可以选用脚本加速：

```bash
python scripts/calc_unit_economics.py --price 199 --cogs 70 --commission 5 \
  --payment 0.6 --shipping 8 --return-rate 8 --ads-pct 20 \
  --fixed 12000 --volume 200 --level L3
```

输出：成本结构表 → 贡献毛利与毛利率 → 盈亏平衡月销量与安全边际 → 三档情景（客流 −30% / 成本 +20% / 两者同时）→ 可直接粘贴的 03 档案片段 → 台账行。

**脚本是可选加速器，不是许可证**：用了脚本同样要把输入口径与输出贴进档案。

`--level` 填输入数据的取证级别（L1–L5），脚本据此给出台账建议分：L1→9、L2→8、L3→6、L4→5、L5→3。
**L5 的输入不该跑测算** —— 跑出来的数再精确，也只是把假设乘了一遍。

## 收尾必做：人工核实清单

全部阶段完成后输出，明确列出：

1. 本轮**未能联网核实**、需要用户自己确认的项
2. 需要**线下实地走访**才能得到的项（如：去数一下周边有几家同类店）
3. 涉及**资质、许可、类目限制**的项，提示以主管部门最新口径为准

**清单从 `98_证据台账.md` 里筛出来**，不是凭印象列：
台账中可信度 < 8 分（C/D 级）的条目、以及"复核动作"未完成的条目，逐条搬进 99。
这样每一条"未核实"都能指回它当初的取证过程。

> 这份清单不是免责声明，是交付物的一部分。
> 明确说出"哪些我做不到"，用户才会相信"哪些我做到了"。
