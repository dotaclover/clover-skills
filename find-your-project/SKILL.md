# 定位项目工作区

## 目标

把用户提供的项目线索解析为一个可验证的项目根目录，并在开始修改前确认：

- 路径存在且是目录；
- 目录包含项目标记（例如 `.git`、`go.mod`、`package.json`、`README.md` 或用户指定的入口文件）；
- 目录内的 `AGENTS.md`、`CLAUDE.md` 或项目级说明已读取；
- 当前任务与该目录的技术栈和权限边界相符。

## 工作流

1. 先检查用户给出的绝对路径；不要把相似目录或旧副本默认为目标。
2. 如果用户只给项目名，在已授权的工作区范围内用 `rg --files` 或目录枚举查找候选。
3. 候选多于一个时，按最近修改、Git 分支、项目标记和用户上下文排序，并明确列出差异；不要静默选择有风险的候选。
4. 读取项目根目录及任务涉及子目录的本地规则，再决定是否需要创建工作树或委派子任务。
5. 把最终选定的绝对路径写入后续工作记录；未验证路径前不执行写入、部署或删除。

## 边界

- 不扫描用户未授权的宽泛目录，不读取凭据文件内容。
- 不因为目录名称相似就迁移或合并项目。
- 如果用户已经给出明确存在的路径，直接验证并使用该路径，不额外寻找替代项目。
