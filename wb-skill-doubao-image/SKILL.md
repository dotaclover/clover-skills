# 豆包网页版图片生成

## 与其他能力的分工

- 网页版**视频**生成走 `doubao-web-video`；同一创作页的两个 tab 不要混用参数与结果。
- 需要接口、批量、幂等任务或服务端集成时走对应 API 技能（如 `site-visual-design`、`juhe-nexgate`），本技能只管浏览器手动操作。
- 精确中文、数字、招牌与界面文字一律后期叠字，不让模型写；这不是平台保证，是多次实测的返工教训。参考图只借语义，**不锁构图、人数、白边和道具细节**，需要精确复现的元素不要押在生成阶段。

## 前置契约

确认批准提示词（含明确写出的出图张数）、参考素材及上传权限、目标比例、预算与次数、交付目录与覆盖策略，以及本期是否需要"一图流拼版再切格"等项目约定。**出图张数没有独立控件，靠提示词指定**：实测同账号、同模型、同比例、画面描述逐字相同的单变量对照下，不写数量返回4张2×2网格，提示词开头写「只生成一张图片。」则只返回1张完整大图。别把"默认4张"当平台保证，也别把其他数量写法当成已验证。豆包官网为 `https://www.doubao.com/`，官方创作入口为 `https://www.doubao.com/chat/create-image`（「AI 创作」页，图像与视频在同一页切换）；官方入口属于产品知识，不是私人硬编码。加载浏览器操作技能，再检查实际工具与登录窗口。控件细节看本技能目录下的 `references/ui-map.md`，其中线索不保证当前账号版本一致。

**单张、批量、重出、试风格都必须先取得用户明确授权**，不在同一对话里顺手补发。当前账号可用模型、比例档位、一次出图张数、配额与费用必须实时核验，不用历史账号结论替代。创作页提交前不显示剩余免费次数，实测同一天两个账号对照：一个提交后明确返回「今日图片生成免费额度已用完」且无结果图，另一个经用户授权换用的账号正常出图。额度属于失败态，订阅、换账号或改渠道都另请授权；不同账号的界面也可能不同，不照抄账号结论。

## 执行流程

1. 枚举工具可见浏览器及标签，定位用户授权的豆包标签并认领。核登录态；工具看不到的窗口请用户绑定，不新建错误窗口反复尝试，不读取凭证。未登录时只能看到落地页，不能据此推断图像模式的控件。
2. 从官方创作入口进入，优先用语义节点点击 `role=tab` 的「图像」，核输入框 placeholder 变为「描述你想要的图片」、参数控件属于图像模式；底部快捷 chip 不一定随 tab 切换，不单凭它判断模式。详细定位线索见 `references/ui-map.md`。
3. 打开参数面板，读取当前实际可选比例、风格/模型与收费提示，选择已批准规格。参数浮层实测**向上弹出并盖住输入框，选中档位后不会自动关闭**；点所谓空白处未必能收起，此时点输入框中部会命中浮层第二行、把已选16:9悄悄改成4:3，且输入工具虽返回成功、文字却没进输入框。**最可靠的是按一次 `Escape` 收浮层**，再截图确认比例摘要未变、浮层消失，然后才点输入框中部（避开浮层覆盖区）、输入、再截图核文字。执行"核提示词文字→核模型摘要→核比例摘要→核附件→发送"，缺一项都不发；输入工具返回成功不等于内容已落框。若要求不可满足，先停下确认替代方案。详细覆盖区坐标与档位见 `references/ui-map.md`。
4. 用当前可用的官方上传控件或环境支持的剪贴板功能上传参考图，不依赖项目外私人脚本。每次上传后截图核缩略图、内容、数量及顺序；失败先确认页面状态，不重复盲传。新对话与已有对话的上传差异按当前窗口实测，不照抄别的项目结论。
5. 提示词写清主体、场景、光线、风格与用途；**数量约束放开头**，如「只生成一张图片。」，这是目前唯一实测有效的单张写法；不写数量按平台当次默认（实测4张）。不要为控制张数堆"不要多张／不要拼版／不要网格"等否定词，未验证其效果，且否定描述可能被模型当画面内容。需要精确文字时生成无字画面，后期叠。参考图用途与顺序要明确写出，不把"首图/尾图"之类文字标签当作严格锁帧能力。
6. 按下方状态机跟踪同一请求。**每次新任务提交前复核参数**：网页版曾出现生成后参数退回默认值的情况，图像模式是否同样重置须实测，不假定保留也不假定必然重置。
7. 完成后先核结果属于本次请求再下载。张数以提示词为准：不写数量实测4张2×2网格，写「只生成一张图片。」实测1张大图；生成中的灰色占位数量就是早期信号（1个或4个）。悬停结果图，2×2网格时工具栏在**目标卡片底部**，单张大图时在**图片左下角**；4个图标均为引用／重新生成／**下载原图**／编辑，先核 tooltip 再点一次，别误点重新生成。用浏览器下载记录、下载前文件基线对照认领，不单凭最新 mtime 或文件名；文件名取自会话标题，同标题会追加 ` (1)` 这类编号，多图逐张核归属。
8. 核浏览器显示下载完成、文件大小/mtime 在观察间隔内稳定、无仍在写入迹象。`.crdownload` 只代表可能未完成；仅稳定或仅能读出图片头都不足以证明下载完整。
9. 调用本地收尾脚本，失败保留源文件并排查下载或解码，不把校验失败当作重新生成的授权。

## 状态机（防重复扣费）

| 状态 | 证据 | 允许动作 |
|---|---|---|
| 等待确认 | 本次请求明确要求确认参数、尚无受理回执 | 核参数与用户授权后仅确认一次，记录已确认状态 |
| 已受理 | 本次任务编号、受理回执或排队信息 | 记录回执并观察，不补确认、不重发 |
| 生成中 | 进度或运行状态明确对应本次任务 | 在工具允许的检查节奏下刷新状态，不提交新任务 |
| 完成 | 本次任务成功状态且可见对应结果图（张数按提示词，实测1张或4张2×2网格，缩略图渐进加载） | 等缩略图渲染完再逐张预览、下载并验证；不把灰占位判成没出图，不把旧结果当本次 |
| 失败 | 本次任务明确失败/取消状态 | 保存证据和费用情况，解释失败；重试另请授权 |
| 额度受限 | 明确「免费额度已用完」且无结果图，出现订阅入口 | 按失败处理并留证；不自动重发、不擅自开通订阅、不换账号或改付费渠道 |
| 不明确 | 异常文案、超时、矛盾回执、无最新状态 | 滚到最新消息或查看任务历史，必要时请用户查看；绝不自动重发 |

"预计等待"是受理证据不是完成；"系统异常"也不是足以重试的失败证据。生成完可能是**追加一条新消息而页面不自动滚到底**，判"没出图"之前先滚底或点向下箭头。若确认已发送但无回执，记为不明确，不能再次确认。升级套餐、付费、换账号、重出与批量生成都需明确授权。

## 焦点、上传与下载排障

| 现象 | 核查步骤 |
|---|---|
| 输入工具返回成功，输入框却为空 | 浮层未收起时点输入框其实是点了档位，或点到了输入框左上角边缘没取得焦点；按 `Escape` 收浮层→点输入框中部→输入→截图核文字。工具返回成功不代表文字已落框，点输入框边缘也可能完全没聚焦 |
| 「图像」tab 点击无变化 | 查 `role=tab` 选中状态、输入框 placeholder 与当前模型；邻近坐标易误点，优先语义节点 |
| 比例/模型摘要与所选不符 | 浮层向上盖住输入框且选中后不自动关，点空白未必收起；按 `Escape` 关闭、重新读 DOM 并截图核三项摘要；点输入框中部若落在浮层第二行会把16:9改成4:3 |
| 提交后提示免费额度已用完 | 明确失败态，无结果图；留证并请用户决定订阅、换号或改渠道，不重发、不点订阅按钮 |
| 结果区先出灰色占位 | 缩略图渐进加载；等渲染并滚底，不据此判失败或重发 |
| 下载后找不到文件 | 对照浏览器下载记录与下载前基线；文件名取自会话标题，同标题会追加 ` (1)` 等编号，不按 mtime 或文件名猜 |
| 只要1张却出了4张 | 提示词没写数量约束；确认授权后在**新对话**里把「只生成一张图片。」放开头重出，别在旧结果上反复点重新生成 |
| 参考图无缩略图 | 先核上传控件、会话状态及系统文件选择结果；截图验证后再继续，不假定点击成功就是附件已上传 |
| 新对话首条传不进图 | 按当前窗口实测处理；可请用户先建立已有对话，不为绕过而发送无意义消息 |
| 发完看不到进度 | 滚到对话底部或点向下箭头，核追加消息与本次回执；确认是否等待确认，不盲补确认 |
| 看见旧图或旧回执 | 滚底并关联本次请求与参数，不用旧消息宣布完成 |
| 保存按钮误关闭画布 | 视频态核右上工具栏「保存」tooltip，旁边 `X` 是关闭；图像态改用单张卡片 hover 的「下载原图」，不混用路径；重开结果后查下载记录，避免重复下载 |
| 多张图只下来一张 | 逐张核结果卡片与下载记录，不把一次下载当整组完成 |

## 本地收尾

将 `SKILL_DIR` 设为本次加载技能的实际绝对目录，不假设当前工作区存在 `expert/skills`。使用完整下载源路径与新的目标路径：

```bash
python "$SKILL_DIR/scripts/finalize_image.py" --source "<已确认下载完成的图片>" --dest "<交付目录>/图片.png" --download-complete --ffprobe "<ffprobe路径或命令名>" --ffmpeg "<ffmpeg路径或命令名>"
```

脚本再次检查源文件稳定性，用 ffprobe 读图像流尺寸，用 ffmpeg 完整解码，全部成功后才发布。默认拒绝已存在的目标、拒绝源目标相同；`--expect-width` / `--expect-height` 与 `--min-bytes` 来自交付配置。`--overwrite` 需用户明确授权覆盖。工具默认从 PATH 查找，也支持显式路径。脚本不能自行核浏览器状态，`--download-complete` 仅是调用者已核验的声明，不可为绕过检查随意添加。

## 验收与交付

- 对照要求检查实际格式、尺寸、比例与是否有透明通道；拼版切格属于项目策略，按当前约定另做，不在本技能里预设格数。
- 目视检查文字、手指、道具数量、边缘白边与是否需要局部修复；脚本能证明文件完整，不能证明画面正确。
- 交付图片、实测规格、已确认的额度/费用及未解决问题；未观察到费用不得编造。失败时不报完成。
- 仓库中的 `scripts/test_finalize_image.py` 是离线 mock 回归，只在本仓库 `_local` 隔离目录创建合成文件，不操作真实素材、浏览器或 API。
